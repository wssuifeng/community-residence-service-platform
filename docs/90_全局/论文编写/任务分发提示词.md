# 论文编写任务分发提示词

复制以下提示词，填写方括号中的任务信息后，分发给独立写作会话或协作者。

```text
你协助编写本科毕业设计论文《基于 Spring Boot 的小区居住服务管理系统设计与实现》。

本次只处理：［具体章节、段落或核验任务］
输入材料：［列出明确文件路径；不要默认扫描或改写全仓库］
预期产物：［输出文件路径或仅返回审阅意见］

执行要求：
1. 先阅读本项目 AGENTS.md、docs/00_总控.md，以及 docs/90_全局/论文编写/README.md、写作计划.md 和论文知识结构目录.md 中与任务相关的部分。
2. 严格限定在本次任务和指定材料内；不改需求、系统定义或其他人的文件，不覆盖已有内容。若要编辑文件，只编辑明确指定的产物。
3. 事实、数据、项目能力和测试结论必须能追溯到指定文档、源码、迁移脚本或测试证据；区分“设计目标、已实现、已验证、用户确认”。没有依据的内容标记“待核实”，不要推测补齐。
4. 涉及文献时，只使用项目已有且可追溯的文献及阅读记录；逐项保留“文献来源/页段—支持的论点”。不得编造文献、页码、研究结果或把摘要信息扩写成全文结论。
5. 写作使用中文、表述朴实准确；综合比较相关研究，不按作者逐条堆砌，不夸大创新性，不虚构访谈、问卷、用户实验或数据。
6. 遇到材料冲突、证据不足、需要改变论文结构或超出任务范围时，先列出问题和出处，不自行裁决。

完成后只需报告：完成了什么、修改了哪些文件、主要事实依据、未解决/待用户确认项、执行过的核验。不要声称未运行的检查已经通过。
```

## 并行分发建议

- 每个会话分配互不重叠的章节或核验产物，避免多人同时改同一文件。
- 文献综述按“主题分组、证据核验、段落蓝图、正文修订、引用格式检查”拆分；不同会话共用同一份术语与引用口径。
- 目录或章节结构尚未确认前，只分发资料盘点、事实核验和结构建议，不分发整章定稿任务。
