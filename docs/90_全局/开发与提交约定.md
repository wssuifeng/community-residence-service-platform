# 个人项目开发与提交约定

自 2026-11-10 起按本约定维护。项目既有阶段定义和验证要求继续生效。

## 分支

- main 是默认展示入口，只描述该分支实际拥有的代码与已记录验证。
- 每次实际任务使用短期分支：feat/具体功能、fix/具体问题、docs/具体文档；没有并行发布需求时不设长期 develop/frontend/backend 分支。
- 完成文件审查、适用检查和文档回写后合入 main，再结束任务分支。删除前核对远程 tip、未关闭 PR、独有提交与内容去向。
- 仍有失败或未验证的重要检查时，保留明确命名的候选分支和差距记录，不提前宣布发布。

## 提交

一件可理解、验证、回退的事情形成一个提交；实现与对应测试一起提交，纯展示/维护文档可单独提交。

提交示例：

- fix(ingest): restore subscriptions after reconnect
- docs: update local setup and verification evidence

提交前先看 diff，按文件或片段暂存；临时文件、真实数据、环境密钥和安装包不整包提交。
保留已有公开提交的作者、时间与编号；不为了展示重写历史，不补造过去版本的提交。合入长期已公开分支时保留其真实提交链。

## 验证与发布

- 写清验证日期、源码基线、环境、执行命令、通过/失败/未执行及原因。
- 测试方法数、自动化通过、用户体验验收和生产使用是不同事实。
- 源码版本、标签、下载文件和发布说明对应后才能标为可下载版本；本机候选包不能当公共 Release。
- README 介绍产品、运行方法和证据；逐日交接放 docs，历史首页和已结束分支资料放 archive。
- 保持个人项目与 AI 编码工具使用的真实说明；许可证沿用现状。
