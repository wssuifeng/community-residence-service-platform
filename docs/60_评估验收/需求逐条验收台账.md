### 1.1 逐条记录格式

索引表每行链接对应批次的详细记录；执行时填写，不预填尚未执行的结果。记录至少包含：

| 字段 | 填写要求 |
|---|---|
| 对象与标准 | R/N/E编号、原标准位置及后续批准修订、全部适用子判据；子项仅作核对索引 |
| 范围与版本 | 角色、社区/本人/参与者范围、页面/操作/接口、日期、源码/构建/运行版本、环境及数据条件 |
| 场景与结果 | 前置条件、操作、预期结果、实际结果；原需求适用的成功、拒绝与边界分支分别列明 |
| 证据适用性 | 类型、原路径与原日期、可证明的判据、和当前版本的关系、尚缺内容；金融明确采用用户确认 |
| 结论与差距 | 通过/未通过/证据不足；不适用另列依据；部分判据不足不能将整条计为通过；未满足项关联G编号 |
| 整改与复验 | 实际修改、修复版本、原问题与相邻受影响入口、结果、证据及日期；无整改则按事实记录 |

采用证据不等于整条需求通过；统计时分别给75条R、10条N、13个流程对象的结论数量、证据覆盖与未核实内容，不能将建账或子项断言数量作为通过率。判定和进入质量评估条件统一按[阶段计划§4](阶段计划.md#4-需求验收任务明细)及§3办理。
