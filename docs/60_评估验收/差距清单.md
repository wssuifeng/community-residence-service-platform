## 1. 分类与排序规则

- 待核实是事实核对进度，不是第四种差距分类；先确认标准、版本和证据，再按缺陷/不足/超纲分类。
- 缺陷：有复核证据证明违反现行需求或已批准约束。明确要求但未实现的功能不能降为一般不足；缺陷优先处理。
- 不足：已满足既定底线，仍有体验、结构或效率上的改进价值；按影响 ÷ 成本排序。没有既定阈值的主观建议不自动升级为阻断验收的缺陷。
- 超纲：超出现行定义或需求的建议，只记录并关联全局灵感留存处，不直接开发。
- 同类中单列权限、数据和核心流程影响；排序须有理由。证据缺口保留核实动作，不用“没有发现”替代结论。

## 3. 确认差距后的必填内容

| 内容 | 记录要求 |
|---|---|
| 来源与依据 | G编号、60任务编号、相关R/N/E及当前标准；多维度共用同一编号 |
| 事实与证据 | 角色与数据范围、入口、原判据、前置条件、操作、实际/预期、复现方法、版本/环境、证据类型及原路径/日期；历史证据说明适用性，未复现风险明确标注 |
| 分类与影响 | 核实后的分类、严重程度及理由、影响范围、现有替代办法和残余风险 |
| 成本与排序 | 预计改动、依赖、验证成本及相对顺序；不在事实核实前捏造数值 |
| 处理批次与范围 | 标明来源为需求验收或质量评估；验收差距归60-03、评估差距归60-07；纳入本版的依据、批次目标和相关文件；冻结变更/新增范围的裁决记录 |
| 复验与回写 | 修复前后版本与证据、实际改动、原失败判据和相邻受影响入口的验证、结果及日期；更新相关质量结论和R/N/E条目。版本变化重核已验收范围，文档修改或代码提交本身不能作为关闭依据 |
| 最终去向 | 关闭依据，或本版保留理由、影响、用户裁决与后续位置；不得以“建议优化”掩盖未满足需求 |

每批开始前将本批条目整理为有编号、有范围、有验证方式的有限任务；执行中本清单是整改唯一工作来源。没有确认差距时不预写代码方案或开展重构。
