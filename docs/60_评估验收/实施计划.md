# 60阶段细化实施计划

编制日期：2026-10-19。依据[阶段整体计划](阶段计划.md)的七组工作与依赖细化；用户已要求开始执行，按本会话顺序办理。执行状态只在[_中控](_中控.md)维护，各产物保留实际记录。本计划不新增需求、质量维度或验收门槛。

## 1. 目标、文件与依赖

目标：先证明项目是否按20包现行需求实现，完成需求差距整改复验；再评价验收版本质量，处理本版质量差距，交付一份可审阅报告。

本项目采用Java 17、Spring Boot 4、Vue 3和TypeScript；本阶段以已有系统、测试证据和用户确认作输入，未核实差距前不预设代码改造。方法参考writing-plans的任务拆分及产物核验，位置、状态与执行方式遵守本项目文档纪律，直接在当前会话执行。

## 2. 共同执行规则

1. 原需求摘要只用于检索，判定须包含原标准与后续批准修订。修订优先顺序保留来源；疑似冲突先核对和登记，不复活已替代规则。
2. 证据分为可直接采用、部分适用、需要补证和用户确认；每项说明原日期、版本、角色、规模与限制。静态代码、单元测试、合成页面、真实运行和用户确认分别记录。
3. 金融沿用户确认，不发起支付、查单、退款或写渠道配置；正常8084/5176仅作版本/只读页面核对，写入、负载与故障验证另用独立环境和自建数据。浏览器使用独立会话。
4. 10～50与archive保持只读。需求或设计变化先记录影响并走已有裁决流程；普通修复从60差距清单取得有限范围。
5. 每个执行批次依次保存证据、回写逐条台账/差距/报告、更新中控及必要入口，再本地提交；本轮不推送远程。
6. 文件中未列代码修复方案，是因为尚未核实全部差距；确认G条目后才能确定真实改动文件和定向检查，不能提前填写猜测的实现代码或全量测试要求。

### 60-01.3 建立入口及证据适用性对应

- 核对五类身份、公共入口、三端实际路由与旧路由跳转；入口关联当前源码文件，不将测试夹具独立当作路由事实。

### 60-01.4 检查交付

运行本包scripts/build_acceptance_coverage.py生成来源登记，再用--check只读复核。预期：75R、10N、13E不重不漏；来源和代码引用可定位；当前接口与路由来自实际来源；金融保持用户确认；无验收通过预填。回写中控后进入60-02。
