### 2.4 核心规范

1. **三端布局**：
   - 居民端/服务人员端：顶部导航 + 内容区（单栏）
   - 管理端：左侧边栏 + 顶部导航 + 内容区

2. **路由设计**：路由前缀区分角色（/resident, /guest, /staff, /admin），按 C1~C12 模块组织

3. **交互规范**：表单交互（实时校验/提交保护）、列表交互（筛选/分页/批量操作）、弹窗交互（二次确认）、状态反馈（Message/Notification）、响应式布局（桌面端 ≥1200px/平板端 768~1199px）

4. **视觉规范**：色彩系统（品牌色/成功色/警告色/危险色/中性色）、排版规范（字体/字号/行高）、间距规范（4px~32px）、圆角与阴影

5. **无障碍设计**：键盘导航（Tab/Enter/ESC/方向键）、焦点指示（蓝色外边框 2px）、语义化标签（nav/main/h1~h6/label/button）、对比度（≥4.5:1 WCAG AA 级）

6. **实时通信**：WebSocket 连接（/ws/notifications, /ws/feedback/{id}）、消息接收（Notification 弹窗 + 未读角标）、断线重连（指数退避 3s→6s→12s→30s）、增量补拉（lastSeq 机制）

7. **权限控制**：菜单权限（五角色映射）、按钮权限（超管独占按钮）、数据过滤（社区管理员限绑定社区）

## 3. 变更管理规则

### 3.1 冻结后变更流程

UI 设计冻结后，任何变更必须遵循以下流程：

1. **提出变更**：说明变更原因（需求变更/设计缺陷/用户反馈）
2. **影响评估**：评估对前端开发、组件库、用户体验的影响
3. **用户审批**：重大变更需用户审批
4. **文档更新**：更新 UI设计.md，记录变更历史
5. **版本递增**：v1.0 → v1.1（小改动）或 v2.0（大改动）
6. **通知下游**：通知前端开发团队

---

### 3.2 变更类型定义

| 变更类型 | 定义 | 审批要求 | 示例 |
|---------|------|---------|------|
| 微调 | 文案优化、颜色微调、间距调整 | 自行修改 | 按钮文案优化 |
| 小改动 | 新增可选字段、布局微调 | 团队确认 | 新增筛选条件 |
| 中等变更 | 新增组件、交互流程调整 | 用户审批 | 新增导出功能 |
| 重大变更 | 新增页面、路由变更、组件库替换 | 用户审批 + 影响评估 | 新增模块页面 |
