## 1. 概念模型（实体关系）

### 1.1 核心实体（45 张表）

按 C1~C12 业务模块分组，每个实体对应一张数据库表：

**C1 社区基础信息管理（7 张表）**
- 社区 `community` — 多社区架构的顶层实体
- 楼栋 `building` → 社区（N:1）
- 单元 `unit` → 楼栋（N:1）
- 房屋 `house` → 单元（N:1），含状态枚举
- 房屋状态历史 `house_status_history` → 房屋（N:1），状态变更留痕
- 公共资源 `public_resource` → 社区（N:1）
- 可预约时段 `resource_timeslot` → 公共资源（N:1）

**C2 居民与居住关系管理（4 张表）**
- 居民 `resident` — 跨社区账号体系
- 入住申请 `residence_application` → 居民 + 社区 + 房屋（N:1）
- 居住关系 `residence_relation` → 居民 + 社区 + 房屋（M:N 关联表）
- 全局配置 `sys_config` — 注册开关等全局级配置

**C3 租住管理（3 张表）**
- 租住记录 `lease_record` → 居民（租客）+ 社区 + 房屋（N:1）
- 到期提醒去重 `lease_reminder` → 租住记录（N:1），唯一约束防重复提醒
- 租约续约支付单 `lease_payment` → 租住记录 + 居民（N:1），在线续租支付流水（V15，R61）

**C4 服务申请与工单管理（5 张表）**
- 服务类别 `service_category` → 社区（N:1）
- 工单 `work_order` → 居民 + 社区 + 服务类别（N:1）
- 工单附件 `work_order_attachment` → 工单（N:1）
- 工单处理记录 `work_order_process` → 工单（N:1），时间线展示
- 工单派单关系 `work_order_assignment` → 工单 + 服务人员（N:1）

**C5 公告广播管理（3 张表）**
- 公告 `notice` — 可跨社区广播
- 公告目标范围 `notice_target` → 公告（N:1），定向发布
- 公告查看记录 `notice_view_record` → 公告 + 用户（M:N 关联表）

**C6 居民反馈管理（3 张表）**
- 反馈单 `feedback` → 居民 + 社区（N:1）
- 反馈附件 `feedback_attachment` → 反馈单（N:1）
- 反馈会话消息 `feedback_message` → 反馈单（N:1），自引用 parent_id

**C7 公共资源预约管理（2 张表）**
- 资源预约 `resource_reservation` → 用户 + 公共资源 + 社区（N:1）
- 违约处置记录 `violation_record` → 用户（N:1）

**C8 服务评价管理（2 张表）**
- 工单评价 `work_order_evaluation` → 工单 + 居民 + 社区（1:1）
- 不满意跟进 `unsatisfied_followup` → 评价（1:1）

**C9 社区运营统计（1 张表，可选）**
- 统计快照 `statistics_snapshot` → 社区（N:1），预聚合优化

**C10 用户与权限管理（5 张表）**
- 系统用户 `sys_user` — 管理员/服务人员账号体系
- 管理员-社区绑定 `sys_admin_community` → 管理员 + 社区（M:N 关联表）
- JWT令牌黑名单 `auth_token_blacklist` — DB 双写降级方案
- 操作日志 `sys_operation_log` — 关键变更留痕
- 拉黑审计日志 `sys_blacklist_log` — 频控与拉黑记录

**C11 消息与通知中心（5 张表）**
- 通知记录 `notification` → 用户（N:1），含全局递增 seq
- 模拟渠道发送记录 `notification_channel_log` → 通知（N:1）
- 多方会话 `conversation` → 社区（可空，不设外键），看房群聊 / 居民-管理员直通（V16，R63）
- 会话参与者 `conversation_participant` → 会话（N:1），多态用户引用 + 已读游标（V16，R63）
- 会话消息 `conversation_message` → 会话（N:1），发送人按角色选表回姓名（V16，R63）

**C12 房源展示与看房预约（4 张表）**
- 房源信息 `housing` → 社区 + 房屋（N:1）
- 看房预约 `viewing_appointment` → 用户 + 房源 + 社区（N:1）；V5/V14/V16 增量列
  （游客姓名电话 / 带看人 assigned_staff_id / 关联会话 conversation_id）见 §9
- 房源可预约时段 `housing_timeslot` → 房源（N:1）
- 看房沟通会话消息 `viewing_message` → 看房预约（N:1），R59 单聊模型（V14；R63 群聊模型取代，表保留兼容）

**横切支撑（1 张表）**
- 定时任务执行日志 `sys_task_log` — 任务监控

### 1.2 关键关系

**1:N 关系（外键约束）**
- community → building → unit → house（4 层层级）
- community → public_resource → resource_timeslot
- work_order → work_order_process / work_order_attachment
- feedback → feedback_message
- notice → notice_target / notice_view_record
- housing → viewing_appointment
- viewing_appointment → viewing_message（R59 单聊消息，V14）
- viewing_appointment → conversation（看房群聊，V16）
- lease_record → lease_payment（租约续约支付单，V15）
- conversation → conversation_participant / conversation_message（多方会话，V16）

**M:N 关系（关联表）**
- resident ↔ house（通过 residence_relation）
- sys_user(管理员) ↔ community（通过 sys_admin_community）
- notice ↔ user（通过 notice_view_record，查看记录）
- conversation ↔ 用户（通过 conversation_participant；user_id 为多态引用不设外键）

**自引用关系**
- feedback_message.parent_id（会话消息回复）

**多态引用（不设外键，口径同 V1 feedback_message.sender_id 先例）**
- viewing_message.sender_id（预约居民=resident.id / 带看人=sys_user.id）
- conversation_participant.user_id、conversation_message.sender_id（居民=resident.id，
  STAFF/ADMIN/SUPER_ADMIN=sys_user.id；居民不在 sys_user 表，单表外键无法表达）
- conversation_message.sender_role 落库时取认证角色，读侧按角色选表回姓名，
  消解 resident.id 与 sys_user.id 两套自增序列的撞号歧义

## 2. 逻辑模型（表结构设计）

### 2.1 命名规范

- **表名**：小写 + 下划线，单数形式（`resident` 而非 `residents`）
- **字段名**：小写 + 下划线，避免保留字（如 `order` → `work_order`）
- **主键**：统一命名为 `id`（BIGINT UNSIGNED AUTO_INCREMENT）
- **外键**：`关联表名_id`（如 `community_id`、`resident_id`）
- **时间戳**：`created_at` / `updated_at` / `deleted_at`
- **软删除**：`is_deleted` (TINYINT) + `deleted_at` (DATETIME)

### 2.2 字段类型约定

| 用途 | 类型 | 说明 |
|------|------|------|
| 主键 | BIGINT UNSIGNED AUTO_INCREMENT | 统一主键类型 |
| 外键 | BIGINT UNSIGNED | 统一外键类型，必加索引 |
| 状态枚举 | VARCHAR(20) | 灵活性优先，代码层控制 |
| 短文本 | VARCHAR(长度) | 标题/名称/编号 |
| 长文本 | TEXT | 内容/描述/备注 |
| 金额 | DECIMAL(10, 2) | 租金/价格 |
| 布尔 | TINYINT(1) | 0/1 |
| 日期 | DATE | 业务日期（租期起止） |
| 时间 | TIME | 时段（08:00:00） |
| 日期时间 | DATETIME | 时间戳，默认 CURRENT_TIMESTAMP |
| JSON | JSON | 扩展字段/操作内容 |

#### 3.3.3 lease_payment（租约续约支付单）

> 来源：V15__lease_payment.sql（需求规格 v1.4 R61，决策日志 2026-09-20）。
> 居民在线续租支付单（支付宝电脑网站支付 / 微信 Native 扫码）。

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | BIGINT UNSIGNED | PRIMARY KEY AUTO_INCREMENT | 支付单ID |
| payment_no | VARCHAR(64) | NOT NULL | 业务单号（RENEW+yyyyMMdd+6位随机） |
| lease_id | BIGINT UNSIGNED | NOT NULL | 租住记录ID |
| resident_id | BIGINT UNSIGNED | NOT NULL | 付款人ID（resident.id） |
| channel | VARCHAR(16) | NOT NULL | 支付渠道：ALIPAY-支付宝, WECHAT-微信 |
| months | INT | NOT NULL | 续租月数 |
| amount | DECIMAL(10, 2) | NOT NULL | 应付金额（月租×月数，服务端计算） |
| status | VARCHAR(16) | NOT NULL DEFAULT 'PENDING' | 状态：PENDING-待支付, SUCCESS-已支付, CLOSED-已关闭 |
| channel_trade_no | VARCHAR(64) | NULL | 渠道流水号（支付成功后回写） |
| paid_at | DATETIME | NULL | 支付完成时间 |
| created_at | DATETIME | NOT NULL DEFAULT CURRENT_TIMESTAMP | 创建时间 |
| updated_at | DATETIME | NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP | 更新时间 |

**索引**：
- PRIMARY KEY (id)
- UNIQUE KEY uk_payment_no (payment_no)
- INDEX idx_lease_id (lease_id)
- INDEX idx_resident_id (resident_id)
- INDEX idx_status (status)

**外键**：
- FOREIGN KEY (lease_id) REFERENCES lease_record(id)
- FOREIGN KEY (resident_id) REFERENCES resident(id)

**约束**：
- 状态机：`PENDING → SUCCESS / CLOSED`（后两者终态）
- 幂等口径（应用层校验，MySQL 无部分唯一索引故不建库级约束）：同 lease_id
  仅允许一个进行中（PENDING）支付单
- 金额由服务端按月租×月数计算，客户端不可传金额
- 成功落账（同一事务、幂等不重复延展）：回写支付单 status/channel_trade_no/paid_at
  + 租约 end_date 顺延 months 个月 + 通知居民与社区管理员

## 4. 物理模型（索引与约束策略）

### 4.1 索引设计总结

#### 4.1.1 主键索引（自动创建）
所有表统一使用 `id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY`

#### 4.1.2 外键索引（必须创建）
所有外键字段自动创建索引，优化关联查询：
- `community_id`、`building_id`、`unit_id`、`house_id`
- `resident_id`、`user_id`、`operator_id`
- `work_order_id`、`feedback_id`、`notice_id`
- `resource_id`、`housing_id`

#### 4.1.3 唯一索引（业务约束）

| 表 | 唯一索引 | 说明 |

| **resource_reservation** | idx_resource_date (resource_id, reserve_date, status) | 冲突校验（R33） |
| **auth_token_blacklist** | idx_expire_time (expire_time) | 定时清理过期黑名单 |
| **sys_operation_log** | idx_operator_id (operator_id, created_at)<br>idx_target (target_type, target_id, created_at) | 按操作人查询<br>按目标对象查询 |

**其他业务优化索引**：

| 表 | 复合索引 | 查询场景 |
|---|---------|---------|
| resident | idx_status (status) | 按状态查询居民 |
| work_order | idx_resident_id (resident_id, status) | 居民工单列表 |

| sys_task_log | idx_task_name (task_name, start_time) | 任务执行历史 |

#### 4.1.5 软删除索引

所有软删除表增加复合索引 `idx_is_deleted (is_deleted, community_id)`，优化过滤查询。

### 4.2 外键约束策略

**约束行为**：
- `ON DELETE RESTRICT`（默认）：防止误删被引用数据
- `ON UPDATE CASCADE`：主键更新时级联更新外键

**例外情况**：
- 日志表不设外键约束（性能优先，避免锁等待）
- 跨模块引用使用应用层控制

### 4.3 字符集与排序规则

```sql
CREATE DATABASE community_residence_service
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;
```

- **utf8mb4**：支持完整 Unicode（含 emoji）
- **utf8mb4_unicode_ci**：不区分大小写，多语言排序准确

### 4.4 分区表设计（可选优化）

**操作日志按月分区**（保留 ≥4年，N6）：

```sql
CREATE TABLE sys_operation_log (
  ...
) PARTITION BY RANGE (YEAR(created_at) * 100 + MONTH(created_at)) (
  PARTITION p202601 VALUES LESS THAN (202602),
  PARTITION p202602 VALUES LESS THAN (202603),
  ...
  PARTITION p203012 VALUES LESS THAN (203101),
  PARTITION pmax VALUES LESS THAN MAXVALUE
);
```

**任务日志按周分区**（保留 1年）：

```sql
CREATE TABLE sys_task_log (
  ...
) PARTITION BY RANGE (TO_DAYS(created_at)) (
  PARTITION p20260101 VALUES LESS THAN (TO_DAYS('2026-01-08')),
  ...
);
```

**说明**：
- 分区表提升大数据量下的查询和删除性能
- 自动删除旧分区（`ALTER TABLE ... DROP PARTITION`）
