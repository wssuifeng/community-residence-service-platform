## 1. 概述

### 1.1 设计目标

为社区居住服务管理系统设计三端界面：
1. **居民端**：面向居民的消费者界面，强调美观与易用性
2. **服务人员工作台**：面向服务人员的任务处理界面，强调效率与清晰度
3. **管理员后台**：面向社区管理员与超级管理员的管理界面，强调功能全面与数据可视化

### 1.2 设计原则

1. **角色分离**：三端界面独立设计，避免混淆
2. **权限可见**：界面元素根据用户角色与权限动态显示
3. **响应式布局**：适配桌面端（主要）与平板端（次要）
4. **一致性**：统一组件规范、交互模式、视觉风格
5. **可访问性**：符合 WCAG 2.1 AA 级标准

### 1.3 组件策略

- **自写为主**：核心业务组件自行编写，保证美观与个性化
- **Element Plus 可用不依赖**：通用组件（表格/分页/弹窗/表单）可引用 Element Plus 加速开发，但经业务薄封装层引用，不与组件库强绑定
- **可整体替换**：架构上组件库可整体切换，不影响业务逻辑

### 1.4 技术栈

- **前端框架**：Vue 3.5 + Vite 8 + TypeScript
- **状态管理**：Pinia 3
- **路由管理**：Vue Router 4.6
- **HTTP 客户端**：Axios 1.16
- **组件库**：Element Plus 2.14（可选引用）
- **图表库**：ECharts 6 + vue-echarts 8
- **测试**：Vitest 4

## 2. 整体布局架构

### 2.1 居民端布局

**布局类型**：顶部导航 + 内容区（单栏）

```
┌─────────────────────────────────────┐
│ Header（Logo + 导航 + 用户菜单）    │
├─────────────────────────────────────┤
│                                     │
│          内容区（单栏）              │
│                                     │
│                                     │
└─────────────────────────────────────┘
```

**特点**：
- 强调内容展示，弱化管理功能
- 顶部导航固定，内容区滚动
- 移动端友好（顶部导航可折叠）

---

### 2.2 服务人员工作台布局

**布局类型**：顶部导航 + 内容区（单栏）

```
┌─────────────────────────────────────┐
│ Header（Logo + 导航 + 用户菜单）    │
├─────────────────────────────────────┤
│                                     │
│          内容区（单栏）              │
│          （工单列表 + 详情）         │
│                                     │
└─────────────────────────────────────┘
```

**特点**：
- 强调任务处理效率
- 工单卡片式布局，快速筛选与操作
- 实时通知提醒（WebSocket 推送）

---

### 2.3 管理员后台布局

**布局类型**：左侧边栏 + 顶部导航 + 内容区

```
┌──────┬───────────────────────────────┐
│      │ Header（面包屑 + 用户菜单）   │
│  侧  ├───────────────────────────────┤
│  边  │                               │
│  栏  │          内容区                │
│      │     （数据表格 + 表单）        │
│      │                               │
└──────┴───────────────────────────────┘
```

**特点**：
- 左侧边栏固定，按功能模块组织
- 内容区支持多标签页（可选）
- 数据表格 + 搜索筛选 + 批量操作
- 运营看板采用卡片 + 图表布局

## 4. 核心页面设计

### 4.1 居民端核心页面

#### 4.1.1 首页（/resident/home）

**布局**：顶部导航 + 轮播公告 + 快捷入口卡片

**核心元素**：
- **轮播公告**：置顶公告轮播（3-5 条）
- **快捷入口**：工单提交、反馈提交、资源预约、房源浏览（4 个卡片）
- **最新公告列表**：最近 10 条公告（标题 + 发布时间 + 阅读数）

**交互**：
- 点击快捷入口卡片跳转对应功能
- 点击公告标题查看详情并记录查看记录

---

#### 4.1.2 工单列表（/resident/work-orders）

**布局**：筛选栏 + 工单卡片列表 + 分页

**核心元素**：
- **筛选栏**：状态筛选（全部/待受理/处理中/已完成）+ 搜索框
- **新建按钮**：右上角「提交工单」按钮
- **工单卡片**：
  - 工单号 + 状态标签
  - 类别 + 标题
  - 提交时间 + 当前处理人
  - 操作按钮：查看详情、取消（待受理）、确认（待确认）、评价（已完成）

**交互**：
- 状态筛选切换工单列表
- 点击卡片进入详情页

---

#### 4.1.3 工单详情（/resident/work-orders/:id）

**布局**：面包屑 + 工单信息卡片 + 时间线 + 操作区

**核心元素**：
- **工单信息卡片**：
  - 工单号 + 状态标签
  - 类别 + 标题 + 描述
  - 提交时间 + 预约上门时间
  - 附件图片（多张，点击放大）
- **时间线**：
  - 提交 → 受理 → 派单 → 接单 → 处理中 → 待确认 → 已完成 → 已关闭
  - 每个节点显示操作人 + 时间 + 备注
  - 处理结果节点显示服务人员提交的文字 + 图片
- **操作区**：
  - 取消工单（待受理/待派单）
  - 确认完成（待确认）
  - 退回处理（待确认，填写原因）
  - 评价工单（已完成）

**交互**：
- 点击附件图片弹窗查看大图
- 确认/退回弹窗二次确认
- 评价弹窗：星级评分 + 评价文字

---

#### 4.1.4 反馈详情 + 会话（/resident/feedbacks/:id）

**布局**：面包屑 + 反馈信息卡片 + 会话区 + 输入框

**核心元素**：
- **反馈信息卡片**：
  - 反馈单号 + 状态标签
  - 标题 + 内容
  - 提交时间 + 附件
- **会话区**：
  - 消息列表（居民消息居右，管理员消息居左）
  - 每条消息显示：头像 + 昵称 + 时间 + 内容
  - WebSocket 实时接收新消息
- **输入框**：
  - 文本输入框 + 发送按钮
  - 支持 Enter 发送

**交互**：
- 发送消息通过 WebSocket 推送到管理员
- 接收管理员消息实时显示
- 自动滚动到最新消息

---

#### 4.1.5 资源预约创建（/resident/reservations/create）

**布局**：面包屑 + 表单

**核心元素**：
- **资源选择**：下拉框（展示资源名称 + 类型 + 位置）
- **日期选择**：日期选择器
- **时段选择**：可预约时段列表（单选，禁用已被预约的时段）
- **备注**：文本框（可选）
- **提交按钮**

**交互**：
- 选择资源后加载可预约时段
- 选择日期后刷新时段可用性
- 提交后跳转预约列表并显示成功提示

---

#### 4.1.6 房源详情（/resident/housings/:id）

**布局**：面包屑 + 房源图片 + 信息卡片 + 时段选择 + 预约按钮

**核心元素**：
- **房源图片**：多图轮播（主图 + 细节图）
- **信息卡片**：
  - 房源标题 + 社区名称
  - 面积 + 户型 + 朝向 + 楼层
  - 租金 + 押金 + 物业费
  - 房源描述
  - 配套设施标签
- **时段选择**：
  - 日期选择器
  - 可预约时段列表（单选）
- **预约按钮**：「预约看房」

**交互**：
- 轮播图片切换
- 选择日期后加载可预约时段
- 点击预约按钮提交看房预约（居民/游客）

## 6. 交互模式与规范

### 6.1 表单交互规范

#### 6.1.1 表单校验

- **实时校验**：失焦时校验单个字段，红色错误提示显示在字段下方
- **提交校验**：提交前整体校验，首个错误字段自动聚焦
- **必填标识**：必填字段 label 后标红色星号（*）
- **长度提示**：超长输入实时显示字符计数（如"50/100"）

#### 6.1.2 表单提交

- **提交中状态**：按钮 loading + 禁用，防止重复提交
- **提交成功**：弹窗提示 + 跳转列表页或关闭弹窗
- **提交失败**：错误提示（Message）+ 保持表单内容

---

### 6.2 列表交互规范

#### 6.2.1 数据加载

- **初次加载**：表格 loading 骨架屏
- **筛选刷新**：表格 loading + 保持筛选条件
- **空状态**：无数据时显示空状态插图 + 提示文案

#### 6.2.2 操作按钮

- **操作列宽度**：固定 120-180px
- **按钮间距**：文本按钮间距 8px
- **权限控制**：无权限的按钮隐藏（不显示禁用态）
- **危险操作**：删除/停用/驳回等红色文本按钮

#### 6.2.3 批量操作

- **勾选行**：表格首列 checkbox
- **批量操作栏**：勾选后表格上方显示批量操作栏（已选 N 项 + 操作按钮）
- **二次确认**：批量删除/停用弹窗确认

---

### 6.3 弹窗交互规范

#### 6.3.1 弹窗类型

- **表单弹窗**：宽度 600px，高度自适应，带取消/确定按钮
- **确认弹窗**：MessageBox 确认框，带取消/确定按钮
- **详情弹窗**：宽度 800px，高度自适应，只读展示，带关闭按钮
- **大型弹窗**：全屏或 80% 屏幕，带关闭按钮（如富文本编辑）

#### 6.3.2 弹窗行为

- **蒙层点击**：不关闭弹窗（防止误操作）
- **ESC 键**：关闭弹窗
- **关闭前确认**：表单有修改时弹窗二次确认

---

### 6.4 状态反馈规范

#### 6.4.1 消息提示（Message）

- **成功**：绿色，2 秒后自动关闭
- **警告**：橙色，3 秒后自动关闭
- **错误**：红色，4 秒后自动关闭
- **信息**：蓝色，3 秒后自动关闭

#### 6.4.2 通知（Notification）

- **系统通知**：右上角弹出，5 秒后自动关闭
- **实时消息**：WebSocket 推送，右上角弹出，点击跳转详情
- **未读角标**：通知中心图标显示未读数（最大 99+）

---

### 6.5 响应式规范

#### 6.5.1 断点定义

- **桌面端**：≥1200px（主要适配）
- **平板端**：768px ~ 1199px（次要适配）
- **移动端**：<768px（不适配，提示使用桌面端）

#### 6.5.2 响应式策略

- **导航栏**：平板端折叠为汉堡菜单
- **侧边栏**：平板端默认收起，点击展开
- **数据表格**：平板端横向滚动
- **操作按钮**：平板端部分隐藏，显示"更多"下拉

## 8. 无障碍设计

### 8.1 键盘导航

- **Tab 键**：焦点在可交互元素间切换
- **Enter 键**：激活按钮/提交表单
- **ESC 键**：关闭弹窗/取消操作
- **方向键**：在列表/下拉框中导航

### 8.2 焦点指示

- **焦点样式**：蓝色外边框（2px solid #409EFF）
- **焦点顺序**：从上到下、从左到右

### 8.3 语义化标签

- **导航**：`<nav>` 标签
- **主内容**：`<main>` 标签
- **标题**：`<h1>` ~ `<h6>` 层级清晰
- **表单**：`<label>` 关联 `<input>`
- **按钮**：`<button>` 而非 `<div onclick>`

### 8.4 对比度

- **正文文字**：对比度 ≥4.5:1（WCAG AA 级）
- **大号文字**：对比度 ≥3:1
- **图标按钮**：对比度 ≥3:1

- **登录后**：自动连接 `/ws/notifications`
- **连接成功**：右上角通知中心图标显示在线状态（绿点）
- **连接失败**：显示离线状态（灰点）+ 3 秒后自动重连

#### 9.1.2 消息接收

- **通知消息**：
  - 右上角弹出 Notification（标题 + 内容 + 时间）
  - 未读角标数字 +1
  - 通知列表实时插入新消息
- **反馈会话消息**：
  - 反馈详情页会话区实时插入新消息
  - 自动滚动到最新消息
  - 页面未激活时浏览器标题显示"[新消息] 社区居住服务管理系统"

#### 9.1.3 断线重连

- **断线检测**：心跳包 30 秒无响应判定断线
- **重连策略**：指数退避（3s → 6s → 12s → 30s）
- **重连成功**：调用增量补拉接口（GET /api/v1/notifications/pull?lastSeq=xxx）

---

### 9.2 增量补拉机制

#### 9.2.1 补拉时机

- **上线时**：登录后连接 WebSocket 前调用补拉接口
- **重连时**：WebSocket 重连成功后调用补拉接口

#### 9.2.2 补拉流程

1. 客户端从本地存储读取 `lastSeq`（上次接收的最大序号）
2. 调用 `GET /api/v1/notifications/pull?lastSeq=xxx`
3. 服务端返回 `seq > lastSeq` 的通知列表
4. 客户端插入通知列表 + 更新未读数 + 更新 `lastSeq`
