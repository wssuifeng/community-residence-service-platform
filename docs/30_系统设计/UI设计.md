## 1. 概述

### 1.1 设计目标

为社区居住服务管理系统设计三端界面：
1. **居民端**：面向居民的消费者界面，强调美观与易用性
2. **服务人员工作台**：面向服务人员的任务处理界面，强调效率与清晰度
3. **管理员后台**：面向社区管理员与超级管理员的管理界面，强调功能全面与数据可视化

### 1.2 设计原则

1. **角色分离**：三端界面独立设计，避免混淆
2. **权限可见**：界面元素根据用户角色与权限动态显示
3. **响应式布局**：适配桌面端（主要）与平板端（次要）
4. **一致性**：统一组件规范、交互模式、视觉风格
5. **可访问性**：符合 WCAG 2.1 AA 级标准

### 1.3 组件策略

- **自写为主**：核心业务组件自行编写，保证美观与个性化
- **Element Plus 可用不依赖**：通用组件（表格/分页/弹窗/表单）可引用 Element Plus 加速开发，但经业务薄封装层引用，不与组件库强绑定
- **可整体替换**：架构上组件库可整体切换，不影响业务逻辑

### 1.4 技术栈

- **前端框架**：Vue 3.5 + Vite 8 + TypeScript
- **状态管理**：Pinia 3
- **路由管理**：Vue Router 4.6
- **HTTP 客户端**：Axios 1.16
- **组件库**：Element Plus 2.14（可选引用）
- **图表库**：ECharts 6 + vue-echarts 8
- **测试**：Vitest 4

```
┌─────────────────────────────────────┐
│ Header（Logo + 导航 + 用户菜单）    │

│                                     │
│          内容区（单栏）              │
```

**特点**：
- 强调内容展示，弱化管理功能

- 移动端友好（顶部导航可折叠）

  合并三源按时间倒序：`GET /leases/{id}/changes`（状态流转，§9.17.1）+ 
  `GET /leases/{id}/payments`（支付流水，§9.19.13 **字段扩展后**）+ `GET /leases/{id}/deposit-refunds`
  （退款流水）；条目展示**类型标识**（状态 / 支付 / 退款）+ **支付项目** +
  **金额构成拆分**（月租部分 / 押金部分分别列出）+ **覆盖租期区间** + 业务单号 +
  **渠道流水号** + 创建与完成时间（口径见接口设计 §9.20.3）；空态文案与既有风格一致。

**★ 租约状态呈现位置（唯一口径，v1.1 明确）**：

- **租约状态只在「我的租约」（`/resident/housing-lease?tab=lease`）呈现**；
- **消息中心（`/resident/notifications`）只承载「通知」与「沟通会话」两个 tab，不呈现租约状态**；
- **租约类通知点击必须跳转到「我的租约」对应租约**：
  - `sourceType='LEASE'` 且 `sourceId` 为租约 ID → 居民端 `/resident/housing-lease?tab=lease&leaseId={id}`，
    管理端 `/admin/leases/{id}`；
  - **`LEASE_AGREEMENT` / `LEASE_PAYMENT` 的 `sourceId` 不是租约 ID** → 一律只落列表页
    （居民 `/resident/housing-lease?tab=lease`、管理端 `/admin/leases`），
    **禁止拼接 `/leases/{id}`**（防跳转到错误或不存在的租约详情）；
  - 通知列表把 `LEASE*` 从「系统」分类拆出为独立 **「租约」** 分类
    （保留 `SYSTEM` / `TASK` 兜底分类）。
- 「我的租约」支持 `?leaseId=` 深链定位并高亮对应租约卡片（消息中心跳转落地用）。

    「受理后将自动建立工单沟通群」的占位提示）；

- **操作区**：
  - 取消工单（待受理/待派单）
  - 确认完成（待确认）
  - 退回处理（待确认，填写原因）
  - 评价工单（已完成）

**交互**：
- 点击附件图片弹窗查看大图
- 确认/退回弹窗二次确认
- 评价弹窗：星级评分 + 评价文字

## 6. 交互模式与规范

### 6.1 表单交互规范

#### 6.1.1 表单校验

- **实时校验**：失焦时校验单个字段，红色错误提示显示在字段下方
- **提交校验**：提交前整体校验，首个错误字段自动聚焦
- **必填标识**：必填字段 label 后标红色星号（*）
- **长度提示**：超长输入实时显示字符计数（如"50/100"）

#### 6.1.2 表单提交

- **提交中状态**：按钮 loading + 禁用，防止重复提交
- **提交成功**：弹窗提示 + 跳转列表页或关闭弹窗
- **提交失败**：错误提示（Message）+ 保持表单内容

---

### 6.2 列表交互规范

#### 6.2.1 数据加载

- **初次加载**：表格 loading 骨架屏
- **筛选刷新**：表格 loading + 保持筛选条件
- **空状态**：无数据时显示空状态插图 + 提示文案

#### 6.2.2 操作按钮

- **操作列宽度**：固定 120-180px
- **按钮间距**：文本按钮间距 8px
- **权限控制**：无权限的按钮隐藏（不显示禁用态）
- **危险操作**：删除/停用/驳回等红色文本按钮

#### 6.2.3 批量操作

- **勾选行**：表格首列 checkbox
- **批量操作栏**：勾选后表格上方显示批量操作栏（已选 N 项 + 操作按钮）
- **二次确认**：批量删除/停用弹窗确认

---

### 6.3 弹窗交互规范

#### 6.3.1 弹窗类型

- **表单弹窗**：宽度 600px，高度自适应，带取消/确定按钮
- **确认弹窗**：MessageBox 确认框，带取消/确定按钮
- **详情弹窗**：宽度 800px，高度自适应，只读展示，带关闭按钮
- **大型弹窗**：全屏或 80% 屏幕，带关闭按钮（如富文本编辑）

#### 6.3.2 弹窗行为

- **蒙层点击**：不关闭弹窗（防止误操作）
- **ESC 键**：关闭弹窗
- **关闭前确认**：表单有修改时弹窗二次确认

---

### 6.4 状态反馈规范

#### 6.4.1 消息提示（Message）

- **成功**：绿色，2 秒后自动关闭
- **警告**：橙色，3 秒后自动关闭
- **错误**：红色，4 秒后自动关闭
- **信息**：蓝色，3 秒后自动关闭

#### 6.4.2 通知（Notification）

- **系统通知**：右上角弹出，5 秒后自动关闭

## 9. 实时通信交互

### 9.1 WebSocket 连接

#### 9.1.1 连接建立

- **登录后**：自动连接 `/ws/notifications`
- **连接成功**：右上角通知中心图标显示在线状态（绿点）
- **连接失败**：显示离线状态（灰点）+ 3 秒后自动重连

#### 9.1.2 消息接收

- **通知消息**：
  - 右上角弹出 Notification（标题 + 内容 + 时间）
  - 未读角标数字 +1
  - 通知列表实时插入新消息
- **反馈会话消息**：
  - 反馈详情页会话区实时插入新消息
  - 自动滚动到最新消息
  - 页面未激活时浏览器标题显示"[新消息] 社区居住服务管理系统"

#### 9.1.3 断线重连

- **断线检测**：心跳包 30 秒无响应判定断线
- **重连策略**：指数退避（3s → 6s → 12s → 30s）
- **重连成功**：调用增量补拉接口（GET /api/v1/notifications/pull?lastSeq=xxx）

---

### 9.2 增量补拉机制

#### 9.2.1 补拉时机

- **上线时**：登录后连接 WebSocket 前调用补拉接口
- **重连时**：WebSocket 重连成功后调用补拉接口

#### 9.2.2 补拉流程

1. 客户端从本地存储读取 `lastSeq`（上次接收的最大序号）
2. 调用 `GET /api/v1/notifications/pull?lastSeq=xxx`
3. 服务端返回 `seq > lastSeq` 的通知列表
4. 客户端插入通知列表 + 更新未读数 + 更新 `lastSeq`
