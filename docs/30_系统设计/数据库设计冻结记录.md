## 三、设计成果总结

### 3.1 表结构统计

- **总表数**：40 张（47 张计划表中，7 张合并优化）
- **业务模块**：C1~C12 共 12 个模块 + 1 个横切模块
- **核心实体**：community, building, unit, house, resident, work_order, notice, feedback 等
- **关联表**：residence_relation, sys_admin_community, notice_view_record（M:N 关系）
- **日志表**：sys_operation_log, sys_task_log, house_status_history, work_order_process

### 3.2 关键设计特性

| 特性 | 实现方式 | 对应需求 |
|------|---------|---------|
| 多社区数据隔离 | 21 张表挂 community_id | 架构设计 §3.2 |
| JWT 黑名单 DB 双写 | auth_token_blacklist 表 | 架构设计 §3.1 |
| 通知增量补拉 | notification.seq 字段（Redis INCR） | R50 |
| 租期到期提醒去重 | lease_reminder 表，uk_lease_status | R15 |
| 软删除保护 | 5 张核心实体表（is_deleted + deleted_at） | R6 |
| 操作日志留痕 | sys_operation_log（仅追加，≥4年） | R47, N6 |
| 预约冲突校验 | 复合索引 + 应用层锁 | R33, R55 |
| 密码安全存储 | password_hash（BCrypt） | N4 |
| 6 套状态机 | VARCHAR(20) 状态字段 + 枚举值 | 架构设计 §6 |

### 3.3 索引策略

- **主键索引**：40 个（自动创建）
- **外键索引**：50+ 个（全覆盖）
- **唯一索引**：12 个（业务约束）
  - auth_token_blacklist.jti
  - lease_reminder(lease_id, status)
  - work_order_evaluation.work_order_id
  - sys_admin_community(admin_id, community_id)
  - notice_view_record(notice_id, user_id)
  - sys_config.config_key
  - 等
- **复合索引**：15+ 个（高频查询优化）
  - notice(community_id, status, publish_time)
  - work_order(community_id, status, created_at)
  - notification(user_id, seq)
  - resource_reservation(resource_id, reserve_date, status)
  - lease_record(status, end_date)
  - 等

### 3.4 分区表方案（可选优化）

| 表 | 分区策略 | 保留期 | 实施状态 |
|---|---------|--------|---------|
| sys_operation_log | 按月分区（RANGE PARTITION） | ≥4年 | 📋 已设计，40 阶段根据数据量评估 |
| sys_task_log | 按周分区（RANGE PARTITION） | 1年 | 📋 已设计，40 阶段根据数据量评估 |

## 五、变更管理规则

**冻结后变更规则**：

1. **禁止变更**（需重新评审）：
   - 删除表/字段
   - 修改主键/外键关系
   - 修改唯一约束
   - 修改状态机枚举值

2. **允许变更**（记录决策日志）：
   - 新增表/字段（向后兼容）
   - 新增索引（性能优化）
   - 调整字段长度（放宽限制）
   - 新增枚举值（状态机扩展）

3. **轻量变更**（无需审批）：
   - 字段注释修正
   - 索引名称调整
   - 默认值优化

**变更流程**：
- 提出变更 → 评估影响范围 → 决策日志记录 → Flyway 新增迁移脚本 → 文档同步更新
