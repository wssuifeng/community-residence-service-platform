# 需求设计追踪矩阵

> 30 阶段设计产物与 20 阶段需求条目的双向追踪表。上游唯一来源：
> `20_需求分析/需求规格说明.md`（R1~R57 / N1~N10 / E1~E12 + E10b）。
>
> 使用纪律：
> - 每份设计产物定稿或修订时，回填对应列的「§章节」；R 级精确映射
>   在各设计文档内部逐条声明（本表按 C 归组收口，避免两份 57 行长表漂移）；
> - 验收自查：任一需求行存在空列 → 该需求未被该产物覆盖，产物不得定稿；
> - 无法覆盖的条目 → 停下来回 20 包核对口径，按依赖向上填补规则处理，
>   不允许在设计层私自删改或弱化需求。

## 二、非功能性需求

「预期落点」为设计分工的初始假设，产物回填「§章节」后以实际落点为准；
跨产物条目（如 N5）在多个产物列同时回填。

| 编号 | 要点（摘自 20 包） | 预期落点 | 设计内位置 |
|------|------------------|---------|-----------|
| N1 | 常规查询 P95 ≤ 2 秒（50 并发） | 架构（缓存/分页策略）；50 阶段压测复核 | 架构 §1（无状态）；索引/分页详述在数据库设计 |
| N2 | ≥ 50 并发在线 / ≥ 200 注册账号不劣化 | 架构（无状态 JWT / Redis） | 架构 §1 |
| N3 | 通知在线送达 ≤ 3 秒；会话消息 ≤ 3 秒 | 架构（长连接选型）+ 接口 | 架构 §4 |
| N4 | BCrypt 存储；JWT 有效期/刷新/登出失效 | 架构（Security 骨架）+ 数据库（用户表） | 架构 §3.1 |
| N5 | 五角色越权 100% 拒绝并记录；社区数据越权 100% 过滤 | 架构（两层权限模型）+ 数据库（社区归属列）+ 接口（权限标注） | 架构 §3.2 |
| N6 | 操作日志仅追加、保留 ≥ 4 年 | 数据库（日志表）+ 架构（切面留痕） | 架构 §2 `log` 模块（表结构在数据库设计） |
| N7 | 5 社区 / 5000 房屋 / 年万工单不劣化 | 数据库（索引 / 分页 / 容量验证） | （数据库设计回填） |
| N8 | Chrome / Edge / Firefox 最新两个大版本 | UI（兼容性口径） | （UI 设计回填） |
| N9 | 单机可部署；启动脚本；无付费第三方依赖 | 架构（部署图），70 阶段细化 | 架构 §7 |
