# 看房预约注册居民化实施计划

日期：2026-10-08
依据设计：`docs/superpowers/specs/2026-10-08-registered-viewing-appointments-design.md`

## 目标

按用户裁决的方案 B，把“看房预约”从游客可写能力收敛为注册居民账号能力，同时保持游客房源与可预约时段的公开浏览，并兼容历史游客预约数据。

## 实施步骤

1. **上游定义与决策留痕**
   - 在 `90_全局/决策日志.md` 记录：不采用短信验证码，预约要求注册并登录居民账号。
   - 更新 `10_系统定义/系统定义.md` 的版本、游客职责、C12 验收边界与冻结说明。
   - 更新 `20_需求分析/需求规格说明.md` 的权限矩阵、游客/居民看房预约需求与验收标准。
   - 更新 `90_全局/术语表.md` 的“游客”“看房预约”定义。

2. **接口与交互设计同步**
   - 更新 `30_系统设计/接口设计.md` 的 C12 权限、请求体、数据级权限与取消规则。
   - 更新 `30_系统设计/UI设计.md` 的游客路由、房源详情入口与居民预约页交互。

3. **后端权限闭环**
   - 收紧 `SecurityConfig` 的公开路由。
   - 为创建、详情、取消补齐 Controller 角色注解/方法级契约。
   - 在 `ViewingAppointmentService` 增加居民身份防线、详情数据级权限与取消角色分支。
   - 保留历史游客字段和历史数据的管理端读取兼容，不新增匿名写路径。

4. **前端入口与表单收口**
   - 游客详情页引导登录/注册并保留回跳。
   - 居民预约页移除游客身份字段并按居民身份提交。
   - API 类型和页面测试夹具同步到注册居民契约。

5. **自动化回归**
   - 先增加失败测试，再修改实现。
   - 覆盖未认证 / STAFF / ADMIN / RESIDENT 的创建、详情、取消权限矩阵。
   - 覆盖居民本人/他人数据级权限、管理端历史游客数据读取、前端游客跳登录和居民提交。

6. **浏览器模拟手测**
   - 启动后端与前端。
   - 游客浏览房源、时段，点击预约跳登录。
   - 登录 `resident1` 后回到原房源详情并提交预约。
   - 验证居民列表/取消，以及管理端确认、分配、完成和已有 R63 看房群聊。
   - 检查 1440/1024/768 视口、控制台和 API 失败。

7. **文档与分阶段提交**
   - 回写 `50_系统测试/_中控.md` 与 `08_缺陷跟踪与回归.md`，将 DEF-158 从“待裁决”改为方案 B 的实现与回归记录。
   - 必要时同步总控当前批次描述，但不宣称 50 阶段整体通过。
   - 提交拆分为：文档/设计、后端权限、前端交互与测试证据；每次只纳入本任务文件。

## 不在本次范围

- 短信验证码、预约编号、游客匿名查询/取消新链路。
- 历史游客预约数据迁移或删除。
- 与看房预约无关的公共资源、V29 图片、论文和其他未提交改动。
