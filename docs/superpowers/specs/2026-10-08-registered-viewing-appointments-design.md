# 看房预约注册居民化设计说明

日期：2026-10-08
范围：C12 看房预约（R54~R60、R63 相关房源页入口）
裁决来源：用户选择方案 B——游客只浏览，预约必须注册并登录居民账号；不引入手机号短信验证码预约。

## 1. 目标与边界

- 游客可以浏览公开房源、房源详情和未来可预约看房时段。
- 未登录游客不能创建、查询或取消看房预约。
- 居民账号登录后可以在房源详情发起预约，在「我的预约」查看本人预约，并取消本人仍处于可取消状态的预约。
- 社区管理员 / 超级管理员继续负责预约确认、分配带看人、完成登记、违约处置和绑定社区范围内的详情查询。
- 服务人员只消费被分配的预约，不获得创建或取消预约的权限。
- 不新增短信验证码、预约编号、匿名凭据或游客预约新数据路径。
- 既有数据库中的 `visitor_name`、`visitor_phone` 与历史游客预约数据暂时保留，作为兼容字段；新建预约必须带 `user_id`，历史数据仍可由管理端读取。

## 2. 业务权限模型

| 能力 | 游客 | 未登录 | 居民 | 服务人员 | 管理员 | 超级管理员 |
|---|---|---|---|---|---|---|
| 浏览房源 | 允许 | 允许 | 允许 | 允许 | 允许 | 允许 |
| 查看可预约时段 | 允许 | 允许 | 允许 | 允许 | 允许 | 允许 |
| 创建看房预约 | 不允许 | 不允许 | 本人 | 不允许 | 不允许（仅管理） | 不允许（仅管理） |
| 查询预约详情 | 不允许 | 不允许 | 本人 | 被分配预约 | 绑定社区 | 全局 |
| 查询预约列表 | 不允许 | 不允许 | 本人 | 被分配预约 | 绑定社区 | 全局 |
| 取消预约 | 不允许 | 不允许 | 本人 | 不允许 | 绑定社区 | 全局 |
| 确认 / 分配 / 完成 / 违约 | 不允许 | 不允许 | 不允许 | 不允许 | 绑定社区 | 全局 |

## 3. 前后端契约

### 3.1 API

- `POST /api/v1/viewing-appointments`：`RESIDENT`；服务端从 JWT 取居民身份，忽略/拒绝游客姓名字段，不允许匿名写入。
- `GET /api/v1/viewing-appointments/{id}`：`RESIDENT / STAFF / ADMIN / SUPER_ADMIN`；居民仅本人，服务人员仅被分配预约，管理员按社区数据权限。
- `GET /api/v1/viewing-appointments`：保留现有居民、服务人员、管理端列表权限；不公开。
- `PATCH /api/v1/viewing-appointments/{id}/cancel`：`RESIDENT / ADMIN / SUPER_ADMIN`；居民仅本人，服务人员明确拒绝。
- 房源详情、房源列表、可预约时段与浏览计数接口继续公开只读。

### 3.2 DTO / 数据兼容

- 新建请求不再要求游客姓名；联系电话改为可选，居民缺省时由后端读取居民资料（若资料无联系电话则允许为空，不为历史字段迁移设置短信依赖）。
- 不修改数据库表结构，不删除历史游客字段，不添加短信或匿名凭据字段。
- 返回 VO 对历史游客预约继续保留已有游客展示字段；新预约以居民实名作为预约人展示名。

## 4. UI / 交互

- 游客房源详情保留“可预约时段”只读展示；主操作按钮文案为“登录 / 注册后预约看房”。
- 未登录点击该按钮跳转 `/auth/login?redirect=<当前房源详情>`；登录成功后回到原房源详情，再由居民点击“预约看房”进入预约页。
- 非居民账号点击预约入口显示“请使用居民账号登录”，不调用创建接口。
- 居民预约页不显示游客姓名 / 游客手机号字段；联系人信息以当前居民账号身份为准，备注仍可填写。
- 居民端预约完成后进入预约详情；取消按钮只在状态允许时出现。
- 不设计短信验证码、匿名查询表单或预约编号输入框。

## 5. 兼容与风险控制

- 历史游客预约不删除、不回填居民账号、不强制补短信凭据；管理端照常查询并继续执行确认、分配、完成等处置动作。
- 历史游客预约的取消不再走匿名游客入口；管理端仍可按绑定社区取消，避免历史数据成为无法收口的脏数据。
- Service 层与 Controller 层双重校验：即使未来出现内部调用或路由配置回退，也不能创建匿名预约。
- 前端 fake backend 与测试夹具同步收口为居民身份，避免单测继续掩盖匿名写入路径。

## 6. 验收标准

1. 未认证创建、查询、取消分别返回 401。
2. STAFF 创建与取消返回 403；ADMIN 创建返回 403。
3. RESIDENT 创建成功，列表只返回本人，详情不可读取他人预约，取消本人成功。
4. ADMIN 可查询 / 取消绑定社区内预约，确认、分配、完成流程不受影响。
5. 历史 `user_id IS NULL` 预约仍可由管理端读取。
6. 游客浏览房源和时段正常，点击预约进入登录并携带回跳地址。
7. 登录居民后回到原房源详情，能正常提交预约；浏览器控制台无新增错误。
