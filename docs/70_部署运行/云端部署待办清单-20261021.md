如果 `free -h` 显示没有 swap，再创建约 2 GiB swap；先确认 `/swapfile` 不存在，不要重复创建：

```bash
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

如果系统已有可用 swap，只记录现状，不重复处理。

## 7. 配置公网反向代理

Compose 前端只监听 `127.0.0.1:8088`。宿主机使用 Nginx 或 Caddy 接收公网 `80/443`，转发到 `http://127.0.0.1:8088`。

反向代理必须保留：

- `/api/` 转发；
- `/ws/` 的 WebSocket `Upgrade` 和 `Connection` 头；
- `/uploads/` 转发；
- 前端单页应用回退到 `/index.html`；
- 足够的上传请求体大小，当前前端 Nginx 已设置 `60m`，宿主机代理不得更小。

验收标准：

- [x] 通过 ECS 公网 IP 访问首页返回 `200`。
- [x] 通过公网入口访问 `/v3/api-docs` 返回真实 JSON 和 `200`。
- [x] 反向代理未直接暴露 backend、MySQL 或 Redis 端口。
- [x] `/ws/info` 返回 `websocket: true`，反向代理未拦截 WebSocket/SockJS 入口。

## 10. 更新与回滚

更新必须先在本机重新构建并验证，再推送新的不可变版本，例如 `cloud-20261021-r2`：

```bash
docker compose --env-file .env.cloud -f docker-compose.cloud.yml pull
docker compose --env-file .env.cloud -f docker-compose.cloud.yml up -d --wait
```

回滚时把 `.env.cloud` 中两个应用镜像改回上一版本 tag 或 digest，再执行相同的 `pull` 和 `up -d --wait`。不要删除 `mysql_data`、`redis_data` 或 `cloud_uploads` 卷来处理普通版本更新。
