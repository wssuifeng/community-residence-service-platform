# 本地容器化部署

## 1. 前置条件

- Windows 10/11 + Docker Desktop，开启 Linux containers。
- Docker Compose v2；本机 Docker Desktop Linux engine 已启动。
- 本地上传目录（`uploads`）保留需要展示的图片资源。
- 不需要预装 MySQL 或 Redis；Compose 会启动隔离容器。

## 2. 配置凭据

在仓库根目录执行：

```powershell
Copy-Item .env.docker.example .env.docker
```

编辑 `.env.docker`，至少修改：

- `MYSQL_APP_PASSWORD`
- `MYSQL_ROOT_PASSWORD`
- `JWT_SECRET`，长度至少32字符

`.env.docker` 已被 `.gitignore` 忽略，不要提交。不要把支付宝、微信、数据库密码或 JWT 密钥写进 Dockerfile。

## 3. 构建当前工作区产物

Compose 本地配置从工作区已经构建好的后端 JAR 与前端 `dist/` 打包，便于将同一应用镜像推送到容器仓库。应用源码构建仍由 `docker/backend.Dockerfile` 和 `docker/frontend.Dockerfile` 提供；本地 Compose 使用对应的 `.artifact.Dockerfile`，不把 Maven/Node 构建工具放入运行镜像。

```powershell
Push-Location backend
$env:JAVA_HOME = 'C:\Program Files\Java\jdk-17.0.4.1' # 替换为本机 JDK 17 路径
.\mvnw.cmd -B -DskipTests package
Pop-Location

Push-Location frontend
npm ci
npm run build
Pop-Location
```

`-DskipTests` 只跳过打包时的测试执行；部署构建成功不代表本轮重新执行了后端测试套件。系统测试阶段已有独立测试结论，容器验证另行记录于70阶段执行记录。

## 4. 构建和启动

```powershell
docker compose --env-file .env.docker -f docker-compose.local.yml config
docker compose --env-file .env.docker -f docker-compose.local.yml build
docker compose --env-file .env.docker -f docker-compose.local.yml up -d --wait
docker compose --env-file .env.docker -f docker-compose.local.yml ps
```

访问入口：

- 前端：默认 `http://localhost:8088`；当前本机 `.env.docker` 因端口冲突使用 `http://localhost:18088`
- 后端 OpenAPI：默认 `http://localhost:8080/swagger-ui.html`；当前本机 `http://localhost:18080/swagger-ui.html`
- 本机 MySQL / Redis：默认 `127.0.0.1:3306` / `127.0.0.1:6379`；当前本机为 `127.0.0.1:13306` / `127.0.0.1:16380`
- 上传图片：由前端同源访问上传路径，实际文件来自宿主机上传目录（`uploads`）。

所有宿主机发布端口绑定 `127.0.0.1`。后端首次启动会等待 MySQL/Redis 健康后运行 Flyway，当前迁移链应达到 V45。MySQL 首次初始化会通过只读授权脚本授予应用账号读取 Flyway 11 所需 Performance Schema 视图的权限，不扩展其业务库以外的数据写权限。日志检查：

```powershell
docker compose --env-file .env.docker -f docker-compose.local.yml logs -f backend
```

## 5. 停止和清理

停止服务但保留数据库卷：

```powershell
docker compose --env-file .env.docker -f docker-compose.local.yml down
```

重建干净的容器演示库。该命令会删除 Compose MySQL/Redis 卷，但不会删除宿主机上传目录：

```powershell
docker compose --env-file .env.docker -f docker-compose.local.yml down -v
docker compose --env-file .env.docker -f docker-compose.local.yml up -d --build --wait
```

`down -v` 会永久删除这个 Compose 项目的 MySQL/Redis 数据卷；仅用于可重建的开发演示库，不要对生产环境执行。

## 6. 本地宿主机数据库重置

用于当前本机 MySQL（非 Compose 数据库）时：

```powershell
pwsh -File .\tools\demo\reset-demo-database.ps1
```

脚本只接受本机数据库地址，先将数据库备份到 `output/db-backups/`，再删除并重建 `community_residence`。随后启动后端，Flyway 会自动创建结构并写入演示种子。脚本不会删除宿主机上传目录。

## 7. 云端迁移

云端使用仓库中的 `docker-compose.cloud.yml`，该文件只拉取已经发布的应用镜像，不执行本地源码构建，也不挂载本机 `uploads/`。正确的交付链路是“本机生成镜像 → 推送到镜像仓库 → ECS 拉取固定版本镜像”，不是把运行中的容器目录直接上传到云服务器。部署机先复制 `.env.cloud.example` 为 `.env.cloud`，填入固定镜像标签和云端密钥，再执行：

```powershell
docker login <your-registry>
docker compose --env-file .env.cloud -f docker-compose.cloud.yml pull
docker compose --env-file .env.cloud -f docker-compose.cloud.yml up -d --wait
docker compose --env-file .env.cloud -f docker-compose.cloud.yml ps
```

云端上线前至少完成：

- 将 `.env.cloud.example` 中的 `BACKEND_IMAGE` / `FRONTEND_IMAGE` 替换为已推送的不可变版本标签或 digest；
- 仅对公网开放 TLS 反向代理入口；Compose 前端只绑定云主机回环端口，数据库、Redis和后端不直接暴露公网；
- `JWT_SECRET`、数据库密码和 Redis 密码改由云端 Secret 注入；Compose 通过 `SPRING_DATA_REDIS_PASSWORD` 连接启用密码的 Redis；
- MySQL/Redis 改为云托管服务或独立持久卷；
- 配置域名、TLS、CSP、CORS、备份和回滚；
- `cloud_uploads` 是独立的云端上传卷，首次部署为空；本地上传目录不进入镜像、不进入 Git，也不会自动上传云端，因此云端不会显示这些本机图片。若云端需要既有图片，须另行人工上传到云端卷或对象存储。

本轮已完成云端 Compose 交接模板和配置边界，并已在阿里云中国香港 ECS 完成首次镜像拉取、Compose 启动、宿主机 Nginx 反向代理、域名绑定和 Let's Encrypt HTTPS 配置。云端验证证据见《云端部署验证记录-20261021》。备份恢复和费用告警经用户裁决不纳入本演示环境；后续开机行为以 Docker `enabled` 和 Compose `restart: unless-stopped` 为准。
