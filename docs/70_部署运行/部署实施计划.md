# 70阶段部署实施计划

本阶段目标是把当前已验收版本整理为可重复启动的本地演示环境，并保留向云端迁移的清晰边界。部署不引入真实支付、外部商业接口或图片上传到远程仓库。

## 一、本地交付范围

| 工作组 | 产出 | 验证方式 |
|---|---|---|
| 容器构建 | `docker/backend.artifact.Dockerfile`、`docker/frontend.artifact.Dockerfile`；源码构建文件保留为 `docker/backend.Dockerfile`、`docker/frontend.Dockerfile` | Maven/JDK17跳过测试打包成功、前端类型检查与构建成功；本地应用镜像由当前JAR和dist制作 |
| 服务编排 | `docker-compose.local.yml` | MySQL/Redis健康，后端/前端运行，服务间使用 Compose DNS，宿主机端口仅回环绑定 |
| 生产配置 | `application-prod.yml`、`.env.docker.example` | 凭据由环境变量注入，JWT 无默认生产密钥 |
| 图片隔离 | `./uploads:/app/uploads`、`.dockerignore`、`.gitignore` | 本地镜像构建上下文不含上传图片，宿主机图片可由前端同源代理读取且散列一致 |
| 云端迁移 | `docker-compose.cloud.yml`、`.env.cloud.example` | 云端只拉取固定版本镜像；数据库/Redis不发布公网；云端使用独立空上传卷，本机图片不随镜像或配置上传 |
| 演示数据库 | `tools/demo/reset-demo-database.ps1` | 本地备份后重建库，Flyway V1~V45 自动迁移，演示种子可登录 |
| 演示说明 | `本地容器化部署.md`、`演示环境使用说明.md` | 第三方按文档可启动并进入各端 |

## 二、执行顺序

1. 复制 `.env.docker.example` 为 `.env.docker`，改成本地强凭据与未占用端口。
2. 使用 JDK17/Maven 构建后端JAR，使用 npm 构建前端dist。
3. 确认 Docker Desktop Linux engine 已启动，构建并启动 `docker-compose.local.yml`。
4. 检查 MySQL/Redis健康状态、后端Flyway日志、超管登录、OpenAPI和宿主机图片代理。
5. 云端部署时在本机生成并推送应用镜像到选定仓库，然后在阿里云 ECS 使用 `docker-compose.cloud.yml` 拉取固定标签；配置域名/TLS/密钥/持久卷；本机图片不随镜像上传。

## 三、云端迁移边界

云端部署必须重新提供数据库、Redis、反向代理/TLS、密钥管理和上传存储方案；备份恢复属于可选的长期运维保障。仓库已提供不带本地构建上下文的通用 `docker-compose.cloud.yml`；当前本地图片目录不进入镜像、不进入 Git，也不自动上传云端，云端使用独立的 `cloud_uploads` 卷。宿主机 HTTP/HTTPS 反向代理已完成。本次短期毕业设计演示环境按用户裁决不执行云端数据库/上传卷备份恢复演练，生产部署时仍应另行评估。

## 四、当前已知环境限制

2026-10-21本机已完成Compose部署。当前`.env.docker`使用回环端口13306/16380/18080/18088以避开现有服务冲突；此文件仅本机存在并被Git忽略。云端已完成 ACR 固定镜像发布、ECS Compose 启动、宿主机 Nginx HTTP/HTTPS 代理和部署级冒烟；`uploads/`不自动上云，云端图片由用户在演示过程中主动上传。费用告警和云端备份恢复演练按用户裁决不纳入本次演示部署，不构成阶段待办。
