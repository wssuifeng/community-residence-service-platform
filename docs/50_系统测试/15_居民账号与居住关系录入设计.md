# 居民账号与居住关系录入

> 2026-10-11，依据用户已确认规则及本轮“开始执行”授权；本功能仅处理DEF-141/143，不包含租约签约与交易。任务状态见50中控。

## 1. 现有模型与功能边界

resident保存id/username/passwordHash/realName/phone/idCard/email/avatarUrl/status/创建更新时间；无communityId/houseId。residence_relation单独保存residentId/communityId/houseId/relationType/moveInDate/moveOutDate/isPrimary。复用该模型，不新建一份居民资料，不把所选社区写成账号固有归属。

管理员代建与CSV导入统一使用姓名、手机号、证件号、用户名、邮箱。头像沿用账号资料页面的现有上传能力，不在CSV中填写外部头像URL。状态由服务端创建为ACTIVE；密码生成和一次性返回沿既有机制，不在日志中记录密码。

## 2. 管理端完整操作

入口：管理端“居民 → 代建居民/批量导入”。代建默认选择“同时登记居住关系”；选择社区→楼栋→单元→房屋，录入OWNER/TENANT/FAMILY及入住日期。可明确切换“仅建账号”，界面说明该社区仅用于鉴权，不表示已有居住关系。不能让用户选完社区却静默丢失绑定意图。

关系登记复用现有管理员直建关系契约：目标房屋必须属于所选社区且可入住，入住日期不晚于今天；不是租赁协议确认，不创建或代签租约。不在本批自行新增共同居住或主次关系规则。已入住/预留/维护房屋不可通过这一入口越过既有入住流程。

提交后返回账号及relationId/houseId；成功面板明确“关系已登记”或“仅建账号”。失败保留表单；关闭确认前仅本次展示初始密码。社区、楼栋、单元下拉分页读齐，变更上级即清空下级，旧请求不得覆盖新范围。

## 3. CSV模板与兼容

新模板为UTF-8 CSV：`社区ID,姓名,手机号,证件号,用户名,邮箱,房屋ID,关系类型,入住日期,备注`。用户名/证件号/邮箱/备注可空；关系三项房屋ID、类型、日期必须全有或全无。日期YYYY-MM-DD，房屋ID是系统房屋主键，不是房号。旧四列表头继续支持，仅建立账号，结果明确没有关系。

每行使用与代建相同的DTO校验和账号/关系保存路径。每行一个独立事务：账号、关系、房屋状态和审计全部成功才提交，任一失败整行回滚；下一行继续。重复用户名/手机号逐行失败，不合并进已有账号，不生成重复关系。成功结果含账号与relationId/houseId；行号按数据行计，不含表头。前后端文件大小统一5MB，超过请拆分；不新增原生xlsx支持。

## 4. 接口与持久化

复用POST /api/v1/residents/admin-create与POST /api/v1/residents/import。AdminCreateResidentDTO扩展email、houseId、relationType、moveInDate、remark；houseId为空时不建立关系，其他关系字段不能单独残留。ADMIN仅可对可管理社区操作，房屋社区不匹配拒绝，不能通过伪造communityId写范围外关系。

使用已有事务管理器的REQUIRES_NEW逐行事务，避免同类内@Transactional失效。关系路径锁定房屋，与入住申请等竞争操作串行。无需数据库新列/迁移。既有关系直建保护不放宽；关系历史、居民私有数据权限仍沿现有设计。

## 5. 可验证结果

- 代建邮箱保存；账号与关系、房屋状态一起落库。
- 范围外/错误社区房屋、非法关系/未来日期、关系半填拒绝。
- 关系或审计失败时账号不残留；CSV一行失败不回滚成功行。
- 新模板关系落库、旧模板明确只建账号、重复导入逐行拒绝。
- UI级联选房、默认登记关系、切换仅账号清空关系、结果显示关系、低分辨率无页面级溢出。

实现与回归证据写入08；不借本功能关闭DEF-142旧Excel现场，不要求现在开始用户全站手测。
