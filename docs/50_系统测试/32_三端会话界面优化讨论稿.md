# 三端会话设计稿：按业务分类的三段式布局

按用户2026-10-17参考图重新整理，取代前版双栏讨论。用户已于2026-10-17整体采纳三段设计，要求修正侧栏滚动条；该样式已处理。统一会话功能尚未工程落地，不能把设计预览视为正式页面。

## 1. 页面长什么样

**最左业务导航｜中间会话列表｜右侧聊天。** 最左一列不能省略，也不和原后台导航混为一列。

- **管理端**：保留原后台顶部及一级侧栏，在“消息会话”右侧内容区嵌入上述三段工作区。
- **居民端、服务人员端**：保留各端顶部导航，“消息会话”子页直接展示同一工作区，不复制后台一级侧栏。
- 工作区最左显示本端有权使用的会话类别；中间搜索/找会话；右侧上方会话标题与菜单、中间消息、下方工具栏与输入框。

## 2. 统一显示哪些会话

| 类别 | 居民 | 管理端 | 服务人员 |
|---|---|---|---|
| 租约沟通 | 本人租约 | 本人参与的租约群 | 不增加租约权限 |
| 看房沟通 | 本人预约 | 本人参与的看房群 | 本人参与的带看群 |
| 工单沟通 | 本人工单 | 本人参与的工单群 | 本人参与的工单群 |
| 反馈会话 | 本人反馈 | 沿用原反馈访问权限 | 原无权限，不显示 |
| 社区直通 | 本人所属社区管理方 | 原权限内对应居民 | 原无权限，不显示 |

“全部”合并上述来源，不再漏掉反馈。这里的“整个项目”指业务模块完整，**不是读取所有人的私密对话**，超管也不自动查看全部群。反馈仍用原业务和消息存储，经统一展示适配接入；匿名反馈的标题、摘要、头像、成员/检索均不能泄露真实姓名。待受理反馈不因查看而自动受理，沿用首次回复受理规则；办结后只读。

**活跃排序**：按最后一条有效消息时间倒序（消息含图片、协议和系统消息），尚无消息用创建时间，同时间用稳定标识补序。本人发送与对方回复都能使会话上移；仅打开/已读不制造活跃。关闭会话不强制置底，新消息不抢走当前选中会话。

## 3. 每个区域保留哪些功能

| 区域 | 功能 |
|---|---|
| 业务导航列 | 全部、租约、看房、工单、反馈、直通；仅显示本端有权类别，不照搬QQ的空间/游戏/云盘 |
| 会话列表 | 搜索会话/对象/业务编号，全部与未读切换；名称、业务标识、最后摘要、时间、真实未读数；滚动继续加载 |
| 聊天顶部 | 名称、类型、实时状态、业务定位；“⋯”查看成员和业务详情，不常驻第四列 |
| 消息区 | 文字、图片、系统消息、协议卡片；有未读时定位阅读位置、上拉历史、新消息提醒；看旧消息不强制跳底 |
| 工具栏/输入区 | 图片、＋业务功能、文字输入和明确发送按钮。居民租约群可预约/查看同意协议，管理端可发出/查看协议；其它类别进入原业务详情处理 |

沿用500字、图片格式/大小、Enter发送/Shift+Enter换行约束。字体/表情/文件是参考图的示例工具，第一稿不擅自新增这些能力，也不画不可用的装饰按钮。

## 4. 四条不能改错的规则

1. 未读按各来源真实阅读游标统计，不把通知数当聊天未读；本人发送不增加本人未读，看到并确认成功后才减少，当前未读筛选中的会话不突然消失。
2. 切换保留各会话草稿/阅读位置；关闭只读，发送失败保留输入。离开/切账号时清理，不让旧请求覆盖新会话。
3. 协议继续“管理端发出、居民同意一次”，不增加重复承租确认或让员工代签；本稿没有支付动作。
4. 小窗口先收缩外层导航；再放不下时列表与聊天切换，最左业务列仍保留。空、失败、断线和只读状态均有明确处理。
