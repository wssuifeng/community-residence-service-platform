# 三端会话界面优化：讨论稿

依据：2026-10-16用户要求登记居民、服务人员、管理端会话优化；方向为“左侧群聊/未读、搜索和菜单，右侧消息”。这是已有会话体验待办的细化，不是本轮实施清单；执行状态只在本阶段中控记录。

## 1. 先说明当前差异

| 端 | 现有入口与机制 | 需要补齐的界面 |
|---|---|---|
| 管理端 | ConversationListView已有左列表/右ConversationChat，但筛选拥挤、缺搜索，会话分页当前只取第一页50条 | 不重新造聊天逻辑，重整列表/搜索/菜单、完整加载和业务上下文 |
| 居民端 | 消息中心的会话Tab展示列表，再跳独立ConversationDetailView；不是同页连续切换 | 收入同一个会话壳，切群不用退出消息页 |
| 服务人员端 | 消息中心目前只有通知列表；工单详情及带看工作台可进入聊天，没有独立统一会话列表 | 补齐本人参与的统一会话入口，保持服务人员权限边界 |

租约、看房、工单、直通使用同一conversation/participant/message及ConversationChat。反馈有独立业务模型，但共享ChatMessageList/ChatComposer。此处不提议重建聊天后端，也不未经确认把反馈强迁入多方会话。

## 2. 推荐布局：共享一套会话壳，角色决定业务功能

```text
┌─会话列表（约280～320px）──┬─选中会话──────────────────────┐
│ 搜索会话            ⋯    │ 群名称 / 关联业务 / 当前状态  ⋯│
│ 全部 · 未读 · 业务筛选   ├──────────────────────────────┤
│ 群名       时间   未读数 │ 消息历史                     │
│ 角色/末条消息摘要        │ 文字、图片、业务卡片         │
│ ……独立滚动/继续加载      │ 新消息提示 / 回到底部        │
│                         ├──────────────────────────────┤
│                         │ 图片 / 业务功能＋ / 输入发送 │
└─────────────────────────┴──────────────────────────────┘
```

建议默认只露“全部、未读”，业务类型放筛选菜单；不要再把所有类型按钮挤成两行。现有系统侧栏保留，会话列表作为工作区内的第二列；窄桌面支持收起列表、返回列表，不把右侧聊天挤成窄条。

## 3. 需细化的规则与建议

| 项目 | 推荐方案 |
|---|---|
| 列表信息 | 群名、业务类型/社区或房屋定位、末条摘要、时间、未读数；无未读不留红点。默认按最近消息排序；关闭群保留只读标记，不自动隐藏导致找不到历史 |
| 搜索分工 | 左上搜索“找会话”：群名、可见关联业务编号等；右上查找“本会话消息”。先支持找会话，群内全文检索另行确认，不能用当前第一页50条前端过滤冒充全量搜索 |
| 未读语义 | 沿用服务端已读游标；实际看到消息后才推进。打开后台Tab、鼠标点选列表但消息未加载，均不应直接清零；本人发言不增加本人未读；通知铃铛和聊天未读是不同对象，不能互相清零 |
| 新消息与滚动 | 当前正看底部时跟随新消息；翻看旧消息时保持位置，只显示“有N条新消息”，点击再回到底部。上拉旧消息保持原锚点，列表/消息区分开滚动 |
| 菜单分层 | 顶部⋯：成员、关联业务详情、会话内查找；输入区＋：本业务能用的动作。会话列表⋯放会话筛选等列表设置。置顶/免打扰可以作为个人偏好候选，但需独立持久化设计，不能影响其他成员；暂不引入“删除业务群”“退出群”“任意拉人” |
| 三端业务菜单 | 居民：按现有租约/看房规则预约、查看/确认协议或打开申请；管理端：按现有权限发协议、处理工单等；服务人员：本人被派工单/带看相关操作，不显示协议确认或管理权限按钮。具体动作必须核对既有端点与当前状态，业务关闭后只读 |
| 连续操作 | 切群保留每群输入草稿与滚动位置，按账号隔离；推送更新摘要/角标/状态，不全页刷新，不把当前输入和选中会话冲掉。提交失败保留输入、显示重试，避免重复发送 |
| 权限与加载 | 只列本人参与的会话；超管不默认读取全部群。菜单不是权限来源，后端仍校验；过期响应不能串到新会话或另一个账号。加载失败与真正空列表必须区分 |

**建议本轮讨论先确定的范围**：统一布局、完整会话列表、找会话、现有菜单整理、真实未读/滚动及三端权限渲染。**不默认附带**群内全文检索、置顶/免打扰、任意群管理、语音视频/表情/消息撤回等能力。待用户后续确认具体方案与原型，再补20/30局部设计和实施任务；本轮不实施、不排序，也不要求为此重新手测其他业务链。

## 4. 官方交互参考（非本项目现有能力声明）

- Microsoft Teams官方：会话列表提供未读过滤、消息预览等，用于参考列表层级，不照搬全部功能。[Explore the new chat and channels experience](https://support.microsoft.com/en-us/teams/teams-channels/explore-the-new-chat-and-channels-experience-in-microsoft-teams)
- Slack官方：区分不同搜索对象，支持从当前会话查找消息，用于参考“找会话”与“查群消息”的区分。[Search in Slack](https://slack.com/help/articles/202528808-Search-in-Slack)

最终界面以本系统的业务、权限和已读规则为准；不因参考社交软件而自动增加其功能。
