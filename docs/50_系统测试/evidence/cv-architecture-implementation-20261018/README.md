# cv 架构整理实施证据

2026-10-18，依据[37实施计划](../../37_架构优化实施计划.md)，阶段状态只在50中控cv维护。本文记录实测事实与限制，不代替人工验收或阶段出口。

## 1. 实施范围

- S0～S3：原464个生产Java文件归属，混合Controller按方法拆分；原264HTTP映射/授权/参数夹具保留，60个Mapper离线注册。
- S4/S5：共享预约提取，前端公共与三端按模块归组，根路由装配；导航/标题同源，公共不反向导入端，无调用者的permission Store删除。
- O1：三端工单详情共享读取，主辅独立失败/重试，ID/身份变化及卸载隔离。
- O2：HTTP写入与通知统一映射域/对象失效，保留事件合并、串行刷新、可见性和轮询兜底。
- O3：原事务保存业务记录，固定载荷在成功提交后投递，无事务直接发送；回滚不发，发送失败由读取补偿。
- O4：社区结构数据/选区与范围/网格/详情拆分；保留范围缓存、4并发、楼层约束和未勾选不改语义。
- O5/O6：固定当前角色/本人的两个只读摘要入口，旧接口保留；工作台负荷与事件次数分开，租约快照复用RentSchedule并同页批量读取。
- O7：管理端协调社区删除，14个所属域清理Service参加外层事务；原锁定、两次确认、完整名称、级联顺序、账号保留和审计语义保留。
- O8/O9：工作台区块与局部样式收口、失败状态区分，合成内容区布局和请求/缓存测量；没有证据支持新增虚拟化或淘汰策略。

## 3. 请求与缓存测量

| 对象 | 调整前 | 当前实测或实现 | 解释 |
|---|---|---|---|
| 服务工作台主体 | 5次工单列表请求拼统计 | 1次摘要；连同通知/事件统计共3次初始请求 | 只证明HTTP次数减少，未测真实数据库耗时 |
| 十条租约卡片 | 1次列表＋10次支付流水 | 1次摘要；展开1条才请求该条支付/退还/变更流水 | 同页合同/成功支付快照在后端批量读取，不逐条查单 |
| 90条已加载会话刷新 | 3次、每次30条 | 1次、大小90且不超过服务端100上限 | 去重/分页/权限与晚到响应隔离仍在 |
| 会话有限历史 | 初始40条 | 4次显式向前加载后200条，合成DOM约240项；切20个会话后返回仍有200条和原草稿 | 使用真实useChatChannel＋合成渲染器，不是正式消息卡片渲染基准或长时内存试验 |

会话原来已有30个缓存条目上限。200条单会话历史不代表消息数量已经有新硬上限；本轮不新增容量政策。`o9-cache-measurement.json`中的切换耗时包含每次180ms刻意等待，不作为接口延迟；`o8-browser.json`的elapsedMs也是合成加载/等待后的观察点，不与旧版真实后端做性能比较。

## 5. 浏览器隔离与复现

浏览器使用独立agent-browser会话`cv-architecture-20261018`，不接管用户窗口。当前Vue组件经Axios合成adapter供数，未匹配请求直接失败；最终隔离Vite配置无后端代理，并替换WebSocket连接模块。六例无整页横向溢出，长工单/社区名可显示，结构详情弹窗可达；这些是独立内容区宽度，不能冒称完整三端布局或人工观感验收。

复现时将`browser-harness.ts`复制为`frontend/cv-architecture.ts`，`browser-vite.config.ts`复制为`frontend/cv-vite.config.ts`，`websocket-stub.ts`复制为`frontend/cv-ws.ts`。在frontend下新建仅加载`/cv-architecture.ts`的HTML入口`cv-architecture.html`，运行`npm run dev -- --config cv-vite.config.ts`，再在仓库根运行`python docs/50_系统测试/evidence/cv-architecture-implementation-20261018/browser-check.py`。脚本仅使用5188和上述命名会话；agent-browser安装路径可能需按机器调整。结束后关闭这个独立会话/隔离服务并删除这四个临时入口文件。本次已回收它们，正常8084/5176不由该测试启停。

首次浏览器练习继承默认开发WebSocket代理，出现连接尝试；该次结果未用于最终证据，已使用无代理＋WebSocket替身完整重跑。最终无后端接口调用，不声称首次运行绝对无连接尝试。
