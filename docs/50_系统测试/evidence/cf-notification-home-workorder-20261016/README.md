## 现场与修复

| 缺陷 | 根因 | 修复 |
|---|---|---|
| DEF-209 铃铛漏列未读/混入已读 | 预览从latest.slice(0,5)获取，latest本身截20条；未读计数与预览不一致 | 完整未读快照派生列表与计数、限高滚动，打开补读；阅读成功移出；防退出、重叠请求及迟到快照复活已读 |

| DEF-212 工单直接派单无群/入口缺失 | assign只join，而群只在intake创建；会话中心也无工单筛选 | 派单同事务先建/复用群再入群；管理端显式幂等恢复旧单，只补引用不更新业务状态；三端顶部入口；补全筛选及处理函数类型白名单 |

## 群聊实际覆盖

| 业务链 | 类型/建立时机 | 入口 |
|---|---|---|
| 入住申请审核与租约协议沟通 | LEASE_GROUP，申请审核通过创建 | 租约/协议业务页、消息会话 |
| 看房预约及带看沟通 | VIEWING_GROUP，预约创建，分配带看人时加入 | 看房详情、消息会话 |
| 服务工单 | WORK_ORDER_GROUP，受理或直接派单创建 | 三端工单详情、本人参与的消息会话 |
| 居民联系社区管理员 | DIRECT，显式发起幂等创建 | 联系管理员、消息会话 |

四类共用conversation/participant/message、ConversationChat及同一参与者鉴权。反馈用自己的业务详情与feedback_message，并非多方群聊的一类，但复用ChatMessageList/ChatComposer和统一图片消息基础；公共资源预约、公告不自动建群。超管也不默认读取所有会话；管辖管理方可从工单“进入工单沟通”显式加入/恢复。正常库历史漏群未静默批改，首次进入时按接口幂等补齐。
