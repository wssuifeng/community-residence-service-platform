# 用户手测清单（B 轨 + 四端手测 + 视觉检查）

> 用途：AI 全量回归通过后，由用户亲自执行的最终验收测试。逐条勾选，
> 全部通过即 50 阶段测试收口，进入 60 评估验收。
> 环境：前端 `cd frontend && VITE_PROXY_TARGET=http://localhost:8081 npm run dev`
> → http://localhost:5173；后端 8081 实例（连测试库，已应用 Flyway V1~V17）
> 由测试会话保留；U-22 续约支付需支付宝沙箱环境变量已配置（后端已配并实测过）。
> 种子账号：超管 superadmin/Admin@123456、社区管理员 admin1/Admin123456、
> 服务人员 staff1/Staff123456、居民 resident1/Resident123456。
> 执行方式：浏览器手动操作，每条只判「通过/不通过」，不通过处记录
> 现象（截图更佳）反馈给主会话登记处置。
> 清单版本：U-01~U-21（2026-09-15 第五轮收口版）+ U-22~U-27（2026-09-19/20
> 批次新增流程，见 08 §3.13~§3.21）。

## 使用说明

- 每条含【操作步骤】与【预期】，按序执行即可，无需测试背景；
- 标 ⭐ 的为核心业务判据项（对应毕设答辩演示口径），必须通过；
- 全部约 90~120 分钟（U-01~U-27）；可分多次执行，中途退出无影响（数据可累积）。

---

## 一、游客端（无需登录）

### U-01 游客浏览与看房预约 ⭐
- 步骤：访问 http://localhost:5173/guest/home → 公告列表看置顶公告排最前（若有置顶）→ 进「房源」→ 筛选「出租/出售」与「户型」两下拉，选中后列表正确刷新 → 点开一个房源详情（含地图位置、图片）→ 选可预约时段提交看房预约。
- 预期：筛选结果准确；预约提交成功提示；时段外无可选项。

### U-02 视觉检查 · 游客端
- 步骤：游客首页/公告列表/公告详情/房源列表/房源详情 五页逐页查看。
- 预期：布局整齐无错位、无遮挡文字、无控制台报错（F12 看 Console 无红字）、加载无长时间白屏。

## 二、居民端（resident1 登录）

### U-03 登录与首页
- 步骤：登录页「居民登录」Tab 输 resident1/Resident123456 → 登录。
- 预期：进入居民首页，问候语与公告、快捷入口正常；铃铛有未读角标。

### U-04 提交工单（含图片）⭐
- 步骤：「我的工单」→ 提交工单：选类别（**确认下拉里没有停用类别**）、填标题描述、上传一张图片 → 提交。
- 预期：生成工单号；图片缩略图显示；提交成功。

### U-05 反馈会话实时性 ⭐
- 步骤：「我的反馈」→ 新建反馈提交 → 用另一浏览器窗口以 superadmin 登录管理端打开该反馈 → 居民窗口输入消息发送 → 观察管理端窗口。
- 预期：管理端**无需刷新**，3 秒内出现新消息；双方消息气泡左右区分清晰。

### U-06 资源预约（栅格时段）⭐
- 步骤：「资源预约」→ 选健身房等资源 → 选日期 → 查看时段格。
- 预期：时段按半小时（或资源配置粒度）展示；已满时段显示不可选/余量；提交成功后在「我的预约」可见。

### U-07 消息中心与通知
- 步骤：点铃铛 → 查看最近通知 → 点「消息」进通知列表 → 标记已读。
- 预期：未读数准确；已读后角标减少；U-04/U-05 产生的通知可溯源（点开能跳到对应工单/反馈）。

### U-08 视觉检查 · 居民端
- 步骤：居民首页/工单列表/工单详情/反馈列表/反馈详情/预约页/公告/房源/消息 九页逐页查看。
- 预期：同 U-02 口径。

## 三、服务人员端（staff1 登录，管理员登录 Tab）

### U-09 工单处理 ⭐
- 步骤：预先让居民提交一个工单并由 admin1 派单给 staff1 → staff1 登录 → 「工单列表」看到被派工单 → 接单 → 开始处理 → 提交处理结果（文字+图片）。
- 预期：每步状态变化正确；工作台能看到自己的按日趋势图（非 MOCK 占位）。

### U-10 视觉检查 · 服务人员端
- 步骤：工作台/工单列表/工单详情 三页查看。
- 预期：同 U-02 口径。

## 四、管理端（admin1 与 superadmin 分别登录，管理员 Tab）

### U-11 管理员派单 ⭐
- 步骤：admin1 登录 → 工单列表 → 对居民新提交的工单点「派单」。
- 预期：**派单对话框能加载出服务人员下拉**（DEF-025 修复点——此前 403 空列表）；派单成功。

### U-12 代建居民与 CSV 导入 ⭐（superadmin 或 admin1）
- 步骤：「居民管理」→ 代建居民（填姓名手机号等）→ 查看弹出的初始密码 → 用该密码在新窗口登录验证 → 再试「批量导入」：下载模板 → 改成 3 行（2 行合法 + 1 行故意重复手机号）→ 上传。
- 预期：代建账号可登录；导入结果显示 2 成功 1 失败且失败行标明原因。

### U-13 公告定向与置顶 ⭐（superadmin）
- 步骤：「公告管理」→ 新建公告：勾选 2 个社区 + 1 个楼栋、开启置顶 → 发布 → 编辑该公告改定向范围 → 保存 → 到游客/居民端查看。
- 预期：创建与**编辑后**的定向都生效（DEF-043 修复点——编辑重写目标）；置顶公告排列表最前；置顶条图标点亮（DEF-039 接线）。

### U-14 渠道分级勾选 ⭐（superadmin）
- 步骤：「全局配置」→ 「通知渠道分级」卡片 → 给某个业务类型勾选 SMS → 保存 → 回读确认勾选保持 → 触发一次该类型通知（如发布公告）→ 管理端「通知列表」或库内查 channel 留痕。
- 预期：勾选保存生效（DEF-037 接线）；WEBSOCKET 显示"站内必达"只读；勾选的渠道产生留痕记录。

### U-15 社区/楼栋管理
- 步骤：admin1 → 社区列表（无删除按钮——仅超管可见）→ superadmin 登录 → 社区列表见删除按钮 → 楼栋管理试「整栋创建」（批量）与楼栋删除（cascade）。
- 预期：权限隔离正确；批量创建一次成多栋；级联删除有强确认提示。

### U-16 运营看板 ⭐
- 步骤：superadmin → 运营看板 → 切换社区筛选 → 逐个查看 16 卡片 + 4 图表 → 试导出图片。
- 预期：卡片数值随社区切换变化；图表渲染正常；导出下载图片成功。

### U-17 操作日志（CREATE 类覆盖）
- 步骤：superadmin → 系统管理 → 操作日志 → 按时间倒序翻看。
- 预期：**刚才 U-12~U-15 的创建类操作（代建居民/建公告/建楼栋）都有日志记录**（DEF-034 修复点）；日志含操作人/时间/对象。

### U-18 视觉检查 · 管理端
- 步骤：看板/社区/居民/工单/公告/反馈/预约/房源/系统管理 九类页面逐页查看（改版后管理端 11 类重构是视觉重点）。
- 预期：同 U-02 口径；侧边栏分组清晰；表格/表单/对话框风格统一。

## 五、专项（对应 B 轨 9 条）

### U-19 浏览器兼容抽查
- 步骤：用你手头另一款浏览器（如 Edge 测过就用 Chrome，反之亦然）走一遍 U-01/U-04/U-16 三个代表流程。
- 预期：功能可用、无布局破坏。

### U-20 Redis 停服降级（可选，最硬核的一条）
- 步骤：停掉本机 Redis 服务（Memurai）→ 刷新居民端页面操作 U-05 发消息 → 观察后 **恢复 Redis**。
- 预期：WS 推送不可用时页面自动回落轮询，消息 30 秒内仍能收到；恢复 Redis 后一切正常。
- （不敢动 Redis 可跳过此条——AI 侧 SP-04 已有协议层验证，标注"跳过，AI 已验"即可）

### U-21 日志保留期配置确认
- 步骤：superadmin → 全局配置 → 找到 log.retention_days。
- 预期：值为 730；说明文案含"到期自动清理并通知超级管理员"。

## 六、2026-09-19/20 批次新增流程（U-22~U-27）

> 本批为 2026-09-19/20 用户手测驱动的修复与需求增量（R59~R63）复验窗口，
> 逐条对应 08 §3.13~§3.21 的缺陷与交付。支付宝沙箱凭据已配置（后端 8081
> 环境变量），微信渠道因无公开沙箱保持置灰。

### U-22 我的租约与续约支付 ⭐
- 步骤：resident1 登录 → 居民端「我的租约」→ 查看租约列表（状态胶囊、到期标注、
  社区徽章、展开明细、同屋历史折叠）→ 对生效租约点「续租」→ 选月数与渠道
  （支付宝）→ 提交 → 在新窗口完成沙箱支付 → 回到弹窗等待轮询确认。
- 预期：租约列表数据正确；续租弹窗显示金额预览（月租×月数）；支付宝渠道可用、
  微信显示「未配置」置灰；支付完成后提示成功且租期止期顺延、双方收到通知；
  支付记录 tab 出现该单（状态 已支付 + 渠道流水号）。

### U-23 看房群聊与直通会话 ⭐
- 步骤：resident1 → 看房预约详情页打开会话窗发一条消息 → 另开窗口以 admin1
  登录管理端 → 看房预约列表「进入会话」发送回复 → 观察双方窗口；再回居民端
  「消息中心」→「联系社区管理员」向本社区管理员发起直通会话并发消息。
- 预期：消息**无需刷新 3 秒内**出现在双方窗口（DEF-060 修复点）；群成员含居民与
  社区管理员（分配带看人后带看人也在群内）；直通会话幂等（重复点击不新建）；
  未读角标随查看归零。

### U-24 带看人分配与「我的带看」工作台（服务人员端）⭐
- 步骤：admin1 → 看房预约列表 → 对一条待确认预约「分配带看人」（下拉选 staff1）
  → 观察带看人列；staff1 登录服务人员端 →「我的带看」→ 打开详情（含会话窗）→
  对已预约记录登记完成。
- 预期：候选下拉可取到启用状态服务人员与管辖该社区的管理员；分配后居民与带看人
  均收到通知；staff1 的「我的带看」仅显示分配给本人的预约；登记完成后状态更新；
  跨社区分配被拒（5805）。

### U-25 房源一体化与批量挂牌（管理端）⭐
- 步骤：superadmin → 社区管理 → 选一个社区 →「房屋与房源」一体化页查看
  （楼栋左竖线层级、单元小标签、房屋五列行）→ 点「批量挂牌」→ 选范围
  （整社区 / 按单元层级筛选）→ 填月租/押金与标题后缀 → 提交 → 到游客端房源
  列表核对数量。
- 预期：树结构正确展示房屋及其房源状态徽章；批量挂牌返回 created/skipped 计数且
  已有房源房屋跳过（幂等）；标题带后缀；跨社区 ID 被拒；游客端可见各社区房源
  （此前仅个别社区有房源）。

### U-26 一体化页筛选与侧栏固定（管理端）
- 步骤：在同一体化页使用房屋筛选（楼栋/单元/房号/房源状态）逐级收窄 → 滚动长
  列表到底部 → 观察左侧导航栏位置。
- 预期：筛选结果与条件一致（层级筛选联动）；滚动时侧栏保持固定在视口（不随页面
  滚走）。

### U-27 公告置顶轮播（游客端 + 居民端）
- 步骤：游客端「社区公告」查看置顶区（3 条置顶时）→ 用左右箭头与缩略图导航切换
  → 静置观察自动轮播 → 鼠标悬浮；再以 resident1 进居民端「社区公告」查看同一区域。
- 预期：置顶区与下方列表同宽、单卡轮换、箭头与缩略图为虚化样式且悬浮显形、5s
  自动轮播（悬浮暂停、手动切换后重新计时）；置顶不足 2 条时降级为单卡且无箭头；
  居民端展示与游客端 v5 口径一致。
