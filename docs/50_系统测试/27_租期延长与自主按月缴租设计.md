# 租期延长与自主按月缴租设计

> 依据2026-10-15本轮用户实测反馈拟定，供确认；只讨论这两项功能。**尚未实施，不替代当前23及冻结20/30。**首期成功、协议确认和一次性押金规则保持；不重做支付接入。

## 1. 现有设计与本次改变

| 项目 | 当前源码实际行为 | 推荐改为 |
|---|---|---|
| 延长期限 | 管理方拟定新增合同段 → 居民同意 → 新增段首笔租金成功才延长 | 居民申请延长 → 管理员审核通过即延长，不以付款为延长条件 |
| 日常缴租 | 按已确认合同段的固定缴租周期收费，尾期截到剩余月份 | 居民选择1至当前合同剩余未缴月数，默认1个月；服务端报价 |
| 入口 | “合同与续租协议”“合同内下一期”“续租首笔”并列 | “合同与租期”“申请延长租期”“缴纳租金”，不再提供新的“续租首笔”入口 |
| 初次首付 | 约定首期月数租金＋一次押金 | 不变；延长和后续交租不再收押金 |

现有“续租首笔”并非第二次初次首付，而是旧设计为新增合同段安排的第一笔租金。用户现已要求取消这种生效门槛；**不能只改按钮文字而保留原支付激活逻辑。**

不推荐只更名保留旧门槛，也不推荐每次延长重新建独立租约，后者会重复处理居住关系/押金。推荐沿用同一租约，单独记录延长申请和历次期限变更。

## 2. 租期延长：居民申请，管理方审核

1. 居民在本人有效租约点击“申请延长租期”，填延长月数（正整数）、理由；显示原止期、拟延长止期、沿用的月租及“不收取新押金”。
2. 提交即代表居民同意这次明确的期限方案。待审期间原期限、已缴月份及居住关系均不变；同一租约只允许一条待审申请，可撤回。
3. 管理端在租约详情、租住管理待审列表及对应租约群查看并审核；展示已有欠租，不能借延长冲销欠款。管理方批准或说明原因驳回，**不在审核时偷偷改月数/价格**；要换方案则驳回后重新申请。
4. 审核通过即更新当前合同止期，保留申请快照和双方确认行为；不要求再点一次居民确认，不要求先支付“新增段首笔”。起租日、已付首期、押金、正式主居住关系和同住依赖关系不重建。
5. 新增期间的租金并入普通缴租，仍从最早未缴月份缴起。到期提醒使用新止期，历史合同和账单不覆盖。

**本次只延长时间，月租、押金和其它约定沿用；不在这个入口加涨租/押金差额功能。**

申请可为待审核、已通过、已驳回、已撤回；已通过不能靠“撤回申请”回滚已生效期限。审批须重新校验租约状态、原期限版本及管辖权限：已退租/已结束、原期限已改变或不再符合办理条件时拒绝旧审批，不能覆盖别人刚更新的期限。居民仅操作本人租约，管理员限管辖社区。

例：原合同2026-10-15至2027-10-14，申请延长3个月；审核通过后止期为2028-01-14。审批前已缴1个月，审批后仍只已缴1个月，总期由12变15，待缴由11变14；审批不生成支付单。

## 3. 自选月数缴租

缴租面板只保留一条主路径：

```text
合同至：2027-10-14       月租：3600元
已缴：1个月             剩余未缴：11个月
本次缴纳：[ 1 ] 个月    可选：1～11
覆盖：2026-11-15 至 2026-12-14
租金：3600元            押金：0元
[选择渠道]  [确认支付]
```

- 只接受整月，最少1个月，最多为**后端确认的当前合同范围内尚未缴清的月份**。已批准延长计入总期，待审/驳回不计；已全部缴清显示“租金已缴清”。
- 必须从最早未缴月份连续覆盖，不允许跳过欠租月份。可提前付多月；“尚未到应付日”不是禁止提前交租的理由。
- 修改月数重新获取离线报价，明确金额和覆盖起止；下单时在锁内重新核算，不能信任前端上限/金额。报价与下单之间有付款或租期变化时，要求确认新报价，不静默换月数/换金额。
- 现有paymentCycleMonths不再作为新表单隐藏的强制本次月数。旧协议/订单原文和已约定周期保留历史；如果旧签约文本需要更新付款约定，须使用明确修订确认，不能悄改已签快照。
- 金额为对应月份的租金合计，首期押金不重复收；普通交租只改变已缴覆盖，**绝不延长合同**。
- 仍按原起租日的日历月锚点划分，不按固定30天，也不从上一截止日反复加月造成月末漂移。

## 4. 现有账目与重复支付保护

- 本轮已成功的首期保持SUCCESS及原金额/覆盖期，不能为了换模型回退、删除或重新收款。
- 当前仍可支付的PENDING单继续展示原订单、月数和金额，不得强制覆盖其快照；如需改月数，先确认渠道已关闭/原单已安全终止，再重开，不能只改数据库CLOSED就另扣一次。
- 有待核对到账异常时先核对，不让自选月数绕过重复扣款保护。超时、迟到成功继续沿既有可信结果/异常记录规则，不在此改退款政策。
- 历史RENEWAL单与已发出的旧续租协议保留真实含义；旧未生效方案不得自动改成“已审核通过”，须明确取消/转换和告知后进入新流程。
- 历史存在不同价格的合同段时按各段原价报价；允许一次缴租跨越连续的已确认段时，支付单须有逐段覆盖与金额明细，不能把所有月份按当前月租一乘了之，也不能暗把用户上限缩为当前段剩余月数。

## 5. 实施范围与确认点

- 保留lease_record、原lease_contract_term及lease_payment历史；新增延长申请的原止期/申请月数/新止期/约定版本/审核留痕。新普通缴租继续为RENT；跨段用覆盖明细承接，不重新增加第二种“首期”。具体迁移/API在确认后的实施计划中确定。
- 同步租约详情、居民缴租面板、管理端审核/待办、群聊入口和时间线；展示原始期限、当前期限、已缴覆盖三个不同信息。
- 追溯现有C3/R61/R64/R73。已核对冻结定义C3明确写有“居民端续租支付成功后租期自动延展”，与本次审核即延长不同。需用户确认本方案后，先走决策日志及定义整份重写流程，只修正相应C3续约生效口径、保留首期成功生效等其它边界，再同步20/30；本轮不直接改冻结正文。

**请确认的是：审批通过即延长、只延时间不改价、普通缴租允许1至所有已确认剩余月数。**这些均按本次用户方向推荐，不沿用旧“续租首笔成功才延长”。

验收重点：12个月已付1个月可选1～11；支付11个月后不可再付；延长3个月审批前上限11、通过后14；重复审批只延长一次；缴租不延长；两窗口同区间不重复收；跨段按真实单价；旧首期/押金与同住关系不受影响。
