# 挂牌金额与申请占用闭环设计

> 按用户裁决修订 · 2026-10-11 · 仅处理出租入住与生效条件，支付渠道实测仍暂缓。

**关键设计：申请提交就保留房屋；审核默认使用申请时的挂牌价；协议确认并支付首期费用后，租约与正式居住关系才生效。**

## 1. 一条完整的操作流程

1. **居民申请**：从具体挂牌进入，核对月租、押金后提交。系统记住这条挂牌和当时的价格，立即临时占用房屋。同一房屋的所有出租挂牌对公众隐藏，其他人不能再申请。
2. **管理员审核**：审核弹窗自动带出申请时的月租、押金。管理员可以修改，通过后生成待签约租约；房屋继续保留，不算正式入住。
3. **管理员发协议**：发出即代表管理方同意，协议正文使用审核后的金额，不再重复确认。
4. **居民确认协议**：居民查看具体正文并同意，进入待首期费用阶段；继续临时保留房屋，不另设“确认承租”。
5. **支付首期费用**：后端确认首期支付成功后，租约生效，同时建立正式居住关系、将房屋置为已入住。支付未完成、失败或关闭支付窗口，都不能提前算入住。

社区自动审批也使用同一份申请时挂牌价，但只到待签约，不能跳过协议确认。

## 2. 管理端界面怎么改

**入住申请审核弹窗**：

| 内容 | 显示与操作 |
|---|---|
| 申请人、房屋、来源挂牌 | 只读，明确审核的是哪一条申请 |
| 申请时月租、押金 | 只读，作为价格对照 |
| 租约起止日期 | 管理员填写 |
| 租约月租、押金 | 默认带入申请时价格，允许修改 |
| 审核备注 | 沿用现有填写方式 |

审核金额不同于挂牌价时，租约历史自动记录**原价、采用价、操作人、时间及审核备注**。后续修改挂牌价，不会悄悄改变已经提交的申请。

**房源管理列表**：发布状态与占用情况分开显示。例如“已发布／待签约”，不能只显示“可租”。占用行可进入对应申请或租约。

## 3. 什么时候释放房屋

| 发生的动作 | 房屋与挂牌结果 |
|---|---|
| 提交申请、审核通过 | 保持临时占用，对公众隐藏 |
| 待审核申请撤回或驳回 | 解除本申请占用 |
| 待签约租约取消或驳回 | 解除本租约占用，结束本链协议和沟通会话 |
| 仅撤回一份协议正文 | **不释放**；租约仍待签约，可以重新发协议 |
| 居民确认协议 | 继续临时占用，等待首期费用 |
| 首期费用确认支付成功 | 转为正式占用，租约和居住关系生效，房屋已入住 |
| 正常迁出 | 无剩余住户或其他有效占用后释放 |
| 管理员主动下线挂牌 | **保持下线**，取消申请或租约也不能自动重新发布 |

解除占用后，只有房屋确实可用、挂牌仍处于发布状态，才恢复公开。列表、旧详情链接、新申请和新看房预约都遵守同一规则，不只是隐藏按钮；既有看房预约不自动取消。

## 4. 价格和历史如何保留

- 一套真实房屋可以有多条历史挂牌。**申请必须指向居民当时选择的那一条**，不能按“最新挂牌”猜价格。
- 申请保存来源与当时价格；租约保存审核后的约定金额和调整历史。
- 所有当前或历史曾被租住占用的挂牌都不物理删除，停止公开时只下线。解除当前占用后恢复原发布可见性，居住与租约历史仍保留。历史记录没有来源时明确提示缺失，不猜测补填。
- 房源不可申请时，居民页面给出说明和“我的入住申请”入口，不白屏。

## 5. 已确认的边界

- **正式生效在首期支付成功之后**，不是审核通过或仅确认协议之后。
- 占用期间对公众下线；取消或退租清理当前占用后恢复可见，但不覆盖管理员主动下线。
- 曾被占用的挂牌保留，租约与居住历史不因释放占用而删除。
- 只调整租赁申请链，不改变业主、家属或管理员直建关系的现有入口。

以上按本次用户裁决实施。交易渠道仍暂缓，不将离线验证写成渠道交易通过。
