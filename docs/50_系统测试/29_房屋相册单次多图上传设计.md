# 房屋相册单次多图上传设计

> 依据2026-10-15用户R-02反馈，供确认；既有单图相册没有其它问题，本次只补一次选择多张，不改图片归属和权限。

## 当前与推荐

当前HouseImageDialog的文件输入没有multiple，处理时也只取files[0]；后端一次上传一张并立即关联当前房屋。

推荐：**一次选多张，弹窗显示队列，逐张上传到同一房屋。**不为这一交互新增多文件大接口，不批量把照片挂到多套房屋。

## 交互规则

1. 点击“选择图片（可多选）”，当前已存N张时明确还可上传10－N张；本批沿用选中的实拍/平面图类型，上传后仍可逐张调整。
2. 选中多张后按选择顺序显示文件名及等待/上传中/成功/失败；串行上传，显示“已完成2/5”，避免并发造成顺序乱和容量竞争。
3. 单张仍沿用JPG/JPEG/PNG/GIF、5MB限制。超容量在请求前整批提示重新选择，不能静默只取前几张；不合格文件逐张标原因，不把失败伪称成功。
4. 上传成功立即保存关联；失败项可单独重试，成功项不重传。结束后刷新服务端相册，顺序/说明仍通过原“保存分类与顺序”。
5. 存在尚未保存的说明/排序时，先提示保存或放弃再上传，避免刷新把编辑覆盖。上传期间禁用切换房屋/关闭操作，批次始终绑定发起时房屋和类型。

## 不变与验收

house_image、单张上传接口、10张总上限、后端真实格式校验、房屋管辖权限、挂牌只读相册均不变；后端仍须锁内守住总量。

验收：一次选3张全部保存、刷新/另一入口同图；一张失败不使另两张丢失，重试不复制已成功图；已有9张再选2张不写入；切房不串图；未保存说明不丢；跨社区仍拒绝。

这是22既有方案的交互补充，批准后再实施并同步相册UI契约，不把新增多图要求反判原R-02失败。
