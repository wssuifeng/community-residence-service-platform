## 1. 缺陷生命周期定义（新建 → 打开 → 修复 → 验证 → 关闭 / 拒绝 / 延期，
各状态流转责任方与入口）

| 状态 | 含义 | 责任方 |
|------|------|--------|
| 新建 | 执行会话发现并登记（现象/步骤/期望/实际 + 关联 TR/TC） | 主测试会话 |
| 打开 | 经复核确认为系统缺陷，待修复（裁决严重度） | 主测试会话 |
| 修复 | 修复会话提交修复（登记 commit） | 后端/前端修复会话 |
| 验证 | 回归用例重测通过 | 主测试会话 |
| 关闭 | 验证通过且无新问题引入 | 主测试会话 |
| 拒绝 | 经裁决非缺陷（口径符合/设计如此/环境问题），写明理由 | 主测试会话（严重裁决需用户确认） |
| 延期 | 严重度不足以阻塞出口准则，经评估接受遗留（写入报告） | 用户确认 |
