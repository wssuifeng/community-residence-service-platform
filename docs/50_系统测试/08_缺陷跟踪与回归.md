各状态流转责任方与入口）

| 状态 | 含义 | 责任方 |
|------|------|--------|
| 新建 | 执行会话发现并登记（现象/步骤/期望/实际 + 关联 TR/TC） | 主测试会话 |
| 打开 | 经复核确认为系统缺陷，待修复（裁决严重度） | 主测试会话 |
| 修复 | 修复会话提交修复（登记 commit） | 后端/前端修复会话 |
| 验证 | 回归用例重测通过 | 主测试会话 |
| 关闭 | 验证通过且无新问题引入 | 主测试会话 |
| 拒绝 | 经裁决非缺陷（口径符合/设计如此/环境问题），写明理由 | 主测试会话（严重裁决需用户确认） |
| 延期 | 严重度不足以阻塞出口准则，经评估接受遗留（写入报告） | 用户确认 |

### 3.7 C2 可约时段栅格化设计定案（用户裁决 2026-09-14，归第三批第 13 项）

**模型（Slot Grid）**：
- 每资源配置：`slot_unit` 预约最小单位（分钟，15/30/60 可选默认 30）+
  `capacity`（语义收窄重定义：**资源级·每时段可承载人数上限**）；
- 周循环模板保存时强制校验起止对齐 slot_unit（不对齐 400，源头保栅格纯净）；
- 预约请求起止须为 slot_unit 整数倍（服务端校验 400）；
- available-slots 返回标准化栅格数组 `[{start, end, booked, capacity, remaining}]`：
  一次范围查询该日该资源全部占用态预约 → 内存按栅格分桶计数；
- 可约判定（服务端权威）：创建预约在 Redisson 锁内对请求覆盖的每个时段
  逐一检查 booked < capacity（复用 DEF-005 锁模式）；
- 三道安全防线：栅格对齐校验 + 锁内逐时段容量检查 + V11 唯一约束兜底；
- 迁移与存量：V11 补 resource.slot_unit 列（默认 30）；模板 max_bookings
  退役（统一 capacity 口径，存量模板值迁移映射后废弃列或保留不用）；
  存量非对齐预约不清洗，按「覆盖即占用」分桶计入；新预约强制对齐；
- 日容量 = 该日开放时段数 × capacity（派生计算不落库，两套口径问题消解）；
- C12 看房预约不套用此模型（capacity=1 语义简单，文档注明口径差异即可）。

性能口径：占用计算 O(预约数+时段数) 单查询分桶，不引入 Redis 预聚合
（50 并发教学规模过度设计）；同日排序 ORDER BY start_time（顺带修无序问题）。
