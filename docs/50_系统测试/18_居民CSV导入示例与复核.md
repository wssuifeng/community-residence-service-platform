# 居民CSV导入示例与复核

## 只看这三步

1. 管理员进入「居民管理 → 批量导入」，选操作社区，点击“查看结构业务编号”。编号强制社区-楼栋-单元-房屋四段，例如5-1-1-101；不是自增主键。此处仅查看，不提供数据导出。
2. 下载当前九列模板，复制表格中的准确编号，按[samples/居民导入九列业务编号样例.csv](samples/居民导入九列业务编号样例.csv)填写。占位编号必须替换成当前表格真实编号；手机号/用户名使用不重复的合成值。
3. 上传CSV并核对成功/失败/空白跳过行；只重试修正后的失败行。建议Excel另存CSV UTF-8，GB18030或带BOM UTF-16也可；不支持.xlsx。

## 当前九列格式

`房屋编号,姓名,手机号,证件号,用户名,邮箱,关系类型,入住日期,备注`

- 姓名、手机号必填；用户名/证件/邮箱选填，用户名支持中文且体系内唯一。
- 仅建账号：房屋编号、关系类型、入住日期和关系备注全留空，操作社区取上传窗口所选值。
- 登记关系：完整四段编号、关系类型、YYYY-MM-DD入住日期同时填写。OWNER/TENANT直接补录仅空置房；FAMILY/CO_RESIDENT须有同房屋有效主关系，主关系唯一时自动关联，不新建租约/支付单。
- 同户多人各一行独立账号；绑定已有账号使用“登记同住人员”，重复导入不合并账号。
- 仅编号且居民资料全空的行计skipped；半填或少列行单独失败，其他有效行可提交。每行账号和关系同事务，无主关系的失败行不会残留账号。
- 九列表头及空列逗号必须保留；旧十列/四列仍兼容，但不再要求新用户查找主键。旧样例仅作兼容资料，不是当前推荐模板。
- 5MB上限；成功初始密码仅结果展示，转交本人，不将其上传公开证据或提交Git。

当前工程证据：[BO接口回归](evidence/bo-implementation-20261014/api.json)、[浏览器回归](evidence/bo-implementation-20261014/browser.json)。用户HT-03结果仍由用户实际回归填写。
