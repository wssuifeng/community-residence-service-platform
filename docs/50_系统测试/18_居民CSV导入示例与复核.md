# 居民CSV导入示例与复核

## 只看这三步

1. 管理员进入「居民 → 批量导入」，下载模板；先选择实际社区，查看/下载房屋位置与ID对照；用Excel编辑时推荐另存为 **CSV UTF-8（逗号分隔）**，Excel GBK或带BOM UTF-16也可解析，不要上传.xlsx或仅更改后缀。
2. 参考[samples/居民导入十列样例.csv](samples/居民导入十列样例.csv)：先替换`{COMMUNITY_ID}`为真实社区主键；仅涉及关系的行再替换`{HOUSE_OWNER}`/`{HOUSE_TENANT}`/`{HOUSE_FAMILY}`为实际房屋主键。样例手机号/账号均为合成值，正常系统使用前自行改成不重复的测试值。
3. 选择CSV → 开始导入 → 核对成功行账号/关系与失败行原因。重复上传成功行应拒绝，不应重复建账号。仅修正失败行后重试。

## 实际模型和文件格式

| 列 | 约束 |
|---|---|
| 社区ID | 必填，实际community.id，且在当前管理员权限内 |
| 姓名、手机号 | 必填；手机号用于联系和初始密码；重复手机号拒绝 |
| 证件号 | 选填，本样例留空，不使用真人证件 |
| 用户名、邮箱 | 选填；用户名支持1～50位中文等文字/数字/下划线，重复或与他人手机号冲突拒绝；邮箱写入居民档案 |
| 房屋ID、关系类型、入住日期 | 三列全有或全无；房屋是house.id不是门牌号；类型OWNER/TENANT/FAMILY；日期YYYY-MM-DD |
| 备注 | 居住关系备注，仅关系行可填；含逗号/双引号时使用标准CSV引号转义（示例第12行姓名演示逗号/引号） |

十列表头必须按样例顺序保留；旧四列`社区ID,姓名,手机号,证件号`仍可用，但只建账号，不登记关系。单文件上限5MB，UTF-8/Excel GBK（GB18030兼容）/带BOM UTF-16，逐行独立事务，部分成功时已成功行不会因其他行失败回滚。管理员直接登记关系是台账录入，**不会自动创建租约或支付单**；租住申请正式关系仍遵循首期成功生效规则。

**现有能力并非“Excel导入导出”**：运行OpenAPI与ResidentController只有CSV导入，前端“下载模板”在浏览器生成CSV；目前没有居民导出接口。本次不新增.xlsx解析或导出功能。

## 本次上传表头问题（2026-10-13）

用户上传文件的编码是GBK兼容编码，十列表头本身正确。修复编码读取不等于替用户修正房屋归属：其中社区ID为2，三行房屋ID为2/3/4；本轮只读核实三个房屋均属于社区2，不能把原表头问题推断成房屋归属错误。导入仍按当时的空置/占用状态校验，后续填表应从真实对照复制主键，不以门牌号/序号替代。不改原上传文件，不把其个人资料复制到公开仓库。

新的对照按位置排序，展示社区名/ID、楼栋、单元、楼层、房号和实际房屋ID；ID不必连续。仅建账号时房屋/关系类型/日期/关系备注都留空，下载模板默认如此；含关系的行只使用有权访问的空置房。当前多人补录限制见[20_多人居住绑定现状与建议.md](20_多人居住绑定现状与建议.md)。
