## 一、非功能用例（NF）

### TC-NF-001 JMeter 压测场景设计与测试计划要素（压测蓝图）
- 关联：TR-NF-01　类型：性能　优先级：P0
- 前置：后端 dev profile 启动正常、种子数据就绪；JMeter 已安装（Q2 裁决）；压测会话与功能自动化错开时段执行（03 计划 §6 风险应对）；JVM 参数记录入 05 环境文档。
- 数据：200 注册账号池（含居民/管理员/服务人员混合，依赖：05 测试环境与数据 · 200 账号池与 JMeter CSV）；既有种子数据（社区 1/房屋/工单/公告/房源若干）。
- 步骤：
  1. 基于本蓝图在步骤 7 创建 .jmx 脚本（脚本文件归档于 docs/50_系统测试/scripts/，交付物清单见 03 计划 §7）；
  2. 线程组：50 并发线程，Ramp-up 60s，稳态持续时间 10min，循环模式「持续时间」；
  3. 登录前置：setUp 线程组以 200 账号池逐一登录换取 JWT，写入 CSV 供取样器引用（HTTP Header Manager 注入 Authorization: Bearer ${token}）；
  4. 取样器清单（Q2 裁决口径，01 §4）：
     - 列表：GET /api/v1/communities（公开）、GET /api/v1/units/{unitId}/houses（公开）、GET /api/v1/work-orders?page=1&size=20（需角色令牌）、GET /api/v1/notices（公开）、GET /api/v1/notifications（需角色令牌）；
     - 详情：GET /api/v1/work-orders/{id}（需角色令牌）、GET /api/v1/housings/{id}（公开）；
  5. 断言：每个取样器配置响应断言（HTTP 200）+ JSON 断言（code=SUCCESS/200，公开接口按实际统一响应格式）；
  6. 监听器：聚合报告（Aggregate Report）采集 P90/P95/P99、吞吐量、错误率，结果另存 CSV/JTL 供报告引用；
  7. 压测期间另挂 ≥50 路 WebSocket 在线连接（本用例仅登记场景要素，连接执行归 TC-NF-004）。
- 预期：
  1. 脚本要素齐全（线程组/取样器/断言/账号池/聚合报告）且可重复执行；
  2. 脚本参数（并发数/时长/接口清单）与 01 §4、03 §2.2 口径一致，任何偏离记录于执行记录。

### TC-NF-005 站内通知与会话消息在线送达 ≤ 3 秒（计时测量口径）
- 关联：TR-NF-03　类型：性能　优先级：P0
- 前置：与 TC-SP-019（WebSocket 推送时延双通道抽样）同体执行，本用例锁定计时方法；自动化计时采用 40 阶段 R30 双浏览器会话 E2E 模式（03 计划 §2.2）。
- 数据：resident1 + admin1（会话双方）；触发通知的业务操作数据（工单流转等，种子即可构造）。
- 步骤：
  1. 计时方法：发送端记录 HTTP 请求发出时刻 t0（自动化脚本 Date.now()，或手动秒表级计时），接收端记录消息渲染完成时刻 t1（铃铛红点/会话列表新消息 DOM 出现），时延 = t1 - t0；
  2. 通知通道抽样 ≥10 次：触发不同业务事件（工单受理/派单、预约审核、公告发布等）产生通知，对在线接收端逐次计时；
  3. 会话消息通道抽样 ≥10 次：反馈会话双方在线，POST /api/v1/feedbacks/{id}/messages 发送，对端渲染计时；
  4. 记录每一样本时延值入执行记录表（01 §4：任一超时记缺陷）。
- 预期：
  1. 全部样本（通知 ≥10 + 会话 ≥10）时延 ≤ 3s；
  2. 任一样本 > 3s 记 DEF（N3 判据），不达标不得出口（03 计划 §5 出口准则 4）。

### TC-NF-006 密码 BCrypt 加密存储（库内哈希抽样核对）
- 关联：TR-NF-04　类型：安全　优先级：P0
- 前置：种子数据已执行（V3 超管 + V6 五角色演示账号）；测试库只读查询通道可用（05 环境文档登记查询脚本）。
- 数据：抽样账号 superadmin、admin1、staff1（sys_user 表）与 resident1（resident 表）。
- 步骤：
  1. 直查库：`SELECT username, password_hash FROM sys_user;` 与 `SELECT username, password_hash FROM resident;`；
  2. 逐行断言 password_hash 前缀为 `$2a$`（BCrypt 标识）；
  3. 断言无任何明文密码、无 MD5（32 位十六进制）/SHA 系裸哈希形态字段；
  4. 新建一个测试账号（居民注册或管理员代建），再查库核对其哈希同样为 BCrypt 且与明文不同、与既有账号哈希不同（随机盐）。
- 预期：
  1. 抽样账号哈希 100% 为 `$2a$` 前缀 BCrypt 格式；
  2. 同一明文密码（如种子默认密码）在不同账号上哈希不同（盐随机）；
  3. 发现明文/弱哈希存储记 DEF（P0 安全缺陷）。

### TC-NF-007 JWT 有效期与登出令牌失效（联动 TC-C10-001）
- 关联：TR-NF-04　类型：安全　优先级：P0
- 前置：本用例与功能用例 TC-C10-001（登录认证）同体执行，此处仅登记非功能侧断言点；后端 JWT 配置 Access Token 默认 2h（架构设计 §3.1）。
- 数据：resident1 / admin1 令牌各一份。
- 步骤：
  1. 登录取 Access Token，解析（jwt.io 或脚本）核对有效期声明（exp）与签发时刻差约 2h；
  2. 携带有效令牌访问任一受保护接口（GET /api/v1/notifications）→ 预期 200；
  3. 调用登出端点（POST /api/v1/auth/resident/logout 或 /api/v1/auth/admin/logout）；
  4. 立即以原令牌再次访问同一受保护接口；
  5. 直查库：`SELECT * FROM auth_token_blacklist;` 核对 jti/expire_time/reason 落库。
- 预期：
  1. 登出后原令牌访问被拒（401 令牌已失效），黑名单立即生效；
  2. auth_token_blacklist 存在对应 jti 记录，reason=LOGOUT；
  3. 令牌过期后访问同样被拒（可由短时效测试账号或等待验证，口径归 TC-C10-001 展开）。

### TC-NF-009 操作日志仅追加不可修改（库与接口双口径）
- 关联：TR-NF-06　类型：安全　优先级：P1
- 前置：sys_operation_log 已有种子操作后的日志数据；swagger-ui 可访问；库只读查询通道可用。
- 数据：任一已有关键变更操作（如 admin1 编辑社区信息）产生的日志记录。
- 步骤：
  1. 接口层核查：遍历 swagger-ui 与接口设计.md §9.10，确认不存在任何对 /api/v1/operation-logs 的 PUT/PATCH/DELETE 端点（仅 GET /api/v1/operation-logs 与 GET /api/v1/operation-logs/{id}）；
  2. 代码层核查（留痕）：后端 log 包 AOP 切面与 auth 模块对 sys_operation_log 仅有 insert 入口，无 update/delete 调用（grep 核对，结果记入执行记录）；
  3. 直查库核对：记录某条日志的 id 与字段快照；
  4. 以超管身份执行若干正常业务操作后，重查该条日志。
- 预期：
  1. 接口层无修改/删除日志的入口（契约与实现一致）；
  2. 业务操作只会新增日志行，原日志字段（操作人/时间/对象/内容）不可变；
  3. 发现任何可变更既有日志的通道记 DEF（P1 安全缺陷）。
