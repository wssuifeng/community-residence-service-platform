# 功能用例 · C2 居民与居住关系管理

> 依据：01_测试需求分析.md §3.2（TR-C2-01~11）、需求规格 R7~R12 + E2、接口设计 9.2、架构设计 §6.5（入住申请三态）。
> 编号规则：TC-C2-NNN；每条至少覆盖一个 TR；执行结果列由步骤 7 回填。
> 通用约定：
> - 种子账号（Flyway V3/V6）：超管 `superadmin / Admin@123456`、社区管理员 `admin1 / Admin123456`（绑定「阳光花园社区」）、居民 `resident1 / Resident123456`（已入住 101，OWNER 居住关系）；
> - 全局配置键（V2 种子）：`registration.enabled`（自助注册开关）、`registration.need_approval`（入住申请是否需审核）；
> - 「操作日志断言」统一指 sys_operation_log 有对应记录，验证方式：超管调 `GET /api/v1/operation-logs` 或库内直查；
> - 涉及注册开关的用例执行后**必须恢复默认值 true/true**（强制检查项）；
> - 每条用例新建的测试居民账号由 05 数据集管理，账号池命名见 05 测试环境与数据。

### TC-C2-001 超管独立配置注册方式开关（三种组合）
- 关联：TR-C2-01　类型：功能　优先级：P1
- 前置：superadmin 已登录
- 数据：无额外（用种子数据；V2 默认 registration.enabled=true、registration.need_approval=true）
- 步骤：
  1. 组合①「代建开·自助开」：调 `GET /api/v1/configs/registration.enabled` 确认 true，`PUT` 维持 true；
  2. 组合②「代建开·自助关」：`PUT /api/v1/configs/registration.enabled` 置 false，调 `GET /api/v1/configs/{key}` 验证；
  3. 组合③「关开」：将 registration.enabled 恢复 true、`PUT /api/v1/configs/registration.need_approval` 置 false，调 GET 验证；
  4. 每次修改后查操作日志；
  5. **恢复默认：两个键均置回 true/true**。
- 预期：
  1. 组合①读取成功，值 true；
  2. 更新成功且 GET 返回 false（两开关独立，互不影响，R7）；
  3. 更新成功且 GET 返回 false（另一开关不受牵连）；
  4. 每次配置变更均有 sys_operation_log 记录（R7 联动：配置变更写操作日志）；
  5. 恢复后两键均为 true（供后续用例使用）。

### TC-C2-002 超管更新配置非法值拒绝
- 关联：TR-C2-01　类型：异常与边界　优先级：P1
- 前置：superadmin 已登录
- 数据：无额外（用种子数据）
- 步骤：
  1. 调 `PUT /api/v1/configs/registration.enabled`，value 传空字符串；
  2. 调 `PUT /api/v1/configs/{不存在的key}`，value 传 "true"；
  3. 调 `GET /api/v1/configs/registration.enabled` 确认原值未变。
- 预期：
  1. 参数校验拒绝（value @NotBlank）；
  2. 返回明确错误（配置项不存在），无新增配置；
  3. 值保持步骤前状态，数据不变。

### TC-C2-003 社区管理员访问全局配置接口 100% 被拒并记录
- 关联：TR-C2-02　类型：权限　优先级：P0
- 前置：admin1 已登录
- 数据：无额外（用种子数据）
- 步骤：
  1. admin1 调 `GET /api/v1/configs`（配置列表）；
  2. admin1 调 `PUT /api/v1/configs/registration.enabled`，body `{"value":"false"}`；
  3. 超管调 `GET /api/v1/configs/registration.enabled` 确认值未变；
  4. 超管查操作日志。
- 预期：
  1. 请求被拒（403，配置列表仅超管）；
  2. 请求被拒（403，R7「社区管理员访问全局配置接口 100% 被拒并记录」）；
  3. registration.enabled 仍为 true，数据不变；
  4. sys_operation_log 存在步骤 1、2 的越权记录。

### TC-C2-004 关闭自助注册后注册接口明确拒绝
- 关联：TR-C2-03　类型：功能　优先级：P1
- 前置：superadmin 已登录
- 数据：依赖：05 测试环境与数据 · 测试账号池（未占用的用户名/手机号）
- 步骤：
  1. 超管 `PUT /api/v1/configs/registration.enabled` 置 false；
  2. 以游客身份调 `POST /api/v1/auth/resident/register` 提交合法注册请求；
  3. 查 resident 表确认无新增账号；
  4. 超管将 registration.enabled 恢复 true，再次提交相同注册请求。
- 预期：
  1. 配置更新成功；
  2. 返回明确拒绝（业务错误码 5201 注册已关闭，R7「注册接口返回明确拒绝」）；
  3. resident 表无新增行；
  4. 恢复后注册成功（开关生效的对照验证；测试账号入 05 账号池）。

### TC-C2-006 管理员代建居民：录入信息 + 初始密码 → 可登录 + 操作入日志
- 关联：TR-C2-04　类型：功能　优先级：P1
- 前置：admin1 已登录（绑定阳光花园社区）
- 数据：依赖：05 测试环境与数据 · 测试账号池（代建专用居民：姓名/手机号/证件号）；依赖：05 测试环境与数据 · 代建入口口径确认（见文末口径疑点 1：实现未见独立代建端点，按「管理员经注册端点代为录入」口径设计，执行前以 03 计划/05 数据脚本定稿口径为准）
- 步骤：
  1. admin1 在管理端录入居民信息（姓名、联系方式、证件号）并设置初始密码（代建路径）；
  2. 查 sys_operation_log 核对代建操作记录；
  3. 用新账号 + 初始密码调 `POST /api/v1/auth/resident/login`；
  4. 登录后调 `GET /api/v1/residents/profile` 核对资料。
- 预期：
  1. 代建成功，账号创建（R8）；
  2. 日志含操作人 admin1、目标 RESIDENT 的创建记录（R8「操作入日志」）；
  3. 登录成功，签发 JWT（R8「代建成功后居民可登录」）；
  4. 姓名联系方式与录入一致。

### TC-C2-007 代建/注册重复唯一性拒绝
- 关联：TR-C2-04　类型：异常与边界　优先级：P1
- 前置：resident1 已存在（种子）；admin1 或游客通道可用
- 数据：无额外（用种子数据）
- 步骤：
  1. 用与 resident1 相同的用户名提交注册；
  2. 用与 resident1 相同的手机号、不同用户名提交注册；
  3. 提交密码长度 7 位（低于下限）的注册请求；
  4. 提交非法格式证件号（17 位）的注册请求。
- 预期：
  1. 唯一性冲突拒绝（用户名重复）；
  2. 唯一性冲突拒绝（手机号重复）；
  3. 参数校验拒绝（密码 min=8）；
  4. 参数校验拒绝（证件号格式），以上均不产生新账号。

### TC-C2-008 自助注册 + 提交入住申请 → 待审核
- 关联：TR-C2-05　类型：功能　优先级：P1
- 前置：registration.enabled=true（默认）；阳光花园社区存在空置房屋（种子 102 或 201）
- 数据：依赖：05 测试环境与数据 · 测试账号池（新注册居民；目标空置房屋 102/201）
- 步骤：
  1. 新居民自助注册并登录（`POST /api/v1/auth/resident/register` → login）；
  2. 调 `POST /api/v1/residence-applications`（houseId=空置房屋、申请类型 RENT、入住日期、家庭人数、联系方式）；
  3. 调 `GET /api/v1/residence-applications/{id}` 查详情；
  4. admin1 调 `GET /api/v1/residence-applications?status=PENDING` 查待审核列表。
- 预期：
  1. 注册登录成功；
  2. 提交成功，status=PENDING（待审核，R9）；
  3. 详情含居民姓名、房屋地址（1号楼1单元xxx）、申请类型、入住日期；
  4. 管理端待审核列表可见该申请。

### TC-C2-009 入住申请异常：非空置房屋与重复申请拒绝
- 关联：TR-C2-05　类型：异常与边界　优先级：P1
- 前置：新测试居民已注册登录；TC-C2-008 的待审核申请存在
- 数据：依赖：05 测试环境与数据 · 测试账号池（同 TC-C2-008 居民）；种子房屋 101（OCCUPIED）
- 步骤：
  1. 调 `POST /api/v1/residence-applications`，houseId=种子 101（已入住非空置）；
  2. 调 `POST /api/v1/residence-applications`，houseId=空置房屋（该居民已有 TC-C2-008 待审核申请）；
  3. moveInDate 传空提交。
- 预期：
  1. 返回明确拒绝（业务错误码 5204 房屋状态非空置）；
  2. 返回明确拒绝（业务错误码 5205 已有待审核申请，防重复申请）；
  3. 参数校验拒绝；三条均未产生新申请。

### TC-C2-010 审核通过：建立居住关系 + 功能入口开放 + 通知申请人
- 关联：TR-C2-06　类型：功能　优先级：P0
- 前置：admin1 已登录；TC-C2-008 的待审核申请存在（目标空置房屋）
- 数据：依赖：05 测试环境与数据 · 同 TC-C2-008（申请与居民）
- 步骤：
  1. admin1 调 `PATCH /api/v1/residence-applications/{id}/approve`（含租住起止/租金等审批信息）；
  2. 核对响应 data：residenceRelationId、leaseRecordId 非空（自动创建居住关系与租住记录）；
  3. 该居民登录后调 `GET /api/v1/residents/{residentId}/residences` 查居住关系，并访问居民端私有功能入口（如工单提交页 `POST /api/v1/workorders` 预检或资源预约页）；
  4. 调 `GET /api/v1/houses/{houseId}` 核对房屋状态联动；
  5. 该居民查通知中心（`GET /api/v1/notifications`）核对申请通过通知；
  6. 超管查操作日志。
- 预期：
  1. 审批通过成功，申请状态→APPROVED（已通过）；
  2. 居住关系（ACTIVE）与租住记录已自动创建且关联正确；
  3. 居住关系可查；居民端私有业务功能入口全部开放可用（C2 判据「通过后账号获得居民端业务功能入口」）；
  4. 房屋状态联动更新为 OCCUPIED；
  5. 通知中心存在「申请通过」站内通知（R48 联动，含操作时间可溯源）；
  6. 审批操作有日志记录。

### TC-C2-011 审核驳回：须填理由 + 通知申请人
- 关联：TR-C2-07　类型：异常与边界　优先级：P1
- 前置：admin1 已登录；存在另一居民的待审核申请
- 数据：依赖：05 测试环境与数据 · 第二测试居民及其待审核入住申请
- 步骤：
  1. admin1 调 `PATCH /api/v1/residence-applications/{id}/reject`，不传 reason（或空串）；
  2. 补填 reason=「房屋已被预定」重新提交；
  3. 该居民查通知中心；
  4. 查操作日志。
- 预期：
  1. 参数校验拒绝（驳回理由必填，R9「驳回须填理由」），申请仍为 PENDING；
  2. 驳回成功，申请状态→REJECTED（已驳回，终态）；
  3. 该居民收到「申请被拒绝（含理由）」通知（R48 联动）；
  4. 驳回操作有日志记录。

### TC-C2-012 入住申请非法流转拒绝（已通过/已驳回再审批）
- 关联：TR-C2-07　类型：异常与边界　优先级：P1
- 前置：TC-C2-010（已通过）与 TC-C2-011（已驳回）的申请均已存在
- 数据：依赖：05 测试环境与数据 · 同 TC-C2-010/011 产物申请
- 步骤：
  1. admin1 对已通过（APPROVED）的申请调 approve；
  2. 对已驳回（REJECTED）的申请调 reject；
  3. 核对两申请的居住关系/通知数量。
- 预期：
  1. 返回明确拒绝（业务错误码 5202 仅待审核可审批；状态机「待审核→已通过/已驳回」之外无合法流转，架构设计 §6.5）；
  2. 同上被拒；
  3. 未产生重复居住关系、未产生新通知（非法流转不产生副作用）。

### TC-C2-013 居民申请搬出 → 审核通过终止关系 + 入口失去 + 历史保留
- 关联：TR-C2-08　类型：功能　优先级：P1
- 前置：TC-C2-010 产物的居民有 ACTIVE 居住关系；admin1 已登录
- 数据：依赖：05 测试环境与数据 · 同 TC-C2-010（居民与居住关系）
- 步骤：
  1. 该居民在居民端发起搬出申请（居民申请路径）；
  2. admin1 审核通过（`PATCH /api/v1/residence-relations/{id}/move-out`，含搬出日期与原因）；
  3. 调 `GET /api/v1/residents/{residentId}/residences?status=MOVED_OUT` 查历史关系；
  4. 该居民登录后访问居民端私有功能入口（工单提交/资源预约）；
  5. 调 `GET /api/v1/houses/{houseId}` 核对房屋状态；
  6. 该居民查通知中心核对搬出通知；查操作日志。
- 预期：
  1. 搬出申请进入待审核/待办理状态；
  2. 迁出办理成功，关系状态→MOVED_OUT，moveOutDate 记录在案（R10「审核后居住关系终止并记录搬出时间」）；
  3. 历史关系可查（R10「历史保留」）；
  4. 该居民失去对应房屋的居民端功能入口（C2 判据，无有效居住关系的账号不具备居民端私有业务功能入口）；
  5. 房屋无其他居民时状态联动回 VACANT；
  6. 搬出通知送达（R48 联动）；迁出操作有日志记录。

### TC-C2-014 管理员发起搬出 + 非 ACTIVE 关系迁出被拒
- 关联：TR-C2-08　类型：异常与边界　优先级：P1
- 前置：admin1 已登录；存在 ACTIVE 关系与已 MOVED_OUT 关系各一条
- 数据：依赖：05 测试环境与数据 · 管理员代发起搬出的居民（ACTIVE 关系）；TC-C2-013 产物（MOVED_OUT 关系）
- 步骤：
  1. admin1 直接对 ACTIVE 居住关系调 `PATCH /api/v1/residence-relations/{id}/move-out`（管理员发起路径，不经居民申请）；
  2. 对已 MOVED_OUT 的关系再次调 move-out；
  3. 核对第二次操作后的通知与日志。
- 预期：
  1. 管理员发起路径迁出成功（R10「居民申请或管理员发起搬出」两路径均可用）；
  2. 返回明确拒绝（业务错误码 5206 仅 ACTIVE 可迁出，状态机非法流转拒绝）；
  3. 步骤 2 未产生新通知，越权/非法流转尝试有日志记录。

### TC-C2-015 按房屋查当前与历史居住人员
- 关联：TR-C2-09　类型：统计核对　优先级：P2
- 前置：admin1 已登录；种子房屋 101（resident1 当前 OWNER 关系）+ 一条历史关系（TC-C2-013 产物或 05 数据集预置）
- 数据：依赖：05 测试环境与数据 · 房屋 101 历史居住关系一条（TC-C2-013 产物或脚本预置）
- 步骤：
  1. admin1 调 `GET /api/v1/houses/{101 id}/residents`（不过滤状态）；
  2. 同接口加 `status=ACTIVE` 过滤；
  3. 同接口加 `status=MOVED_OUT` 过滤；
  4. 将三组结果与库内 residence_relation（house_id=101）直查比对。
- 预期：
  1. 返回当前 + 历史全部居住人员，含姓名、电话、入住/搬出日期、状态；
  2. 仅当前（ACTIVE）居住人员；
  3. 仅历史（MOVED_OUT）居住人员；
  4. 双向一致（R11「按房屋查当前与历史居住人员」，结果与居住关系数据 100% 一致）。

### TC-C2-016 按居民查全部居住历史与双向一致性
- 关联：TR-C2-09　类型：统计核对　优先级：P2
- 前置：resident1 已登录（或 admin1 代查）；该居民存在一条以上居住关系
- 数据：依赖：05 测试环境与数据 · resident1 第二条居住关系（历史，脚本预置或 TC-C2-013 类产物）
- 步骤：
  1. resident1 调 `GET /api/v1/residents/{resident1 id}/residences` 查本人全部居住历史；
  2. resident1 尝试调 `GET /api/v1/residents/{他人 id}/residences`（越权对照）；
  3. 将步骤 1 结果与库内 residence_relation（resident_id=resident1）直查比对，并与 TC-C2-015 房屋维度结果交叉核对。
- 预期：
  1. 返回其全部居住历史（含社区、房屋地址、入住/搬出日期、状态）；
  2. 被拒（403/404，居民仅可查本人，数据级权限）；
  3. 居民维度与房屋维度台账交叉一致（R11「双向查询结果与居住关系数据一致」）。

### TC-C2-017 游客访问居住私有接口一律拒绝
- 关联：TR-C2-10　类型：权限　优先级：P0
- 前置：未携带任何令牌（游客）
- 数据：无额外（用种子数据）
- 步骤：
  1. 不带 Authorization 调 `GET /api/v1/residents/profile`；

### TC-C2-020 E2 全流程：注册→入住申请→审核通过（通知）→功能开放→搬出→审核→终止归档
- 关联：TR-C2-11　类型：功能　优先级：P0
- 前置：superadmin、admin1 已登录；registration 默认开关 true/true
- 数据：依赖：05 测试环境与数据 · E2 流程专用居民账号与空置房屋（05 账号池 + 社区空置房）
- 步骤：
  1. 新居民自助注册并登录；
  2. 提交入住申请（房屋/关系类型/居住起止）；
  3. admin1 审核通过；
  4. 验证居住关系建立 + 居民端功能入口开放 + 收到通过通知；
  5. 居民发起搬出申请；
  6. admin1 审核通过（迁出办理）；
  7. 验证关系终止归档（MOVED_OUT + 历史可查）+ 居民端入口关闭 + 房屋状态回 VACANT；
  8. 全程逐步核对操作日志。
- 预期：
  1. 注册登录成功；
  2. 申请 PENDING；
  3. 申请 APPROVED；
  4. 居住关系 ACTIVE、租住记录创建、房屋 OCCUPIED、通知送达、私有入口可用（E2 数据流逐环验证）；
  5. 搬出申请进入办理；
  6. 关系终止（MOVED_OUT），moveOutDate 记录；
  7. 历史关系可查、入口关闭、房屋状态联动；
  8. 注册后关键操作（申请/审批/迁出）均有日志（E2 全流程留痕）。
