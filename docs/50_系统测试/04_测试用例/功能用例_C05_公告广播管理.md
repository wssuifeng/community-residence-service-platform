# 功能用例 · C5 公告广播管理

> 依据：01_测试需求分析.md §3.5（TR-C5-01~07）、需求规格 R24~R27 + E5、
> 接口设计 9.5（实现口径以后端 NoticeController/NoticeService 为准，
> 状态常量 NoticeStatus）。编号规则：TC-C5-NNN；每条至少覆盖一个 TR；
> 执行结果列由步骤 7 回填。
>
> 种子账号（Flyway V3/V6）：superadmin/Admin@123456（超管）、
> admin1/Admin123456（社区管理员，绑定社区 1）、resident1/Resident123456
> （居民，社区 1）；种子公告「欢迎入住阳光花园社区」（PUBLISHED，
> 定向社区 1，有效期 365 天）。
> 公告状态机：DRAFT 草稿 → PUBLISHED 已发布 → WITHDRAWN 已撤回
> （过期下线由定时任务置 WITHDRAWN + 查询期过滤兜底，NoticeAutoOfflineTask
> 每小时整点，R26 口径）。
>
> **实现口径说明（影响用例预期，见文末口径疑点）**：
> - 定向目标当前仅支持社区级（notice_target targetType=COMMUNITY），
>   楼栋级定向与「多社区勾选」未实现（创建接口单 communityId）；
> - notice 表无 priority 列（优先级/置顶在 work_order 表），后端列表
>   仅按 publishTime 倒序，置顶由前端按 priority 标记——但后端并不返回
>   priority 字段，置顶链路存疑（TR-C5-03 按需求原文设计）；
> - 删除仅限 DRAFT/WITHDRAWN（已发布走撤回后再删），删除前清
>   notice_target + notice_view_record 两张子表（BE-ISSUE-8 修复口径）；
> - 记录查看（POST /{id}/view）限已发布公告，同一用户同一公告仅一次
>   （uk_notice_user 唯一键 + 业务判重），首次查看 view_count +1。

### TC-C5-001 创建公告（定向社区，正常）
- 关联：TR-C5-01　类型：功能　优先级：P0
- 前置：admin1 已登录（绑定社区 1）。
- 数据：title=「国庆假期物业服务安排」，
  content=「国庆假期期间，物业服务时间调整为 9:00-18:00」，
  publishTime=当前时间前 1 分钟，endTime=当前时间 + 20 天，
  communityId=1。
- 步骤：
  1. admin1 调用 POST /api/v1/notices 创建公告；
  2. 调用 PATCH /api/v1/notices/{id}/publish 发布；
  3. resident1 登录调用 GET /api/v1/notices 查看公告列表。
- 预期：
  1. 创建成功，初始 status=DRAFT，publisherId=admin1，
     endTime 未传时缺省为 publishTime + 30 天（默认值口径）；
  2. 发布成功，status=PUBLISHED，publishTime 生效（早于当前时间立即发布）；
  3. 居民列表返回该公告（R24 验收：发布后目标范围用户可见）。

### TC-C5-002 公告编辑留痕（仅草稿可改）
- 关联：TR-C5-01　类型：功能　优先级：P1
- 前置：admin1 已登录；准备 DRAFT 公告与 PUBLISHED 公告各 1 条。
- 数据：编辑请求 title=「国庆假期物业服务安排（修订）」。
- 步骤：
  1. admin1 对 DRAFT 公告调用 PUT /api/v1/notices/{id} 修改标题；
  2. admin1 对 PUBLISHED 公告调用 PUT 修改；
  3. 查询管理端操作日志（sys_operation_log）。
- 预期：
  1. 草稿修改成功，标题更新，操作日志可检索到本次编辑记录
     （R24 编辑留痕）；
  2. 已发布公告编辑被拒（5004，仅草稿状态的公告可修改），内容不变；
  3. 编辑与拒绝尝试均有日志留痕。

### TC-C5-003 社区管理员越范围发布被拒并记录
- 关联：TR-C5-01　类型：权限　优先级：P0
- 前置：admin1 已登录（仅绑定社区 1）。
- 数据：依赖：05 测试环境与数据 · 社区 2（超管创建）。
  创建公告请求 communityId=2（越范围）与 communityId=null（全系统广播）。
- 步骤：
  1. admin1 调用 POST /api/v1/notices，communityId=2；
  2. admin1 调用 POST /api/v1/notices，communityId 为空；
  3. 检查越权日志留痕。
- 预期：
  1. 越绑定社区发布被拒（403/明确业务错误，checkCommunityAccess），
     不产生公告与 notice_target 记录（R24 验收：越范围被拒绝并记录）；
  2. 社区管理员不指定目标社区（全系统广播）被拒
     （INVALID_PARAM，社区管理员必须指定目标社区）；
  3. 两次拒绝均有越权留痕可检索。

### TC-C5-004 超管全系统广播
- 关联：TR-C5-01　类型：功能　优先级：P0
- 前置：superadmin 已登录。
- 数据：title=「系统升级维护通知」，communityId=null（广播），
  publishTime=当前时间。
- 步骤：
  1. superadmin 调用 POST /api/v1/notices，communityId 为空；
  2. 调用 PATCH /{id}/publish 发布；
  3. 依赖：05 测试环境与数据 · 社区 2 的居民 resident2 登录查询公告列表；
  4. resident1（社区 1）查询公告列表。
- 预期：
  1. 创建成功（无 notice_target 记录，表示全系统广播）；
  2. 发布成功；
  3. 非任何特定社区绑定的居民也可见该广播（全系统可达）；
  4. 社区 1 居民同样可见。

### TC-C5-005 定向可见性（范围外用户不可见）
- 关联：TR-C5-02　类型：功能　优先级：P1
- 前置：存在定向社区 1 的已发布公告 A；依赖：05 测试环境与数据 ·
  社区 2 及其居民 resident2。
- 数据：无新增。
- 步骤：
  1. resident1 调用 GET /api/v1/notices 查询列表；
  2. resident2 调用 GET /api/v1/notices 查询列表；
  3. resident2 调用 GET /api/v1/notices/{公告 A id} 查看详情；
  4. 未登录游客调用 GET /api/v1/notices。
- 预期：
  1. resident1 列表含公告 A（目标范围用户可见）；
  2. resident2 列表不含公告 A（R25 验收：范围外用户不可见）；
  3. 范围外用户直接访问详情被拒（404 公告不存在或已下线口径，
     或经列表过滤不可达），内容不泄露；
  4. 游客可见公告列表（公开信息），但仅含面向其可达范围的公告。

### TC-C5-006 置顶公告排列表最前
- 关联：TR-C5-03　类型：功能　优先级：P2
- 前置：存在多条 NORMAL 优先级已发布公告 + 1 条高优先级
  （HIGH/URGENT）公告，发布时间晚于若干普通公告。
- 数据：依赖：05 测试环境与数据 · 高优先级公告（若创建接口不支持
  priority 字段则以 SQL 直插口径造数，见口径疑点 2）。
- 步骤：
  1. resident1 调用 GET /api/v1/notices 获取列表第一页；
  2. 检查高优先级公告的相对位置与置顶标记；
  3. 游客端公告列表页面核对置顶展示。
- 预期：
  1. 置顶（高优先级）公告排在列表最前（R25 验收），先于发布时间更早
     的普通公告；
  2. 高优先级公告带「置顶」标记；
  3. 游客端同样置顶展示。
  4. **当前实现 notice 表无 priority 列、后端列表仅按 publishTime 倒序，
     预期本用例失败并记缺陷**（前端 isPinned 依赖后端返回的 priority
     字段，链路断裂）——以步骤 7 实测为准。

### TC-C5-007 有效期设置与缺省 30 天
- 关联：TR-C5-04　类型：边界　优先级：P1
- 前置：admin1 已登录。
- 数据：请求 A：endTime=当前时间 + 2 小时（短有效期）；
  请求 B：不传 endTime。
- 步骤：
  1. admin1 用请求 A 创建并发布公告甲；
  2. 用请求 B 创建并发布公告乙；
  3. 分别查询两条公告详情（管理端）核对 endTime。
- 预期：
  1. 公告甲 endTime 为指定值（生效/失效时间可设置，R26）；
  2. 公告乙 endTime 为 publishTime + 30 天（缺省口径）；
  3. 两条公告状态均为 PUBLISHED，目标范围正确写入 notice_target。

### TC-C5-008 过期公告自动下线（居民不可见 + 后台归档可查）
- 关联：TR-C5-04　类型：可靠性　优先级：P1
- 前置：公告甲（endTime=当前时间 + 2 小时）已发布且被 resident1 查看过；
  等待至过期后经过一个整点（NoticeAutoOfflineTask 每小时执行）；
  也可依赖：05 测试环境与数据 · SQL 直插 endTime 已过的 PUBLISHED 公告
  加速验证。
- 数据：无新增。
- 步骤：
  1. 过期后（任务执行前，查询期过滤兜底窗口）resident1 查询公告列表；
  2. 任务执行后（整点过后）resident1 再查列表与详情；
  3. admin1 查询管理端公告列表；
  4. 查询 sys_task_log 中 NoticeAutoOfflineTask 的执行记录。
- 预期：
  1. 过期公告不再返回（查询期 endTime 过滤兜底，即使任务未跑也不出现，
     下线前窗口期 ≤1 小时）；
  2. 任务执行后公告被置 WITHDRAWN，详情对普通用户返回 404
     （R26 验收：过期后列表接口不再返回该公告）；
  3. 管理端列表仍可见该公告（含 WITHDRAWN 状态），后台归档可查
     （R26 验收后半句）；
  4. sys_task_log 有对应执行记录（任务名/开始时间/耗时/处理条数），
     幂等（重复执行不重复处理）。

### TC-C5-009 查看记录与已读统计
- 关联：TR-C5-05　类型：统计核对　优先级：P2
- 前置：定向社区 1 的已发布公告；resident1 在线。
- 数据：无新增。
- 步骤：
  1. resident1 调用 POST /api/v1/notices/{id}/view 记录查看；
  2. resident1 再次调用 view（重复查看）；
  3. admin1 调用 GET /api/v1/notices/{id}/viewers 查看查看记录分页；
  4. resident1 查询公告详情核对 viewCount；
  5. SQL 直查 notice_view_record 与 viewers 接口结果比对。
- 预期：
  1. 首次查看记录成功，写入 notice_view_record；
  2. 同一用户同一公告仅记录一次（重复查看不新增记录、viewCount 不重复
     累加，uk_notice_user 兜底）；
  3. viewers 明细含 resident1（用户/姓名/查看时间）；
  4. viewCount 与实际已查看人数一致；
  5. 已读人数（viewers total）与查看记录明细 100% 一致
     （R27 验收：已读统计数与查看记录明细一致）；
  6. 目标人数口径：目标社区居民总数与已读人数分别可查，比值即已读率
     （看板/接口口径以实测收口）。

### TC-C5-010 发布过且有查看记录的公告删除（BE-ISSUE-8 回归）
- 关联：TR-C5-06　类型：异常　优先级：P1
- 前置：公告乙（发布过、resident1 有查看记录、状态 PUBLISHED）；
  admin1 已登录；可直连测试库执行 SQL。
- 数据：无新增。
- 步骤：
  1. admin1 直接调用 DELETE /api/v1/notices/{公告乙 id}（PUBLISHED 态）；
  2. admin1 调用 PATCH /{id}/withdraw（reason=「内容需要修正」）撤回；
  3. admin1 再次调用 DELETE；
  4. SQL 直查三表：notice、notice_target、notice_view_record 中该
     公告 id 的残留记录。
- 预期：
  1. PUBLISHED 态直接删除被拒（5004，仅草稿或已撤回的公告可删除），
     数据不变；
  2. 撤回成功，status=WITHDRAWN；
  3. 删除返回 200 删除成功（BE-ISSUE-8 修复：删除前清两张子表，
     不再触发 FK RESTRICT 冲突）；
  4. 三表零残留：notice 无该行、notice_target 无该公告目标记录、
     notice_view_record 无该公告查看记录（BE-ISSUE-8 验收口径）。

### TC-C5-011 公告撤回与撤回后可见性
- 关联：TR-C5-01、TR-C5-06　类型：功能　优先级：P1
- 前置：已发布公告；admin1、resident1 就绪。
- 数据：reason=「内容需要修正」；空 reason 一组。
- 步骤：
  1. admin1 调用 PATCH /api/v1/notices/{id}/withdraw，reason 为空；
  2. 带理由撤回；
  3. resident1 查询公告列表与详情；
  4. admin1 对 DRAFT 公告调用 withdraw。
- 预期：
  1. 空理由被参数校验拒绝（@NotBlank，400）；
  2. 撤回成功，status=WITHDRAWN；
  3. 居民列表不再返回该公告，详情返回 404（撤回即下线）；
  4. 非发布态撤回被拒（5004，仅已发布的公告可撤回）。

### TC-C5-012 公告管理权限否定（居民/服务人员/游客）
- 关联：TR-C5-01　类型：权限　优先级：P0

- 数据：合法公告创建/发布/删除请求体各 1 组。

  3. 游客重复上述调用；
  4. resident1 调用 GET /api/v1/notices/{id}/viewers（查看记录属管理端）。
- 预期：
  1. 居民全部被拒（403，公告域仅 ADMIN/SUPER_ADMIN，权限矩阵 §1）；
  2. 服务人员全部被拒（403）；
  3. 游客全部被拒（401/403）；
  4. 居民查询查看记录被拒（403）；
  5. 全部拒绝均有留痕（越权 100% 拒绝并记录）。

### TC-C5-014 E5 全流程（发布→通知触达→查看回执→过期下线→归档）
- 关联：TR-C5-07　类型：功能　优先级：P1
- 前置：admin1、resident1 就绪；时钟可等待至公告过期（短有效期公告，
  endTime=当前 + 2 小时；加速口径见 TC-C5-08）。
- 数据：title=「停水通知」，定向社区 1，publishTime=立即，
  endTime=+2 小时；渠道勾选按 R51 口径（站内必达 + 模拟通道勾选，
  渠道否定场景归 TR-C11-04/C11 用例）。
- 步骤：
  1. admin1 创建公告（范围=社区 1 + 有效期）并发布；
  2. resident1 在线，检查通知列表（R48 公告广播事件）；
  3. resident1 打开公告详情（触发查看回执）；
  4. admin1 查询 viewers 已读统计；
  5. 等待过期 + 整点任务执行；
  6. resident1 再查列表；admin1 管理端查归档；
  7. admin1 撤回/删除该公告收尾。
- 预期：
  1. 创建 DRAFT → 发布 PUBLISHED，notice_target 正确；
  2. resident1 收到公告通知（可溯源：操作时间 + 来源事件公告广播）；
  3. 查看回执写入，viewCount +1；
  4. viewers 明细与统计一致；
  5. 任务执行后公告置 WITHDRAWN；
  6. 居民列表不再返回；管理端归档可查；
  7. 撤回/删除成功，全流程闭环无残留错误。

## 口径疑点（步骤 7 执行前需裁决/关注）

1. **楼栋级与多社区定向未实现**：R25 要求「勾选一个或多个社区及楼栋」，
   实现创建接口仅单 communityId、notice_target 仅写 COMMUNITY 类型
   （DDL 支持 BUILDING 但无入口）——需求-实现差异留待裁决；
   TR-C5-02 用例按已实现的社区级定向设计。
2. **置顶链路断裂**：notice 表无 priority 列、实体/VO 不含 priority、
   后端列表仅按 publishTime 倒序；前端 isPinned 判断依赖响应中的
   priority 字段——TC-C5-006 预期失败并记缺陷（TR-C5-03）。
3. **「未评价已完成工单先行提示」之外的关闭前提示**：见 C4 文件疑点；
   本文件无额外项。
4. **全系统广播对 ADMIN 的管理可见性**：page 接口 ADMIN 按绑定社区
   notice_target 过滤，广播（无目标记录）对 ADMIN 不可见——是否符合
   「社区管理员可见全系统广播」预期，以执行时与需求方核对口径。
