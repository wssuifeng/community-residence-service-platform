# 功能用例 · C10 用户与权限管理

> 依据：01_测试需求分析.md §3.10（TR-C10-01~07）、需求规格 R43~R47/R58 + E10/E10b、
> 接口设计 9.10 / 9.2.1（登录登出）。系统定义 v1.2 C10 判据。
> 编号规则：TC-C10-NNN；每条至少覆盖一个 TR；执行结果列由步骤 7 回填。
> 口径说明：TR-C10-02 权限矩阵**全组合否定用例专项（约 60+ 组合）**归
> 「非功能与专项用例」文件（TR-SP-02），本文件只设计 C10 域内代表性越权用例
> （认证 / 用户管理 / 日志 / 全局配置），不与之重复。
> 实现口径（以代码为准，与接口设计的差异已在用例内标注）：
> - 登录双端点：POST /api/v1/auth/admin/login（管理员+服务人员）、
>   POST /api/v1/auth/resident/login（居民）；JWT 有效期 2 小时（expiresIn=7200）；
> - 登出令牌黑名单：Redis + auth_token_blacklist 表双写，黑名单 TTL = 令牌剩余有效期；
> - 系统用户管理（/api/v1/sys-users）：创建/更新/列表/冻结/绑定/解绑为 SUPER_ADMIN，
>   按 id 查询与修改密码为 ADMIN+；「冻结即时吊销全部令牌」「绑定变更后重新登录生效」；
> - 居民账号管理（/api/v1/residents）：列表与冻结/解冻为 ADMIN+，数据级按绑定社区过滤；
> - 操作日志查询（GET /api/v1/operation-logs）：ADMIN+，ADMIN 限绑定社区内日志，
>   无更新/删除接口（仅追加在接口层即不可能）；
> - 服务人员账号：无独立 /staffs 接口，经 9.10.1 sys-users 体系由超管管理
>   （role=STAFF）——「社区管理员管服务人员账号」以当前实现口径设计为否定用例；
> - 日志清理：LogRetentionCleanTask 每日 03:00，阈值 sys_config `log.retention_days`
>   默认 730 天（非法值回退默认），分批删除（批 1000 条），实际清理后经通知中心
>   通知全部在役 SUPER_ADMIN，动作写 sys_task_log（含清理条数）；待删为 0 跳过且不通知。
> 种子账号（Flyway V6）：superadmin/Admin@123456（超管）、admin1/Admin123456
> （社区管理员，绑定种子社区「阳光花园」）、staff1/Staff123456（服务人员）、
> resident1/Resident123456（居民，已入住）。

### TC-C10-001 管理端登录-正确凭据签发 JWT（超管）
- 关联：TR-C10-01　类型：安全　优先级：P0
- 前置：后端已启动，Flyway 迁移完成，种子账号可用。
- 数据：用户名 superadmin / 密码 Admin@123456。
- 步骤：
  1. 调用 POST /api/v1/auth/admin/login，请求体 {username, password}。
  2. 检查响应 data.token（JWT 三段式）、data.expiresIn、data.user.role。
  3. 用该 token 调用 GET /api/v1/sys-users?page=1&size=10（超管接口）。
- 预期：
  1. code=200，返回 token 且为三段式 JWT，expiresIn=7200（有效期 2 小时）。
  2. data.user.role=SUPER_ADMIN。
  3. sys-users 接口 200，返回分页数据——令牌可用。

### TC-C10-002 双端点登录-错误凭据与未知账号拒绝
- 关联：TR-C10-01　类型：安全　优先级：P0
- 前置：后端已启动。
- 数据：① superadmin + 错误密码；② 不存在的用户名 nosuchuser + 任意密码；③ 居民端 resident1 + 错误密码。
- 步骤：
  1. POST /api/v1/auth/admin/login 提交 ①。
  2. POST /api/v1/auth/admin/login 提交 ②。
  3. POST /api/v1/auth/resident/login 提交 ③。
- 预期：
  1. 登录失败（非 200 业务码），不返回 token；错误提示不泄露「密码错误」与「账号不存在」的区别（统一凭据错误类提示，按实际实现断言，口径疑点见文末）。
  2. 同上。
  3. 居民端点同样拒绝，不返回 token。

### TC-C10-003 双端点交叉登录-账号走错端点被拒
- 关联：TR-C10-01　类型：安全　优先级：P0
- 前置：后端已启动。
- 数据：① admin1（社区管理员凭据）打 /auth/resident/login；② resident1（居民凭据）打 /auth/admin/login。
- 步骤：
  1. POST /api/v1/auth/resident/login 提交 admin1/Admin123456。
  2. POST /api/v1/auth/admin/login 提交 resident1/Resident123456。
- 预期：
  1. 拒绝登录（社区管理员非居民，居民端点不认）。
  2. 拒绝登录（居民非系统用户，管理端点不认）。两步均不签发任何角色的 JWT。

### TC-C10-004 冻结账号拒绝登录（管理员冻结即时吊销在用令牌）
- 关联：TR-C10-01　类型：安全　优先级：P0
- 前置：超管已登录（TC-C10-001 令牌）；创建一个临时系统用户（或用 05 数据集提供的临时管理员账号）并登录成功拿到令牌 T1。
- 数据：依赖：05 测试环境与数据 · 临时系统用户 tc10_frozen（ACTIVE，role=ADMIN）。
- 步骤：
  1. 超管调用 PATCH /api/v1/sys-users/{tc10_frozen_id}/status，body {status:"FROZEN", reason:"测试冻结"}。
  2. 用 T1 调用任一需登录接口（如 GET /api/v1/sys-users/{tc10_frozen_id}）。
  3. tc10_frozen 用原密码重新调用 POST /api/v1/auth/admin/login。
  4. 超管再次 PATCH 恢复 {status:"ACTIVE"}。
  5. 恢复后重新登录验证账号可用。
- 预期：
  1. 冻结成功，code=200。
  2. T1 立即失效（401/403），「冻结时吊销所有令牌」生效。
  3. 登录被拒（错误码 5201 口径，FROZEN 拒登）。
  4. 解冻成功。
  5. 登录成功、签发新令牌——处置只影响冻结期。

### TC-C10-005 登出后旧令牌立即失效（黑名单）
- 关联：TR-C10-01　类型：安全　优先级：P0
- 前置：admin1 已登录拿到令牌 T1。
- 数据：admin1/Admin123456。
- 步骤：
  1. 用 T1 调用 POST /api/v1/auth/admin/logout（Authorization: Bearer T1）。
  2. 再用 T1 调用任一需登录接口（如 GET /api/v1/operation-logs?page=1）。
  3. 查库 auth_token_blacklist：存在 T1 的 jti 记录。
  4. admin1 重新登录获得新令牌 T2 并访问同一接口。
- 预期：
  1. 登出成功，code=200。
  2. T1 访问被拒（401），登出后旧令牌立即失效，无时间窗口。
  3. 黑名单表有对应记录（Redis + DB 双写口径）。
  4. T2 正常访问——登出仅吊销当前令牌，不影响重新登录。

### TC-C10-006 过期令牌访问被拒
- 关联：TR-C10-01　类型：安全　优先级：P0
- 前置：已获取一个合法签发的 JWT（有效期 2 小时）。
- 数据：依赖：05 测试环境与数据 · 构造过期令牌——用 JWT_SECRET 对某测试账号签名
  exp 已过期的令牌（脚本生成），或短时调低有效期后等待过期（本用例优先脚本造数，不改服务配置）。
- 步骤：
  1. 携带过期令牌调用 GET /api/v1/operation-logs?page=1。
  2. 携带伪签名令牌（篡改 payload）调用同一接口。
  3. 不带 Authorization 头调用同一接口。
- 预期：
  1. 过期令牌被拒（401）。
  2. 伪签名令牌被拒（401）。
  3. 匿名访问被拒（401）——三步均不返回任何业务数据。

### TC-C10-007 越权代表性样本-居民/服务人员调用管理端登录与系统用户接口
- 关联：TR-C10-02　类型：权限　优先级：P0
- 前置：resident1、staff1 已各自登录；本用例是 C10 域内代表性越权样本
  （全组合矩阵见「非功能与专项用例」TR-SP-02，不重复）。
- 数据：resident1、staff1 令牌。
- 步骤：
  1. resident1 令牌调用 POST /api/v1/auth/admin/login（凭据正确）。
  2. resident1 令牌调用 GET /api/v1/sys-users?page=1。
  3. staff1 令牌调用 GET /api/v1/sys-users?page=1。
  4. staff1 令牌调用 GET /api/v1/operation-logs?page=1。
  5. 检查步骤 2~4 对应的越权记录是否写入操作日志（超管视角查询日志列表）。
- 预期：
  1. 403 拒绝（居民不可访问管理端登录端点）。
  2. 403 拒绝（系统用户列表仅 SUPER_ADMIN）。
  3. 403 拒绝。
  4. 403 拒绝（操作日志查询仅 ADMIN/SUPER_ADMIN）。
  5. 越权拒绝产生日志记录（R44「拒绝并记录」口径）。

### TC-C10-008 越权代表性样本-社区管理员调用全局级接口（管理员账号体系）
- 关联：TR-C10-02　类型：权限　优先级：P0
- 前置：admin1（社区管理员）已登录；本用例覆盖 §1 矩阵「全局配置/管理员账号与社区绑定」行的社区管理员否定格。
- 数据：admin1 令牌；目标用户 tc10_frozen（系统用户）。
- 步骤：
  1. admin1 调用 GET /api/v1/sys-users?page=1（管理员账号列表）。
  2. admin1 调用 POST /api/v1/sys-users（创建管理员账号）。
  3. admin1 调用 PATCH /api/v1/sys-users/{某超管id}/status（尝试冻结超管）。
  4. admin1 调用 POST /api/v1/sys-users/{某管理员id}/communities（尝试改绑定）。
  5. admin1 调用 GET /api/v1/configs（全局配置列表，仅超管）与 PUT /api/v1/configs/{key}。
  6. 超管查操作日志确认步骤 2~5 有拒绝记录。
- 预期：
  1. 403 拒绝（社区管理员不可见管理员账号体系，列表层即拒）。
  2. 403 拒绝。
  3. 403 拒绝（社区管理员无法处置管理员账号）。
  4. 403 拒绝（社区绑定分配仅超管——R44 全局级四类之一）。
  5. 两接口均 403 拒绝（全局配置仅超管，R46/TR-C2-02 口径）。
  6. 全部拒绝且有对应日志——「越权访问 100% 被拒绝并记录」。

### TC-C10-009 社区管理员越绑定社区查询返回空/拒绝（数据级授权）
- 关联：TR-C10-03　类型：权限　优先级：P0
- 前置：admin1 仅绑定种子社区「阳光花园」；环境中存在第二个社区及其居民
  （依赖 05 数据集；本用例不含则用超管造数）。
- 数据：依赖：05 测试环境与数据 · 第二社区「测试社区 B」+ 至少 1 名归属 B 的居民
  与 1 条 B 社区的操作日志。
- 步骤：
  1. admin1 调用 GET /api/v1/residents?page=1&size=50（居民列表，社区过滤由拦截器注入）。
  2. 对 B 社区居民直查 GET /api/v1/residents/{B社区居民id}。
  3. admin1 调用 GET /api/v1/operation-logs?page=1（绑定社区内日志口径）。
  4. 超管调用步骤 1~3 同款接口。
- 预期：
  1. 列表仅含阳光花园社区关联居民，不含 B 社区居民。
  2. 越范围直查被拒（403）或明确返回无权（按实现口径断言）。
  3. 日志列表不含 B 社区日志记录。
  4. 超管可见全量（含 B 社区数据）——两级数据授权对照成立。

### TC-C10-010 冻结/绑定变更对已发令牌的吊销时效
- 关联：TR-C10-03　类型：权限　优先级：P0
- 前置：超管登录；临时管理员账号 tc10_bind（role=ADMIN，已绑定社区 A 并登录获得令牌 T1）。
- 数据：依赖：05 测试环境与数据 · 第二社区 B 与 tc10_bind 账号。
- 步骤：
  1. 超管为 tc10_bind 绑定社区 B：POST /api/v1/sys-users/{id}/communities，body {communityId:B}。
  2. 用 T1 调用任一社区数据接口（如 GET /api/v1/residents?page=1）。
  3. tc10_bind 重新登录得 T2，再查步骤 2 同款接口。
  4. 超管解绑其社区 B：DELETE /api/v1/sys-users/{id}/communities/{B}，tc10_bind 用 T2 访问 B 社区数据。
- 预期：
  1. 绑定成功（仅 ADMIN 角色可绑定，重复绑定报 5002 口径属可选断言）。
  2. T1 已被吊销（401）——「绑定变更后吊销令牌，重新登录生效」。
  3. T2 正常访问，且可见范围随新绑定变化。
  4. T2 已失效或 B 社区数据不再可见——权限变更不残留旧授权。

### TC-C10-011 超管管理管理员账号-创建/启停/绑定/解绑全链路（E10b）
- 关联：TR-C10-04　类型：功能　优先级：P1
- 前置：超管已登录。
- 数据：新账号 tc10_admin2/Pass123456（role=ADMIN）。
- 步骤：
  1. POST /api/v1/sys-users 创建 tc10_admin2（按 9.10.1.3 请求体）。
  2. GET /api/v1/sys-users/{id} 查询，核对 role=ADMIN、status=ACTIVE、boundCommunities 空。
  3. POST /api/v1/sys-users/{id}/communities 绑定阳光花园社区。
  4. GET /api/v1/sys-users/{id}/communities 查绑定列表。
  5. PATCH /api/v1/sys-users/{id}/status 置 FROZEN，随后恢复 ACTIVE。
  6. DELETE /api/v1/sys-users/{id}/communities/{communityId} 解绑。
  7. tc10_admin2 登录后在阳光花园社区开展一项工作（如创建楼栋或发布公告）。
- 预期：
  1. 创建成功，密码 BCrypt 加密存储（库内抽样核对哈希非明文，N4 口径）。
  2. 字段一致，默认 ACTIVE。
  3. 绑定成功（重复绑定返回 5002 口径错误码）。
  4. 列表含阳光花园。
  5. 冻结/解冻均成功。
  6. 解绑成功。
  7. 绑定期内管理员可正常在本社区工作——E10b 组织搭建链路成立。

### TC-C10-012 账号唯一性与自冻结保护（用户管理边界）
- 关联：TR-C10-04　类型：异常　优先级：P1
- 前置：超管已登录；tc10_frozen 账号已存在。
- 数据：① 用户名与 tc10_frozen 相同的创建请求；② 超管冻结自己的请求。
- 步骤：
  1. POST /api/v1/sys-users 提交重复用户名 ①。
  2. 超管调用 PATCH /api/v1/sys-users/{superadmin_id}/status，body {status:"FROZEN"}。
  3. POST /api/v1/sys-users 提交 role=STAFF 的账号，随后尝试对其绑定社区。
- 预期：
  1. 创建被拒（用户名唯一性校验）。
  2. 被拒（错误码 5701 口径「不可自己冻结自己」），超管账号状态不变、令牌仍有效。
  3. STAFF 账号创建成功，但绑定社区被拒（错误码 5702 口径，仅 ADMIN 可绑定）。

### TC-C10-013 社区管理员管理本社区居民账号（启停）
- 关联：TR-C10-04　类型：功能　优先级：P1
- 前置：admin1 已登录；resident1（已入住阳光花园）令牌 R1 在手。
- 数据：resident1/Resident123456。
- 步骤：
  1. admin1 调用 GET /api/v1/residents?page=1 确认列表含 resident1。
  2. admin1 调用 PATCH /api/v1/residents/{resident1_id}/status，body {status:"FROZEN", reason:"测试冻结"}。
  3. 用 R1 调用居民接口（如 GET /api/v1/residents/profile）。
  4. resident1 用原密码重新登录。
  5. admin1 恢复 {status:"ACTIVE"}，resident1 重新登录。
- 预期：
  1. 列表可见 resident1（本社区居民）。
  2. 冻结成功。
  3. R1 立即失效（冻结吊销全部令牌）。
  4. 登录被拒（FROZEN 拒登，5201 口径）。
  5. 恢复后登录成功——「被冻结账号无法登录」与解冻恢复双向验证。

### TC-C10-014 社区管理员不可见管理员账号体系（否定）
- 关联：TR-C10-04　类型：权限　优先级：P1
- 前置：admin1 已登录；与 TC-C10-008 的差异：本例验证「不可见」的信息隔离而非写操作拒绝。
- 数据：超管账号 superadmin 的用户 id（V3 种子，id=1）。
- 步骤：
  1. admin1 调用 GET /api/v1/sys-users/1（直查超管详情）。
  2. admin1 在管理端「用户管理」界面导航（前端 admin/ 用户管理菜单按角色渲染）。
  3. admin1 调用 GET /api/v1/residents/1（本社区居民直查对照）。
- 预期：
  1. 403 拒绝（社区管理员不可见管理员账号体系，R46 判据）。
  2. 前端不出现「系统用户/管理员账号」菜单入口（按权限渲染）。
  3. 本社区居民直查正常（证明步骤 1 拒绝是账号体系隔离而非接口故障）。

### TC-C10-015 服务人员账号管理口径-社区管理员无权管理（否定，实现口径）

### TC-C10-016 修改密码-旧密校验/新密加密/令牌吊销
