# 功能用例 · C6 居民反馈管理

> 依据：01_测试需求分析.md §3.6（TR-C6-01~07）、需求规格 R28~R31 + E6、
> 接口设计 9.6（实现口径以后端 FeedbackController/FeedbackService 为准）。
> 编号规则：TC-C6-NNN；每条至少覆盖一个 TR；执行结果列由步骤 7 回填。
>
> 种子账号（Flyway V3/V6）：superadmin/Admin@123456（超管）、
> admin1/Admin123456（社区管理员，绑定社区 1）、resident1/Resident123456
> （居民，社区 1）、staff1/Staff123456（服务人员）。
> 反馈状态机（架构设计 §6.6）：PENDING 待受理 → IN_SESSION 会话中 →
> CLOSED 已办结（归档只读，终态）；管理员首条回复自动受理
> （PENDING → IN_SESSION）。
>
> **实现口径说明（40 阶段裁决，决策日志 2026-09-10，见文末口径疑点）**：
> - WebSocket 统一走 /ws 端点（SockJS + STOMP，CONNECT 帧认证），
>   订阅 /topic/feedback/{feedbackId}；接口设计 §9.6.3.3 的
>   /ws/feedback/{id} 端点与 /app SEND 通道为设计示例偏差，以实现为准；
> - 发消息统一走 HTTP POST /api/v1/feedbacks/{id}/messages 落库，
>   WS 纯推送（载荷 {type:"FEEDBACK_MESSAGE", data:{…}} 包裹）；
> - 订阅鉴权走 destination 级拦截器（FeedbackSubscriptionInterceptor）：
>   居民限提交人 / ADMIN 限绑定社区（实时查 sys_admin_community）/
>   SUPER_ADMIN 放行 / STAFF 与非参与者拒绝（Forbidden ERROR 帧）；
> - 双方均离线不推送、推送失败不回滚——前端轮询兜底即离线补拉语义
>   （WS 在线 5s→30s 对账、WS 不可用回退 5s 轮询）；
> - 反馈编号（接口设计的 FB+日期+序号）实现未落库——用例以「生成
>   反馈单、状态待受理」为断言口径。

### TC-C6-001 居民提交反馈（正常，含附图）
- 关联：TR-C6-01　类型：功能　优先级：P1
- 前置：resident1 已登录并已入住社区 1。
- 数据：title=「小区噪音扰民问题」，content=「最近夜间经常有噪音，影响
  休息」，category=投诉（COMPLAINT 口径），communityId=1；附图 1 张
  （jpg ≤5MB，经 POST /api/v1/feedbacks/{id}/attachments 上传）。
- 步骤：
  1. resident1 调用 POST /api/v1/feedbacks 提交反馈；
  2. resident1 对该反馈上传 1 张附图；
  3. resident1 调用 GET /api/v1/feedbacks/{id} 查看详情；
  4. admin1 查询反馈列表（status=PENDING 过滤）。
- 预期：
  1. 提交成功，生成反馈单（id 非空），status=PENDING（待受理），
     residentId 为 resident1（R28 验收）；
  2. 附图上传成功（仅提交人可传）；
  3. 详情返回分类/内容/附图/状态待受理，字段一致；
  4. 管理端列表可见该反馈（待受理），社区管理员收到新反馈通知
     （R48 反馈事件——实现通知口径见步骤 7 实测）。

### TC-C6-002 反馈提交参数校验与权限否定
- 关联：TR-C6-01　类型：异常　优先级：P1
- 前置：resident1、staff1、admin1 登录态；游客会话。
- 数据：A：title 为空；B：content 为空；C：category 非法枚举值；
  合法请求体（供 staff1/admin1/游客复用）。
- 步骤：
  1. resident1 依次用 A、B、C 调用 POST /api/v1/feedbacks；
  2. staff1 用合法请求体调用 POST /api/v1/feedbacks；
  3. admin1 调用 POST /api/v1/feedbacks；
  4. 游客调用 POST /api/v1/feedbacks。
- 预期：
  1. 三组均被参数校验拒绝（400），不生成反馈单；
  2. 服务人员提交被拒（403，接口仅 RESIDENT——权限矩阵 §1 反馈提交
     仅居民），不生成反馈单；
  3. 管理员提交被拒（403）；
  4. 游客被拒（401/403）；
  5. 全部拒绝有留痕（越权 100% 拒绝并记录）。

### TC-C6-003 管理员受理建会话（首条回复自动受理）
- 关联：TR-C6-02　类型：功能　优先级：P1
- 前置：admin1、resident1 就绪；存在 PENDING 反馈（TC-C6-001 产物），
  resident1 在线（可查通知）。
- 数据：管理员首条回复 content=「我们已经收到您的反馈，将尽快处理」。
- 步骤：
  1. admin1 调用 POST /api/v1/feedbacks/{id}/messages 发送首条回复；
  2. 查询反馈详情；
  3. resident1 查询通知列表与会话消息列表；
  4. admin1 再发一条消息。
- 预期：
  1. 发送成功，消息落库（senderType=ADMIN）；
  2. 反馈状态自动流转 PENDING→IN_SESSION（会话中），handlerId=admin1
     （R29 验收：受理后进入会话 + 实现口径：首条管理员回复自动受理）；
  3. resident1 收到「反馈有新回复」通知（R29 验收：居民收到通知）；
     会话消息列表含该条消息，时间升序完整；
  4. 第二条消息正常，状态保持 IN_SESSION。

### TC-C6-004 双端在线消息实时送达（≤3 秒计时）
- 关联：TR-C6-03　类型：性能　优先级：P0
- 前置：反馈处于 IN_SESSION；resident1 与 admin1 双端浏览器登录并打开
  该反馈详情页（均已通过 /ws 建立 WS 连接并订阅 /topic/feedback/{id}）。
- 数据：测试消息「噪音问题今晚仍在持续，请协助处理」；计时工具
  （性能面板/脚本时间戳）。
- 步骤：
  1. 双端打开会话页确认订阅就绪（WS connected）；
  2. resident1 发送测试消息（HTTP POST），记录发送时刻 T0；
  3. 观察 admin1 端消息渲染时刻 T1，计算 T1−T0；
  4. admin1 回复消息，反向重复计时；
  5. 双向各重复抽样 ≥10 次（01 §4 口径：会话通道抽样 ≥10 次）。
- 预期：
  1. 双端订阅成功，无 ERROR 帧；
  2. 消息经 HTTP 落库成功；
  3. admin1 端实时收到 FEEDBACK_MESSAGE 推送（{type, data} 包裹，
     data 含 senderId/senderType/content/createdAt），无需手动刷新；
  4. 反向同样实时送达；
  5. 全部样本 T1−T0 ≤ 3 秒（任一超时记缺陷；40 阶段冒烟实测 17ms，
     本阶段系统级复核）。

### TC-C6-005 会话记录完整可查与会话归属限定
- 关联：TR-C6-03　类型：功能　优先级：P0
- 前置：反馈 A（会话中，已有多条双向消息）；另建反馈 B（resident1
  另一话题，会话中）。
- 数据：无新增。
- 步骤：
  1. resident1 调用 GET /api/v1/feedbacks/{A id}/messages 查询会话 A；
  2. admin1 调用同接口；
  3. resident1 查询会话 B 消息列表；
  4. SQL 直查 feedback_message 表比对；
  5. resident1 在会话 A 页面向 B 发送含「B 话题」内容的消息
     （POST /feedbacks/{B id}/messages）。
- 预期：
  1. 会话 A 消息按时间升序完整返回，双向消息、发送人类型、内容、
     时间齐全，与界面渲染一致（R30 验收：会话记录完整可查）；
  2. 管理员视角同一会话记录一致；
  3. 会话 B 仅含 B 的消息，会话 A 的消息不出现在 B；
  4. 接口记录与库内明细 100% 一致（含条数）；
  5. 新消息只落入会话 B，不串单——会话归属限定「本反馈单」，
     新话题须另提反馈（R30 验收口径）。

### TC-C6-006 会话离线兜底（对方离线消息不丢）
- 关联：TR-C6-04　类型：异常　优先级：P0
- 前置：反馈处于 IN_SESSION；resident1 与 admin1 已建立会话。
- 数据：离线期间消息 3 条（居民 2 条 + 管理员 1 条）。
- 步骤：
  1. admin1 关闭浏览器/断开 WS 连接（模拟离线，确认 WS connected=false）；
  2. resident1 连续发送 2 条消息；
  3. admin1 回到在线前，resident1 再观察本地轮询（WS 在线 5s→30s
     对账口径）是否稳定；
  4. admin1 重新登录打开会话页（WS 重连 + 补拉）；
  5. admin1 在离线补拉后发送 1 条回复，resident1 经轮询（暂时断开
     resident1 的 WS）核对收到；
  6. 双方各自调用 GET /{id}/messages（可带 since 增量参数）核对全量。
- 预期：
  1. admin1 离线期间不接收推送（后端 isOnline 判定跳过推送，
     推送失败不回滚）；
  2. 消息全部落库成功，无丢失、无报错；
  3. resident1 本地会话不受对端离线影响；
  4. admin1 上线后经补拉/轮询完整看到离线期间的 2 条消息
     （R30 后半句：离线消息由补拉机制保证不丢，R50 联动）；
  5. resident1 断开 WS 后经 5s 轮询兜底收到管理员回复；
  6. 双端消息列表与库内记录一致，零丢失。

### TC-C6-007 反馈 WS 订阅鉴权矩阵（destination 级）
- 关联：TR-C6-05　类型：权限　优先级：P0
- 前置：反馈 A（resident1 提交，社区 1）；admin1（绑定社区 1）；
  依赖：05 测试环境与数据 · admin2（绑定社区 2）、resident2（非提交人
  居民）；STOMP 客户端工具（或浏览器多会话）。
- 数据：订阅 destination=/topic/feedback/{A id}；各角色有效 JWT。
- 步骤：
  1. resident1（提交人）经 /ws CONNECT 后订阅 /topic/feedback/{A id}；
  2. resident2（非提交人）订阅同一 destination；
  3. admin1（绑定社区 1）订阅；
  4. admin2（绑定社区 2，越社区）订阅；
  5. superadmin 订阅；
  6. staff1 订阅；
  7. 无令牌/伪令牌直接 CONNECT /ws；
  8. 检查后端越权订阅日志（log.warn 反馈会话订阅被拒）与操作留痕。
- 预期：
  1. 提交人订阅成功（SUBSCRIBE 帧无错误）；
  2. 非提交人居民订阅被拒（Forbidden ERROR 帧）；
  3. 绑定社区管理员订阅成功（sys_admin_community 实时查询放行）；
  4. 越社区管理员订阅被拒（Forbidden ERROR 帧）——绑定关系不缓存于
     JWT，实时校验；
  5. 超管订阅成功（放行）；
  6. STAFF 订阅被拒（非会话角色）；
  7. 无令牌/伪令牌 CONNECT 被拒（无法建立会话）；
  8. 全部拒绝场景均有日志留痕（越权 100% 拒绝并记录），
     被拒方均收不到后续 FEEDBACK_MESSAGE 推送（以 resident1 发消息
      验证 2/4/6 方无消息到达）。

### TC-C6-008 会话消息发送权限（居民限本人 + 管理员限绑定社区）

- 前置：反馈 A（resident1 提交，社区 1，会话中）；resident2、admin2
  （依赖：05 测试环境与数据 · 社区 2 管理员）、staff1 就绪。
- 数据：消息 content=「测试越权发送」。
- 步骤：
  1. resident2 调用 POST /api/v1/feedbacks/{A id}/messages；
  2. admin2 调用同接口；
  3. staff1 调用同接口；
  4. resident1、admin1 分别正常发送（对照组）。
- 预期：
  1. 非提交人居民发送被拒（403 无权在他人反馈下发消息），消息不落库；
  2. 越社区管理员发送被拒（403，checkCommunityAccess）；
  3. 服务人员发送被拒（403，接口仅 RESIDENT/ADMIN/SUPER_ADMIN）；
  4. 对照组双方发送成功；
  5. 全部越权拒绝有留痕。

### TC-C6-009 办结须填处理结论
- 关联：TR-C6-06　类型：功能　优先级：P1
- 前置：反馈处于 IN_SESSION；admin1、resident1 就绪。
- 数据：办结结论 reason=「已协调物业加强夜间巡查，问题解决」；
  空 reason 一组。
- 步骤：
  1. admin1 调用 PATCH /api/v1/feedbacks/{id}/close，reason 为空；
  2. admin1 带结论调用 close；
  3. 查询反馈详情与会话消息列表；
  4. resident1 查询通知列表。
- 预期：
  1. 空结论被参数校验拒绝（@NotBlank，400），状态不变
     （R31 验收：办结须填处理结论）；
  2. 办结成功，status=CLOSED，handlerId=admin1；
  3. 会话新增「[办结] 已协调物业……」系统消息落档（结论留痕，
     全程留痕口径）；
  4. resident1 收到「反馈已办结」通知。

### TC-C6-010 办结后归档只读（禁发消息 + 附件禁增删，BE-ISSUE-9 回归）
- 关联：TR-C6-06　类型：异常　优先级：P1
- 前置：反馈已办结（CLOSED）；resident1、admin1 就绪；反馈带历史附件。
- 数据：消息 content=「还有补充」；附件 1 张（jpg ≤5MB）。
- 步骤：
  1. resident1 调用 POST /api/v1/feedbacks/{id}/messages 发消息；
  2. admin1 调用同接口发消息；
  3. resident1 调用 POST /api/v1/feedbacks/{id}/attachments 上传附件；
  4. resident1 调用 DELETE /api/v1/feedback-attachments/{历史附件 id}
     删除附件；
  5. resident1 调用 GET /api/v1/feedbacks/{id}/messages 查看历史会话；
  6. SQL 直查历史消息与附件记录。
- 预期：
  1. 居民发消息被拒（5004 反馈已办结，不可继续会话）；
  2. 管理员发消息同样被拒（5004）；
  3. 办结后附件上传被拒（BE-ISSUE-9 回归口径：已办结禁增）；
  4. 办结后附件删除被拒（已办结禁删）；
  5. 历史会话记录仍可完整查看（归档可读）；
  6. 库内历史消息与附件记录零变动（记录不可修改，R31 验收）。

### TC-C6-011 反馈状态机非法流转
- 关联：TR-C6-06　类型：异常　优先级：P1
- 前置：准备 PENDING、IN_SESSION、CLOSED 三态反馈各 1 条。
- 数据：无新增。
- 步骤：
  1. admin1 对 PENDING 反馈直接调用 PATCH /{id}/close（未建会话先办结）；
  2. admin1 对 CLOSED 反馈再次调用 close；
  3. resident1 尝试调用 PATCH /{id}/close（居民办结权限）；
  4. resident1 对本人 PENDING 反馈发消息（未受理先发言）。
- 预期：
  1. PENDING 直接办结被拒（5004 状态流转非法——IN_SESSION 仅可流转
     CLOSED，未受理无会话不可办结）；
  2. 已办结再办结被拒（CLOSED 空可达集合）；
  3. 居民无办结权限被拒（403，办结仅 ADMIN/SUPER_ADMIN）；
  4. 居民在待受理反馈下发消息成功（居民侧不受受理限制，属实现口径），
     状态保持 PENDING（受理仅由管理员首条回复触发）——此格按实现口径
     记录，若需「受理前居民禁言」以需求方裁决为准。

### TC-C6-013 E6 全流程（提交→受理建会话→实时沟通→办结→归档只读）
- 关联：TR-C6-07　类型：功能　优先级：P1
- 前置：resident1、admin1 双端就绪（浏览器双会话）。
- 数据：反馈数据同 TC-C6-001；会话消息若干条；办结结论「已解决」。
- 步骤：
  1. resident1 提交反馈（分类/内容/附图）；
  2. admin1 受理（首条回复自动建会话），resident1 核对通知；
  3. 双方在会话页实时沟通 ≥3 轮（核对实时性与记录）；
  4. admin1 办结（填处理结论）；
  5. resident1 核对办结通知、会话归档只读（发消息被拒、附件禁增删）；
  6. 双方查看完整会话历史（含 [办结] 系统消息）。
- 预期：
  1. 反馈生成，状态待受理；
  2. 受理后会话建立（IN_SESSION），居民收到通知（R29）；
  3. 消息双端实时送达（≤3s 口径，抽 1 轮计时即可，全量计时归
     TC-C6-004），记录完整；
  4. 办结成功（CLOSED），结论落档；
  5. 归档后只读：发消息 5004 拒、附件增删拒（R31 验收）；
  6. 全程留痕：提交→受理→每条消息→办结均可查，时间线完整
     （E6 判据闭环）。
