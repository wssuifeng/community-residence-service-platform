# 租约默认日期与首期多月计费方案

> 本文只设计日期、支付月数和金额如何一致。原“默认今天、付款不改协议日期”方向已获采纳；新增约束待确认后实施。交易仍暂停，本轮不修改支付代码或现有租约。

## 1. 现状不是“只缺一个默认日期”

| 当前项 | 已核实的实现 | 本次需要解决的点 |
|---|---|---|
| 默认起租日 | 申请人工审核默认今天；自动审核今天起租，按社区默认期限（缺省12个月）生成止期；管理员直接新建为空 | 三个入口采用同一默认与校验 |
| 管理端月数 | `community.default_lease_months`表示整份租约期限，不是首期付款月数；人工审核/新建直接填起止日期 | 表单明确区分“租约期限”和“首期支付月数”，不能用一个“3个月”指代两者 |
| 首期费用 | `PaymentService.FIRST_PAYMENT_MONTHS = 1`，金额固定月租＋押金；首期请求只有渠道，没有首期月数 | 当前确实不能表达管理员约定首期付3个月，并非只改前端合计即可 |
| 费用明细 | 首期覆盖范围固定1个月，租金/押金用当前租约价格反推 | 生成不可变金额与覆盖期快照，不能编辑月租后让旧单拆分变化 |
| 后续付款 | 当前RENEWAL成功会延长整份租约止期，没有区分“原租期内交下一期租金”和“延长租期” | 两者必须分开；不能付下一期3个月就把原12个月合同偷偷变成15个月 |

代码依据：`ResidenceApplicationListView.openApprove`、`LeaseListView.openCreate`、`ResidenceApplicationService.autoApprove`、`LeaseRecord`、`CreateFirstPaymentDTO`、`PaymentService.createFirstPayment/fillAmountBreakdown/depositPartOf/confirm`及`DepositRefundService`。这里只读核对，未调用交易接口。

## 2. 推荐约束：可提前30天约定起租，但月租不换算成固定30天

“今天往后顺延30天”有两种不同含义，不能混用：

| 口径 | 效果 | 推荐 |
|---|---|---|
| **起租日选择窗口为今天～今天＋30天** | 默认今天，可选未来30天内的计划起租日；发协议前重新校验，避免回溯起租或长期占用 | **推荐作为本次日期约束，仍待确认** |
| 一个收费月固定30天 | 首期3个月实际覆盖90天；与目前按日历月顺延不同，2月/31天月份的止期会改变 | 本次不采用；若你确指固定30天计费，必须整套切换，不能只改默认日期 |

推荐的日期规则：

1. 业务日期按Asia/Shanghai计算，不用浏览器UTC截取“今天”。管理员新建、人工审核、自动审核均默认今天。
2. **新租约发出协议时，今天≤计划起租日≤今天＋30天**，两端点均可选；已保存草稿跨日后重新校验。自动审核仍从今天开始。此窗口只限制计划起租日，不代表付款期限或自动取消期限。
3. 月租仍按**以起租日为基准的日历月周期**计价，不是每个收费月固定30天，也不是一律每月1号收租。合同期限以正整数月输入，系统推导止期；不同时开放可相互矛盾的任意止期和总月数。
4. 新规则以边界`B(k)=起租日.plusMonths(k)`计算；第k个收费月为`[B(k-1), B(k))`，界面显示“起日～B(k)前一天（含）”。合同最后可居住日为`B(总月数)-1天`。月份不足原日期时取月末；每次从原起租日计算，不能反复在上次截断日期上加月造成漂移。
5. 例如2026-10-15起租：1个月至2026-11-14（含），3个月至2027-01-14（含），12个月至2027-10-14（含）。今天＋30天是2026-11-14，和“1个月的下一边界2026-11-15”不是同一概念。
6. 现有代码`endDate=startDate.plusMonths(n)`且止期当天仍算有效，存在边界差异；**上述是待采纳的新日期契约，不伪装成已有算法**。实施时统一新建/审核/协议/详情/续期/到期任务口径。历史已发协议、已生效日期不批量减一天，保留旧口径标识或快照读取。
7. 协议同意后不因付款自动改日期。跨过计划起租日仍未付首期，推荐停止新建/继续支付入口，提示管理方撤回旧协议、调整日期并重新发出；不得静默收整期却回溯起租。旧支付单先关闭并确认不可再付，已实际扣款的迟到通知进入异常核对，不自动丢弃或二次收费。该新门禁也须随本方案确认，不能当成已上线。
8. 允许未来起租并提前付款时，首期成功仍按已批准规则使合同生效/建立正式关系，但界面区分“合同已生效、尚未到约定入住日”；实际入住标签和在住服务权限不能因这次新增未来日期选择而提前开放。实施须核查关系有效期读取，不擅改当前账号或历史关系。

## 3. 首期多月金额：总期限、首付月数和押金分别表达

| 字段 | 规则 |
|---|---|
| 月租金`monthlyRent` | 管理员填写，人民币元，非负、最多两位小数；沿当前正额支付门禁，不新增0元支付特例 |
| 租约总月数`leaseMonths`（拟增） | 正整数，定义整份合同覆盖时间，默认取社区配置；不是付款月数 |
| 首期支付月数`firstPaymentMonths`（拟增） | 默认1，正整数且≤租约总月数；管理员可设3。居民支付时不改月数或传金额 |
| 押金`deposit` | 独立填写的固定金额，非负、最多两位小数；不因首付月数增加自动翻倍 |

**服务端唯一计算公式：**

```text
首期租金 = 月租金 × 首期支付月数
首期应付 = 首期租金 + 押金
首期覆盖 = [B(0), B(首期支付月数))
合同租金总额 = 月租金 × 租约总月数（不含押金，不代表已收）
剩余未缴租金 = 合同租金总额 - 已成功支付且归属该合同期的租金
```

金额使用BigDecimal/DECIMAL、元两位；不先按月租÷30生成日价，也不接受前端浮点合计作为收款依据。续接未付款单时显示该单的不可变快照，不用当前租约字段重算。

**同一例子：月租3000元，押金3000元，2026-10-15起租，合同12个月。**

| 首期月数 | 首期租金 | 押金 | 首期应付 | 已缴覆盖（成功后） | 合同期内剩余租金 |
|---|---:|---:|---:|---|---:|
| 1 | 3000 | 3000 | **6000** | 10-15～11-14 | 33000 |
| 3 | 9000 | 3000 | **12000** | 10-15～2027-01-14 | 27000 |
| 12 | 36000 | 3000 | **39000** | 10-15～2027-10-14 | 0 |

若合同本身仅3个月且首期付3个月，应付仍为12000元，合同租金已缴清；并非“合同3个月但固定只收1个月”。首期支付成功只激活并记录已缴覆盖，**不延长原合同期限**。

## 4. 管理端与居民端看同一份明细

管理端新建/审核按顺序展示：**计划起租日 → 租约总月数 → 自动止期 → 月租金 → 首期支付月数 → 押金 → 合计与覆盖期预览**。首期月数超过合同总月数立即提示，后端同样拒绝，不自动截断。

发协议前展示确认卡：

```text
合同：2026-10-15～2027-10-14（12个月）
月租：¥3000.00；首期：3个月
首期租金：¥9000.00；押金：¥3000.00；应付：¥12000.00
首期覆盖：2026-10-15～2027-01-14；后续租金：¥27000.00
付款成功后正式生效；付款不改写以上日期。
```

协议正文快照、居民确认页、支付预览、历史明细都展示这份数据；不得仍写“首月租金”或“租约状态不变”。居民改用另一渠道不改变金额。首期月数/价格/日期变更须撤回旧协议并重新确认，已有未付单先关闭；已成功单据不可改。

## 5. 计费快照及后续付款必须一起对齐

- 支付单拟固化：支付目的、协议版本、月租单价、支付月数、租金金额、押金金额、总额、覆盖开始/结束边界。覆盖边界保存为右端不含的明确字段，界面再减一天；不拿今天或当前租约止期反推历史。
- `FIRST`首次费用、拟增`RENT`原合同期内后续租金、`RENEWAL`延长合同的续约费用分开。后续租金只推进本合同已缴覆盖，不延长合同；续约才改变合同止期。可复用现有支付单和渠道适配，不新建资金池/余额。
- 当前合同内付款不能跨出原合同期限；最后一期按剩余完整月数收费并明示，不静默超收。待付款单不提前算已缴。重复请求/回调只记一次，同租约覆盖期禁止重叠。
- 押金退还必须取成功首期单中**已固化的押金金额**。当前“首期总额－当前月租”反推若用于3个月首期，会把其中2个月租金误当押金，必须同时替换；不能只乘一个月数就上线。
- 本方案只支持完整月周期，不加入零散天数补差、提前退租租金退还或价格分段。需要这些能力时再单独明确规则，不用除以30猜金额。

## 6. 落地范围与确认点

**推荐采用：未来30天起租窗口＋日历月计价＋总期限/首期月数分开＋不可变费用快照；付款不重写已确认日期。**这四项是一套，不能只改默认日期或按钮合计。

实施顺序：①统一纯日期/金额规则与离线测试；②新建/审核表单、协议快照与明细；③支付单快照及首期/原期内缴租/续约/退款拆分离线回归；④获准后才恢复真实沙箱验证。**本轮仍只优化方案，不调用支付、退款、查单，不修改历史日期或财务记录。**

确认后应覆盖：1/3/12个月金额、首期月数越界、未来30天端点/第31天、跨月与闰年、月末锚点不漂移、协议跨日、已付日期不回写、改价后旧单不变、押金不误含多月租金、重复支付不重复覆盖及原合同内付款不延长止期。
