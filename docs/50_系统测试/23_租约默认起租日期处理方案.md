# 租约期限、首期付款与续租治理方案

> 用户于2026-10-15明确采纳本版租约治理方案。本文规定合同期限、首期、后续交租与续租的处理规则；本轮用户授权实施并同步20/30，源码与离线基础测试已落地；不代表正常环境已升级或真实交易通过，历史日期/费用不批量回填。

## 1. 先分清五个量

| 项目 | 管什么 | 默认/设置方式 |
|---|---|---|
| **合同总期限** | 管理方与居民约定可以租多久，决定合同起止日 | 管理员新建/审核设置；默认取社区总月数，当前缺省12个月，允许调整，不强制所有合同一年 |
| **计划起租日** | 同一份合同的时间起点 | 默认今天，发协议前可改；付款不把起租日改成付款日 |
| **首期支付月数** | 第一次收多少个月租金，不是另一个租期 | 默认1，可约定3等正整数，不超过总期限 |
| **后续缴租周期** | 首期之后每次按多少个月收租，不延长合同 | 默认每1个月；若约定季付则3个月。可表达“首期付3个月，此后月付”，不能从首付月数猜以后也季付 |
| **已缴租金覆盖** | 实际支付成功的租金对应哪些日期 | 由成功单据的覆盖期累计；未付单不算已缴，也不决定合同有效期 |

**“首期起租”不是第二个起租时间。**只有合同起租日；首期支付月数决定从该日起先缴到哪里。合同12个月、首期付3个月，表示约定租一年、先支付前三个月，不能解释为只租3个月。

表单顺序：起租日 → 合同总月数/自动止期 → 月租 → 首期支付月数 → 后续缴租周期 → 押金 → 首期金额与覆盖期预览。发出的协议必须包含这些明确约定；居民同意后不可后台静默改写。

## 2. 一个贯穿全流程的例子

设：2026-10-15起租，合同12个月，月租3000元，押金3000元；**首期付3个月，以后月付**。以下日期采用已采纳的“起租日对齐日历月”口径，结束日含当天。

| 动作 | 收取/覆盖 | 合同止期是否变化 |
|---|---|---|
| 初次发出并同意协议 | 约定2026-10-15～2027-10-14 | 初次确定止期；未付首期仍不正式生效 |
| 首期付款成功 | 3×3000＋3000＝**12000元**；租金覆盖2026-10-15～2027-01-14 | **不变**；按既有规则使租约及正式租客关系生效 |
| 2027-01-15交下一月租金 | **3000元**，覆盖01-15～02-14，不重复收押金 | **不变**，仍到2027-10-14 |
| 此后按月交租 | 逐期支付原12个月内尚未缴纳的月份 | **不变**；即使全额预交原12个月，也不自动多租一天 |
| 双方约定再续租6个月，并满足续租生效条件 | 新增2027-10-15～2028-04-14这一段，新增租金按该段单价计算 | **延长为2028-04-14**；原合同记录仍是原来的12个月 |

初次总期限12个月＋后来续租6个月＝当前累计覆盖18个月。不是重新从续租操作日再算18个月，也不覆盖原来约定的日期和价格历史。

## 3. 普通交租与续租的区别

| 对比 | **原合同期内后续租金** | **续租** |
|---|---|---|
| 目的 | 支付已经约定、尚未支付的租金 | 双方约定增加原合同之外的居住时间 |
| 是否改合同止期 | **不改** | **延长** |
| 月数来自哪里 | 协议约定的后续缴租周期；尾期不足一周期按剩余完整月数 | 管理方提出并由居民同意的新增月数，不能由付款界面单方决定 |
| 是否每次签新协议 | 按原已确认协议交租，不重复确认同一内容 | 需要新的续租确认/协议版本，写明新增日期、租金与付款安排 |
| 付款怎么算 | 本次月租×本次覆盖月数 | 新增合同段的月租×本次实际支付月数，不要求一次付清全部新增期限 |
| 押金 | 不再收 | 沿用已经实缴的押金，不默认重复收；若另议调整需明确差额规则，不能偷偷按月数放大 |

**续租6个月，不等于必须一次付6个月租金。**可约定新增6个月、先付1个月，其后月付；也可约定新增6个月、首次付3个月。新增合同总月数与新增段首次付款月数仍须分开。

## 4. 谁能延长、什么时候延长

续租采用“管理方发出代表同意、居民确认具体协议、新增段首笔费用成功才生效”的规则：

1. 居民提出续租意愿，或管理方直接拟定续租方案；**提出意愿不延长合同**。
2. 管理方发出续租协议，列出新增月数/起止、单价、该段首次支付月数及后续周期；发出代表管理方同意，居民确认；**只确认、未付款仍不延长当前已生效止期**。
3. 新增段的首次租金支付成功后，原子记录成功单与新增合同段，才更新当前有效止期；重复通知只能应用一次。既有合同在过程中继续按原起止、价格和应付事项执行。
4. 新增段剩余租金仍是“交租”，**不得每次缴租再延长一次**。续租取消/失败只结束未生效的新增方案，不取消原合同、不删除原居住关系。

例如续租6个月且新增段首次付1个月：先付该段3000元，生效后当前止期延至2028-04-14，已缴新增段仅覆盖2027-10-15～11-14，后面5个月仍需按月交租。合同新增6个月和已付1个月分别显示。

未到期的连续续租从原止期次日开始，不从办理当天开始。已过期时不按“今天＋月数”自动略过中间空档；须核对实际居住和日期后明确处理，发生断档的重新入住按新租约办理，不悄悄回填/免除空档租金。

## 5. 如何防止租期与费用再次混乱

- **合同范围、已缴覆盖、应付时间独立显示。**前三个月租金用完只是下一期该交租，不是合同到期。欠租只标应付/逾期及通知，不自动结束合同或释放房屋；合同到期也不等于自动退租/归档，继续走既有退租处理。欠租进一步处置不在本方案擅自新增。
- 首次合同、每次续租保留各自日期/单价/付款安排及确认版本。续租涨价只作用新增段，不能把原合同未结束的月份和已付账单改价。
- 每笔费用保存服务端计算的单价、月数、租金、押金、覆盖起止与协议引用。首期＝月租×首期月数＋押金；后续＝对应合同段单价×该次月数。不能用“总额减当前单月租金”反推押金，防止把多月租金算成押金。
- 同一覆盖区间不得重复收租，原合同期内单据不能跨出该合同段；尾期剩1个月就收1个月，不因季付配置强收3个月。新的到期缴款在覆盖开始日应付，允许提前支付；既有到期未缴项先处理，不用续租掩盖。
- 提前付续租费用时，旧段可能还有未到期应付月份；**按合同段及真实区间展示已缴情况，不能仅取最大的支付结束日，假装中间所有月份都已缴清**。
- 第一笔付款可在计划起租前成功，仍按既定规则使合同生效/建立关系；页面区分“合同已生效、未到约定入住日”，在住标签及在住服务权限须校验计划日期。用户2026-10-15补充：计划起租日严格早于今天且首期仍未付，系统自动驳回对应申请、撤销未生效租约并释放占用；起租日当天仍可付，不静默回溯。
- 计价按起租日对齐的日历月：边界`B(k)=原起租日.plusMonths(k)`，覆盖`[B(k-1),B(k))`，界面结束日减一天；每次从原锚点推算，避免月末漂移。**本轮已在新合同与订单覆盖中统一此规则。**历史协议不批量改一天。
- “起租日可选未来30天”和“每月固定30天收费”是另外两种约束，不能决定上述合同/缴租/续租区别。本版不设置未来30天选窗，也不采用每月固定30天收费；计费统一使用上述日历月口径。

## 6. 本轮落地范围
| 功能 | 本轮实现 |
|---|---|
| 新约默认值 | 起租默认今天；总月数取社区配置，首付/周期分别默认1；按原锚点计算含止日 |
| 首期费用 | 单价×首付月数+一次押金，金额/区间/约定合同段保存快照，不按当前月租反推旧账 |
| 普通交租 | RENT按最早未缴合同段和约定周期收费，尾期只收余月，不延长合同 |
| 续租 | 管理方发出新增段，居民同意，新增段首笔成功才延长；旧价格保留，押金不重复收；原段已到期租金先缴 |
| 历史 | 日期/支付快照不猜测回填；无新约定时编辑保留原日期/未知字段，明确补录后才能形成新付款安排 |

| 提前付款 | 首期成功使租约/正式关系生效，房屋先预留；到起租日且关系有效再标已入住 |

## 8. 过日起租、订单关闭与迟到成功
- 起租日当天未付仍允许发起；下一天00:05起由5分钟任务锁定重查。无成功/异常记录、无尚在本地有效期的首期单时，驳回该租约精确关联申请，关闭未生效协议/群聊并释放占用。任务重复执行不得重复副作用。
- 渠道可支付24小时，首期不越过起租日次日00:00；本地截止=渠道截止+5分钟，缓冲期不再生成新支付入口，未到本地截止不得仅因关闭弹窗提前关单。离首期截止不足1分钟不再新建订单，避免渠道最小时长越过业务截止。
- 本地已关单、申请已驳回、合同段取消、缺历史约定或渠道付款时间晚于截止时，可信成功保存流水/时间/异常。不得自动复活租约、重复扣款或自动退款；记录不丢失，渠道恢复后由专门核对处置。正常处理中失败不伪造SUCCESS。
- 不凭上述时间参数宣称渠道已经接受24小时或沙箱已恢复；当前仅SDK构建与mock测试，真实渠道验证后续单列。

月末补充：人工/自动审核把原总月数、首付与周期直接传给共用审批内核，不按截短后的日期反算月份。例如2027-01-31起13个月的合同止期2028-02-28，首付仍可为3个月；回归验证保留这两个独立约定，不能因ChronoUnit的整月算法截成12个月。
