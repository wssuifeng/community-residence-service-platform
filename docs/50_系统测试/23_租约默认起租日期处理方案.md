# 租约默认起租日期处理方案（待确认）

## 当前实际上有三个入口

| 入口 | 现状 |
|---|---|
| 入住申请人工审核 | 前端已默认起租日为今天，并提供日期选择；后端要求明确起止日期 |
| 社区自动审核 | 后端默认今天为起租日，按社区default_lease_months生成止期 |
| 管理员直接新建租约 | 当前起租输入为空，必须手填；这才是默认值不一致的入口 |

依据：ResidenceApplicationListView.openApprove、ResidenceApplicationService自动审核、管理端LeaseListView.openCreate。不能笼统说整个系统都没有默认起租时间。

## 推荐：计划起租日与正式生效时点分开

1. 管理员新建/审核时，**起租日默认今天，允许调整为双方沟通确定的计划入住日**；明确标注“计划起租日，并非付款成功时间”。不新增居民申请表必填项。
2. 自动审核仍采用今天与社区默认期限；人工表单显示完整起止日期、期限和金额，发协议前确认。结束日期沿用现有规则，不在这一轮暗改计费或到期算法。
3. 发出的协议保存上述日期快照。居民同意这一份具体快照，不能一边同意、一边由后台偷偷改起租日。
4. **首期支付成功才使租约与正式租客关系生效**，沿用已批准规则；但支付成功不自动把协议中的起租日改成支付日。
5. 若等待付款导致原计划不合适，由管理员与居民在群聊沟通，走已有撤回/修改/重新发出协议流程；不在定时任务中改日期，不重置历史已生效租约。
6. 已过止期的未生效租约继续按已有门禁拒绝首期支付；本次不运行交易或主动查单。

## 为什么不推荐“支付当天自动起租”

它虽然少填一个日期，但会把协议确认后的租期静默改写，居民看到的正文和实际租期可能不一致。若以后确实要采用付款后起算，必须另行设计协议中的明确相对日期条款与到期计算，不能只改一个默认值。

**需要确认：管理员新建租约也默认今天、可在发协议前调整；付款不自动重写日期。确认后仅修默认值与提示，不修改现有租约数据。**
