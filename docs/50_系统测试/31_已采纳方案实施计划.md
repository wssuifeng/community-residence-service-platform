# 已采纳方案实施计划

依据：2026-10-15用户采纳27～30及单套入口/页面刷新反馈。执行状态只在中控ca维护。

目标：在不重复收款、不清理测试数据、不关闭用户浏览器的条件下，分功能交付可回归版本。
架构：沿用既有业务模块、房屋图片单张API、周循环模板和合同段历史；新增深层能力分别封装，界面共享数据来源。
技术栈：现有Vue/TS/Vitest、Spring Boot/MyBatis/MySQL；编辑器选官方最小扩展并锁版本。

## 独立交付顺序与验证

1. **多图相册**：修改HouseImageDialog.vue及其spec，新增队列行为测试（多张/部分失败重试/容量/脏编辑/锁定房屋），先观察失败，再实现逐张串行上传及防丢编辑。测试通过后单独提交。
2. **多星期模板**：ResourceTimeslotService/Controller、批量DTO、PublicResourceListView及api/community，新增锁内全批预检、精确重复跳过及部分重叠零写入测试；后端定向测试、前端类型/build；独立提交。
3. **单套配置与列表刷新**：先查真实单套创建/挂牌表单和批量表单差异；对齐字段/后端校验。围绕notification/todo store、Hub及列表封装可见刷新；测试首次进入、Tab重入、通知、筛选保留、并发旧响应不覆盖。独立提交。
4. **租期与缴租**：先决策日志与系统定义整份重写，再同步需求/30合同段及接口；延长申请新表/实体/受权服务/端点和审批记录，审批锁内只更新期限一次；缴租报价按原锚点连续覆盖所有已确认合同段、按段价合计，月数从1至真实余月，PENDING不强关。后端边界单测+隔离数据库API；前端统一入口，独立提交。
5. **公告编辑页**：Notice结构化正文/修订/阅读版本、服务端白名单与乐观锁；共用只读渲染与正文主编辑页，不提供任意HTML/外图；支持加粗/对齐/列表/插图/宽度。发布后修订不下线、不重发原通知，旧正文兼容。安全、版本、三端组件测试；独立提交。
6. **支付诊断与交付核查**：只读实际订单脱敏字段、本地SDK参数及离线表单耗时；区分API生成、Blob跳转和渠道加载，不调用查单/退款或真实下单探针；无法证明根因则明确保留DEF-205。全量单测/类型/build，独立headless隔离验证；据真实结果回写07/08/中控和定向手册。
