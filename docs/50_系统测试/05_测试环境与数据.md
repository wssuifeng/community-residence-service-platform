### 3.2 数据准备脚本（脚本位置与用法；SQL 直插与接口造数的边界）

脚本位置：`docs/50_系统测试/scripts/`（用途/执行顺序/行数验证详见该目录
README.md）。摘要：

| 脚本 | 内容要点 |
|------|---------|
| `00_create_test_db.sql` | 建测试库（utf8mb4）；只建库不建表，V1~V8 由后端 Flyway 执行 |
| `01_seed_extension.sql` | D1~D5（见 §3.1 清单）；全部幂等（INSERT…WHERE NOT EXISTS，参照 V6 写法）；密码哈希直接复用 V6/V3 已验证 BCrypt 哈希（明文注于脚本头） |
| `02_bulk_data.sql` | D6（N7 批量）；存储过程 + 递归 CTE 集合式生成，分批显式 COMMIT（房屋 1000/批、工单 2000/批，避免单事务过大）；耗时预估 1~3 分钟；标记幂等（存在即整体跳过） |
| `03_cleanup.sql` | 统一清理，口径 A（DROP DATABASE 重建，推荐）/ 口径 B（TRUNCATE 业务表，种子不自动恢复的代价已注明）二选一 |

**SQL 直插与接口造数的边界**（Q5：SQL 直插 + 部分走接口）：
- SQL 直插：基座结构（社区/楼栋/单元/房屋/资源/时段）、账号池、历史存量
  （N7 批量工单/租约/通知）、判定类静态锚点（止期三档、过期公告、冻结账号）；
- 接口创建：一切需要状态机流转、通知触发、WS 推送、日志留痕的业务过程数据
  （工单流转各态、申请审核、预约冲突、反馈会话、评价跟进）——保证被测链路
  真实走通，不留「库里有、链路没跑过」的假数据。

**关键操作约束**：
- `02` 执行后必须同步 Redis 通知序号 `SET notification:seq <库内 MAX(seq)>`，
  否则后端 INCR 生成的 seq 与直插值撞 notification.uk_seq 唯一键（脚本头与
  README 均已注明）；
- 01/02 只能对 `community_residence_test` 执行；对开发库的任何写操作为
  **违规事件**，发现即中止并登记。

### 3.3 数据清理与恢复策略（轮次间重置 or 累加，Q5 裁决）

- **轮次间：累加，不重置**（Q5 裁决）。第一轮功能/专项产生的业务数据保留至
  第二轮，回归用例优先复用同批数据锚点（缺陷复现路径连续可查）；个别用例
  要求「干净起点」时，仅做**局部**清理（该用例自建的数据自删，脚本级支持为
  03 的口径 B TRUNCATE——正常轮次禁用）；
- **收尾：统一清理**（步骤 11/12 执行 03）。推荐口径 A：DROP
  community_residence_test 后保留空库或整库移除（归档时按 10_测试总结与归档
  的资产清单决定是否保留脚本可再生）；归档要求「测试可复现」由脚本体系保证
  （00→Flyway→01→02 全流程可重放）；
- **日志留存验证的恢复**（强制检查项）：TR-C10-07 阈值调低验证后**必须恢复
  sys_config log.retention_days = 730**（用例内置检查项 + 出口准则第 6 条）；
- **Redis 数据**：与开发环境共用实例与 DB 0，不单独清理（通知 seq / 缓存 /
  锁均为易失数据，后端重启或 TTL 自然过期；重建测试库后按 §3.2 同步 seq）。

## 4. 敏感数据处理（测试数据脱敏口径——本系统为教学数据，注明无真实个人信息）

- 全部测试数据为**教学演示性质**（虚构姓名/手机号/地址/证件号）：手机号采用
  138-0000/1000 段虚构号段，姓名为「测试××/压测居民NNN/批量××」，社区与
  地址均为虚构，**无任何真实个人信息、真实联系方式与真实证件号**；
- 密码口径：所有测试账号密码为公开已知的演示明文（Admin@123456 /
  Admin123456 / Staff123456 / Resident123456），库内仅存 BCrypt 哈希（复用
  V6/V3 迁移中已验证哈希，TR-NF-04 抽样核对用）；
- JWT 密钥：dev 默认密钥仅限本机（application.yml 口径），测试环境沿用，
  不涉及真实生产凭据；数据库/Redis 均为本机无外部访问实例；
- 上传附件（SP-05）使用本地生成/项目内测试图片与文档，`./uploads` 目录
  随测试库一同在收尾清理；
- 结论：本阶段不涉及脱敏转换操作，数据集本身即非敏感。
