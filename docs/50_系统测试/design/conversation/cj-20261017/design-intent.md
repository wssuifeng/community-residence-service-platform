本轮采用用户给定的QQ三段结构，不重新讨论社交软件功能。唯一功能说明见[32](../../../32_三端会话界面优化讨论稿.md)。以下为设计稿，不是已上线功能。

- [三端可切换精确稿](design-draft.html)：顶部“管理端 / 居民端 / 服务人员端”切换；右上可选业务菜单、匿名反馈、只读、空、失败、断线及翻阅历史状态。
- 管理端：[1920×1080](screens/admin-1920.png) / [1440×900](screens/admin-1440.png)。保留原232px深色后台侧栏；右侧是独立三段式会话子页。
- 居民端：[1920×1080](screens/resident-1920.png) / [1440×900](screens/resident-1440.png)。仅保留原顶部导航，不复制管理侧栏。
- 服务人员端：[1920×1080](screens/staff-1920.png) / [1440×900](screens/staff-1440.png)。同一工作区，仅显示本人原有权限的工单、带看会话。

## 布局与视觉基准

| 区域 | 确定性设计 |
|---|---|
| 顶部与外层 | 顶部64px；管理侧栏232px沿用现有Token，1279px以下示意收为72px图标栏。该收缩只为设计预览，工程实施仍须对齐项目现有平板抽屉规则，不擅改全站导航 |
| 工作区 | 最左业务列76px，中间列表310px（宽屏334px、居民独立页330px），右侧占剩余宽度；分栏以细分隔线呈现，不做嵌套大卡片 |
| 小窗口 | 999px及以下保留业务列，列表/聊天切换，有明确返回按钮，不强行把三段挤窄；当前只覆盖768px以上桌面/平板，不新增移动端定位 |
| 消息与输入 | 标题及业务状态固定顶部；消息独立滚动；底部工具行＋多行输入＋发送，工具不挤在标题区。成员按需抽屉，不常驻第四栏 |
| 视觉 | 主蓝#3b6dff，后台深蓝#10233f，冷浅灰画布，白色列表与输入；中文系统字体。列表标题13px，正文消息14px，辅助信息分层，不用装饰性大图、渐变或额外统计卡片 |

## 与真实工程的对应

- 业务列是“全部、租约、看房、工单、反馈、直通”，不是复制QQ的联系人关系、空间、文件云盘或电话。
- 全来源列表只聚合当前账号原权限可见的沟通；复用共用消息列表/输入框/图片能力。四类多方会话与反馈继续按各自业务和权限读写，不要求为画面统一而强制迁表。
- 活跃由最近有效消息决定，不由打开次数/已读驱动；搜索全量和反馈已读等缺口见32。设计预览仅对合成数组筛选，绝不冒充真实服务端搜索实现。
- 三端业务动作不同：[管理端协议菜单](screens/admin-business-menu-1440.png)、[居民端看房/协议菜单](screens/resident-business-menu-1440.png)。员工不出现签约/审批；协议不新增重复承租确认。
- [匿名反馈](screens/admin-feedback-1440.png)在列表/摘要/头像/成员和检索中保持匿名。待受理事项不因查看变成已受理；本轮未修改真实状态机。

## 视觉探索与精确稿的关系

风格库选用UI Screenshot System（ui-screenshot-system，case17/2）；实际imagegen输出[方向图](imagegen/direction.png)，运行信息见[清单](imagegen/run-manifest.json)。目标与实际均3840×2160；图片不拉伸冒充4K。

精确稿沿用方向图的“外层后台＋内层业务列＋会话列表＋消息/输入”构成及主蓝/冷灰分区；修正生成图中字号、英文时间、协议内容/状态不一致等非权威细节，补全居民/员工变体。最终文字、状态和几何以确定性HTML/PNG为准，生图不作为业务事实。原图只作方向参考，不切图拼成网页背景；无外部图片依赖，断网仍可打开精确稿。

本轮没有运行screenshot-to-code、没有工程适配；HTML是精确设计稿与审阅演示，不是由该工具生成的原型。用户视觉验收仍为not_evaluated。自动几何/预览交互结果见[核验记录](verification/summary.json)，不计入生产测试用例或CF回归。
