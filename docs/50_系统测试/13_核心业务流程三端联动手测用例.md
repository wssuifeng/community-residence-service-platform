# 核心业务链手测：12条非交易用例＋3条交易保留项

> **当前唯一核心业务链手测入口（2026-10-12）**。先按下表选链，不重跑历史268TC，也不另填旧U-01～U-34。
> 只验证编码是否符合30系统设计；体验与需求满足性只记录到[12_用户手测清单.md](12_用户手测清单.md)，不作为50通过/不通过判据。
> 后端单测、接口否定矩阵、231视口加载等是已有自动证据，**不能自动替你填这12条手测结果**。

## 1. 开始前只做这些

- 本机入口：`http://127.0.0.1:5176`，后端8084；这是正常开发库，不是已回收的8087/5181隔离测试。
- 已有1社区/600房屋/9居民/1租约及0支付/0退款保留。**不清库，不运行旧13的重置种子，不更改既有租约或真实资料。**
- 推荐超管新建“手测-20261012”专用社区，给admin1绑定该社区，并给staff1绑定该社区及本次工单类别；下述新增内容都加同一前缀。已有数据只读，新建记录的ID记在末尾，便于之后按ID回收。
- 每条链只走一个主路径＋一个关键分支；其他非法流转/并发/全部角色组合由AI回归负责，不要求你逐项录缺陷。
- 多端用不同浏览器配置/隐私窗口，不在同一会话来回切账号。游客使用未登录窗口。

## 3. 12条具体用例

### HT-01 登录与角色入口
1. 各端分别登录上表账号，核对用户名/角色、菜单及首页；退出后应回登录入口。
2. 游客浏览挂牌与可约时段，点击预约必须引导注册/登录；没有匿名预约或短信验证码入口。
3. 若要体验注册，使用你控制的测试手机号创建新居民，只核对资料与身份，不冒充已经建立居住关系。
**核对**：居民不出现系统全局管理；服务人员不出现管理员审核入口。权限否定矩阵不要求人工穷尽。

### HT-02 社区结构与责任人
1. 超管建立手测社区，给admin1绑定；管理端建3层楼栋、1单元及至少2套房，户型填“三室一厅一卫”。
2. 尝试第4层建房，应拒绝；先把该楼栋层数改4，再建第4层应允许。这不是全系统统一层数上限。
3. 卡片多选后右键批量设置户型；核对所有选中房屋变化，无独立“房间数”。将责任人绑定admin1，联系人来自账号；不要填任意联系人文字。
**核对**：降低楼栋层数不得让已有房屋落到虚空层；责任人排除SUPER_ADMIN/STAFF，选择责任人不等于权限绑定。

### HT-03 居民录入与重复导入
1. 管理端代建一个合成居民，录入邮箱，并明确选择房屋、OWNER/TENANT/FAMILY、入住日期；核对账号档案与关系都能查到。
2. 打开批量导入，下载十列CSV模板；参考[18_居民CSV导入示例与复核.md](18_居民CSV导入示例与复核.md)及[samples/居民导入十列样例.csv](samples/居民导入十列样例.csv)，替换实际社区/房屋主键和不重复测试账号/手机号后导入。
3. 关闭再打开，选择同文件再次导入；重复行应失败且无重复账号；仅修正失败行再试。
4. 其他链完成后，管理员对这条**直接登记、未关联租约**的合成关系登记迁出；核对已迁出状态、日期/原因和历史留存。不拿正式租约关系绕过FT-03退租退款。
**核对**：原生.xlsx不受支持；旧四列只建账号。直接登记关系是台账录入，不自动创建租约，不等于租住首期已经支付。

### HT-04 挂牌与公开展示
1. 选择手测空置房屋挂牌，填写标题、月租与押金；游客进入详情，核对户型、标题、金额与真实数据一致。
2. 管理端修改房屋户型，核对关联挂牌同步；挂牌金额修改按权限留痕，已经提交的申请使用申请时快照，不靠“最新挂牌”猜来源。
3. 手动下线挂牌，游客列表不再显示。需要后续链时再上架；有申请引用/占用时不要物理删除。
**核对**：房屋实体与挂牌是关联但不是一张数据；没有独立随意造出的挂牌户型。

### HT-05 看房申请、沟通与取消
1. 居民从挂牌进入三步预约：选日期、连续时段、确认提交；核对预约详情和当前登录身份，不再填写短信验证码。
2. 管理端确认并分配staff1，居民与带看人员打开同一预约沟通；**由当前被分配staff1登记完成（备注必填）**，核对状态及通知。
3. 另建一条预约，用居民详情页取消，填写原因；核对取消状态、时段释放及群聊只读。
**边界**：DEF-182已按采纳方案修复，详情见[19带看设计](19_展示与统计口径确认方案.md#viewing-role)。改派后旧人员不得登记完成；违约/冻结仍由管理端处置，人员端不显示处置按钮。

### HT-06 申请占用与协议同意（止于交易前）
1. 居民对出租挂牌提交TENANT入住申请；核对该房屋/挂牌临时占用，公众不能继续看到或申请。撤回一次，应释放并恢复可见；再提交用于后续。
2. 管理端审核通过，仅生成待签约租约；发出协议即表达管理方同意，不应再让管理端重复同意。
3. 居民查看本次具体正文快照并确认同意；没有额外承租/承约确认步骤。核对协议已确认但**首期未成功时租约和正式租客关系尚未生效**。
**核对**：仅撤回某份协议不等于取消整份租约。当前不付款，这条只记录非交易段结果，不宣称完整出租闭环通过。金融详情/非空费用卡片仍需FT-01～03受控验证。

### HT-07 工单、评价与终审
1. 居民进入提交工单，服务类别卡片应可见/可选；填问题与联系信息提交，管理员受理并派staff1。
2. staff1接单、开始处理、填写处理结果并提交；居民确认完成。
3. 居民提交2星评价与说明，管理员发起跟进，新增记录后核对已跟进列表；同一工单不可重复评价。
4. 管理员终审结束，核对工单关闭、群聊只读；服务人员详情显示后端真实居民姓名，不造性别或租客/业主身份。
**核对**：如要抽查改派，只加一条在办工单，改派后旧人员不再具有当前单的详情/列表权限；不要把后端未决历史趋势口径混作权限缺陷。

### HT-08 定向公告与阅读
1. 管理端给手测社区新建公告并发布；居民查看列表与正文。定向范围以表单和绑定数据为准。
2. 居民打开正文后，管理员打开阅读明细，核对实际阅读人；管理员自己查看不应伪造成居民已读。
3. 管理员撤回或按已设计时间下线，居民不再看到公开列表项，管理历史留存。
**核对**：跨社区/全部角色过滤的否定矩阵已有AI证据，人工只抽查本条真实定向链。

### HT-09 反馈双方会话
1. 居民提交反馈；管理员打开并回复，居民补充一条消息，核对双方内容一致。
2. 管理员填写办结原因并办结；居民重进详情，只能查看历史，不能追加消息/附件。
3. 若抽查匿名，只额外建一条匿名反馈，核对管理端不显示真实姓名，不破坏本人查看。
**核对**：失败时应给明确错误，不应让人误认为业务已经完成。

### HT-10 资源图片、连续时段与取消
1. 管理员给手测社区建立资源，通过上传选择图片，调整顺序/删除，保存后居民列表与详情展示一致；不要求居民提供图片URL。
2. 管理员配置开放时段；居民三步预约相邻时段，提交后管理员确认，核对日期/区间/状态。
3. 居民取消另一条仍可取消的预约，填写原因；同容量时段应被释放。非连续/超上限由既有规则拦截，没开放时段应明确说明。
**核对**：资源预约与看房共用类似交互，但不是同一类预约数据；联系电话未填时按已设计账号资料回退。违约处置为本条可选分支：只对额外合成居民的预约标记违约，核对违约记录/操作人与时间；若需触发限制或冻结，另留该账号的受限结果，**不得冻结resident1**。不执行则记“违约分支本轮暂不执行”，不能据主路径关闭该分支。

### HT-11 通知落地与群聊（随前面用例一起做）
1. 在HT-05/07/09操作后核对相应账号的通知；点击应到对应真实对象，不是空标签页或无关联详情。
2. 做一次已读／全部已读，核对未读数；退出后换账号，不能继承上一账号通知。
3. 工单/预约群聊仅参与者可看；终审/取消后历史可查但不能继续发言。
**核对**：无需新建第二套重复工单；跨身份同数字ID等情况由AI权限回归负责。

### HT-12 真实统计与显示
1. 管理端按手测社区筛选看板，用刚创建的房屋/工单/预约/评价核对卡片与图表，不要求手算历史全库。
2. 服务人员工作台的待接单/处理中/已完成（未关闭）与列表相符；不得出现固定伪造曲线或百分比。
3. 空态/错误态区分的500注入及重试已有自动证据；正常操作遇失败，只记录入口与提示，不重复造一批数据。
**核对**：近7日派入/提交结果是按实际事件发生日的次数，重派/退回重做可多次，不是去重工单数。无负荷快照不显示增长百分比；读取失败应有原地重试。依据见[19统计设计](19_展示与统计口径确认方案.md#stats-rules)。

## 4. 交易恢复后才执行的3项

| 编号 | 链路与核对点 | 开始条件 |
|---|---|---|
| FT-01 | 当前协议确认→沙箱首期付款→后端查单确认→租约及正式租客关系同时生效；处理中/失败不提前激活，历史金额与来源正确 | 用户明确恢复项目交易测试，程序内四项支付宝配置/加密密钥可用、沙箱渠道受控启用、明确测试单号与金额 |
| FT-02 | 生效租约续约→付款确认→租期延长且幂等；中断续接/重复通知不重复延长；核对到期是日期标注而非状态变更，已到期拒绝首期但可续期、止期当天不算已过期；非空费用明细及低分辨率布局 | 真实沙箱已成功首期的受控租约，明确续约单；不能用模拟SUCCESS代替 |
| FT-03 | 退租申请/审核→押金原路退款→失败原因与重试幂等→归档/释放挂牌/关系及会话历史 | 原始沙箱支付交易可退款；确认金额与测试范围，禁止正式渠道、线下垫付和资金池 |

到期/首期拒绝分支使用另备的受控未付首期租约，不能拿已付首期的FT-02主路径对象复测；缺这类前置就记录缺前置，不修改既有正常租约或模拟SUCCESS。

2026-10-12的**独立SDK可用性复验**已能访问HTTP200沙箱收银台、无404/invalid-signature；未登录买家/付款/退款，**不是FT-01～03通过**。正常程序渠道仍停用，本次不再重复跑外部沙箱，也不跑真实渠道。
