## 2. 测试策略

### 2.1 轮次划分（2 轮，Q7 裁决）

1. **第一轮（全量）**：冒烟通过后执行全部计划用例（功能/权限/状态机/
   专项 SP-01~06/非功能 NF/12 条 E 流程）；发现缺陷登记 DEF；
2. **修复窗口**：前后端双工作区会话并行修复（分支重拆：backend 任务
   提交 main、frontend 任务提交 frontend 分支，修复完成后合并，主工作区
   执行回归）；
3. **第二轮（回归 + 补测）**：全部 DEF 回归 + 第一轮阻塞/失败用例重测 +
   抽样回归第一轮通过的核心路径（P0 用例 100% 回归、P1 抽 30%、P2 抽
   受影响模块）；第二轮新发现缺陷视严重度决定是否需要第三轮局部回归
   （出口准则未含致命/严重缺陷时可收）。

### 2.2 类型分配与执行方式（Q4 裁决）

| 类型 | 执行方式 |
|------|---------|
| 功能/状态机/异常边界（F/E） | Playwright 自动化（40 阶段 frontend_selftest.py / acceptance 脚本基础扩展，**Edge** 为执行浏览器）+ 人工探索 |
| 权限矩阵（A，SP-02） | 自动化为主（脚本逐角色登录交叉调用否定用例）+ 日志断言查库 |
| 冲突并发（C，SP-01） | 自动化脚本 N 路并发（HTTP 层）+ 落库断言 |
| WebSocket 专项（SP-04） | 自动化（复用 40 阶段 R30 双端 E2E 模式：双浏览器会话计时） |
| 定时任务长跑（R，SP-03 + TR-C10-07） | 半自动：构造数据 → 等待/触发任务 → 查 sys_task_log 与业务表断言；日志清理阈值短时调低验证后**强制恢复 730 天**（用例内置检查项） |
| 性能（P，NF-01/02/07） | **JMeter**（Q2 裁决）：脚本 + 50 并发稳态 + N7 造数前后对比 |
| 统计核对（V） | 半自动：明细 SQL 直查库 vs 看板数值/接口返回比对脚本 |
| 兼容性（B，NF-08） | 用户手动巡检（Q3 裁决），自动化用例以 Edge 覆盖单浏览器 |
| 部署（NF-09） | 一次性手工验证：按 README 冷启动独立测试库 |

### 2.3 专项安排

SP-01 冲突并发 / SP-02 权限矩阵 / SP-04 WebSocket 排第一轮前半（P0）；
SP-03 定时任务长跑第一轮启动后挂后台跨日观察（含日志清理任务）；
SP-05 上传 / SP-06 缺陷回归第一轮常规时段执行。

## 5. 入口准则 / 出口准则（量化值定稿）

**入口准则**（进入步骤 7 前逐条核对）：
1. 步骤 1b 前置开发合入 main 且专项冒烟（社区删除 + 日志清理）通过；
2. 冒烟测试（步骤 6）通过；
3. 全部计划用例完成设计评审（步骤 3 产物含 TC ↔ TR 对照）；
4. 测试环境就绪（独立测试库 + 种子 + 造数脚本可重复执行）；
5. RTM 用例列无空行（100 TR 全部有 TC 覆盖）。

**出口准则**（步骤 9 评估依据）：
1. 计划用例执行率 ≥ 98%（阻塞项需注明原因）；
2. 通过率 ≥ 95%，其中 **P0 用例通过率 100%**；
3. 致命/严重缺陷（DEF）100% 关闭；一般缺陷关闭率 ≥ 90%，遗留项经
   评估可接受并写入报告；
4. N1/N2/N3 性能判据实测达标（P95 ≤2s @50 并发、消息 ≤3s）；
5. R33/R55 冲突拦截率 100%、R44/R45/N5 越权拒绝 100%（这两类任一
   未达标不得出口，不论轮次）；
6. 日志清理阈值已恢复默认 730 天（强制检查项）；
7. 测试报告评审通过。

## 6. 风险与应对

| 风险 | 应对 |
|------|------|
| 步骤 1b 前置开发延期 | 用例设计/环境/造数与其并行；冒烟顺延不阻塞步骤 3~5 |
| 级联删除遗漏关联表（孤儿数据） | 用例设计时从 Flyway V1 全表扫描 community_id 归属，形成级联清单断言 |
| 定时任务跨日长跑与轮次进度冲突 | SP-03 第一轮启动即挂后台，第二轮收口观察结果 |
| JMeter 50 并发对本机资源挤占 | 压测会话单独时段执行，与功能自动化错开；后端 JVM 参数记录在环境文档 |
| 双工作区修复合并冲突 | 修复会话只改各自层文件；_中控/RTM 缺陷登记由主测试会话独占维护 |
| 浏览器巡检发现的环境差异 | 登记为 DEF 或环境问题双通道，不与功能缺陷混淆 |
