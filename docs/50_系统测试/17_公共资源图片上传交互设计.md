# 公共资源图片上传交互设计

> 用户已采纳 · 2026-10-11 · 仅处理公共资源图片，不改变预约功能。

**关键设计：选择本机图片上传，直接预览和移除；不再填写URL。图片修改在保存资源后生效。**

## 1. 图片区域长什么样

放在现有资源新建、编辑表单内，不另开管理页面：

```text
资源图片                                  2 / 6 张

[ 图片1：预览 · 移除 ]  [ 图片2：预览 · 移除 ]  [ ＋上传图片 ]

支持 JPG / JPEG / PNG / GIF，单张不超过 5MB。
第一张用于资源列表预览；无图时显示资源类型图标。
```

缩略图随弹窗宽度换行，长表单内部滚动，不能挤出页面。

## 2. 管理员怎么操作

1. 点击“上传图片”，选择一个或多个本机文件。
2. 每张显示上传结果；成功后立即出现在当前表单中，点击可看大图。
3. 不需要的图片点击“移除”；需要更换时，移除后重新上传。
4. 点击“保存资源”，统一保存当前图片列表。移除全部后保存，表示资源不再展示图片。

编辑时先展示原有图片；原有历史图片可保留或移除，但不提供新增URL输入。

## 3. 保存、取消和失败时的行为

| 场景 | 明确结果 |
|---|---|
| 正在上传 | 显示处理中，暂不能保存或关闭表单 |
| 一张上传失败 | 保留其他已成功图片，提示失败文件，可重新选择重试 |
| 资源保存失败 | 保留表单和图片，重试保存不必重新上传 |
| 取消编辑 | 有修改时先确认放弃；原资源图片不变 |
| 移除图片后保存 | 只取消该资源的图片关联，不立即物理删除平台文件 |

图片数量、大小和真实图片内容由服务端校验，不能只靠界面限制。

## 4. 本次采用的范围

| 方案 | 取舍 |
|---|---|
| **最多6张，单张5MB** | 沿用项目已有上传控件限制，不新设另一套标准 |
| **按上传顺序展示，第一张用于列表预览** | 本次不增加拖拽排序、独立封面设置或裁切功能 |

“文件上传替代URL输入”已经确定；以上限制和交互方案已由用户采纳，按本方案实施。不新增独立文件管理页面或物理删除接口。
