# 锁与事务并发复核矩阵（2026-10-19）

本表记录本轮真实复验覆盖的并发边界和当前实现锁序，用于说明已验证范围，不等同于所有写入口穷举证明。

| 业务入口 | 关键互斥对象与锁序 | 提交/释放边界 | 证据 | 结论 |
|---|---|---|---|---|
| 资源预约 / 看房预约 | 居民日期锁 → 资源或房屋/日期锁 → SQL容量与冲突当前读 | 事务结束后释放；资源单条写自动提交后释放 | `concurrency.json` 13/13 | 同居民重叠仅一笔成功，容量不超售，首尾相接放行 |
| 退租申请创建 | 租约锁 → house行锁 → lease行锁 → 当前日期/状态重检 → application写入 | 申请事务结束后释放分布式锁 | `concurrency.json` | 结束/缩期等待不落旧申请；审核仍按house→lease→application当前读 |
| 资源状态与违约 | reservation行锁 → resident行锁 → 当前违约计数 | 状态更新与副作用同事务；首次冻结时吊销 | `state-fixed.json` 7/7 | 旧状态不覆盖，违约副作用不重复 |
| 看房状态 | appointment行锁 → 当前状态重检；违约再锁resident | 事务结束后提交副作用 | `state-fixed.json` | 已取消状态不能被旧确认覆盖 |
| 反馈办结/消息/附件 | feedback父行锁 → 当前状态重检 → message/attachment写 | 办结后的迟到写入拒绝 | `state-fixed.json` | 关闭后的旧写请求被拒 |
| 通知序号与提交 | 故障时缓存快速短路；恢复先抬升数据库序号下限；序号调用移出进程级锁 | 完整未读快照兜底晚提交小序号 | `redis-fault.json`、`notification-order.json` | 故障恢复可用，提交乱序可恢复 |
| 工单条件更新 | 既有条件更新与锁后当前读 | 失败方返回终态，不重复建群/通知 | `backend-targeted.json` | 受影响工单回归通过 |

未覆盖：全项目所有HTTP写入口组合式穷举、生产多实例容量、真实支付渠道异常、数据库死锁注入和所有外部回调时序。
