# 深度缺陷清单与建议指南（静态审查版）

> 审查日期：2026-09-16（Asia/Shanghai）
> 审查对象：`community-residence-service-platform` 当前工作树
> 文档性质：第五轮局部回归前的深度静态审查输入，不是测试报告，也不等同于缺陷已复现、已修复或已关闭。
> 编号口径：已有 `DEF-001～DEF-044` 仍以 `08_缺陷跟踪与回归.md` 为生命周期权威；本轮新增 `DEF-045～DEF-068` 均保持“静态审查新建/待复现”或相应待验证状态。

## 1. 结论先行

当前不宜直接宣称“全量通过”或进入最终出口评审。已有第三批、第四批、第五批的单测与局部 E2E 结果，只能证明相应已执行范围；第五轮仍有 `DEF-034～036`、`DEF-037～040`、`DEF-041`、`DEF-044`、CREATE 类操作日志逐服务断言和 C 轨失败项待复核。本次静态审查又发现以下几类高风险闭环尚未由环境实测证明：

1. **权限与隐私**：楼栋定向公告的通知接收人、评价详情、看房预约详情、附件 URL、无居住关系居民的私有业务入口存在旁路风险。
2. **范围一致性**：公告的“可见范围、筛选范围、通知范围、查看回执范围”不是同一套解析逻辑；公开 GET 的范围和字段也没有形成可配置白名单。
3. **时间与配置**：预约过去日期/远期日期限制未形成统一服务端规则；若干种子配置能在配置页出现，但后端未检索到消费点。
4. **数据一致性与降级**：通知序号 Redis 故障降级可能破坏游标单调性；公告查看记录采用先查后插，重复请求可能撞唯一键。
5. **交付真实性与部署**：服务人员端仍显示按工单 ID 伪造的性别/居住身份；上传目录与 WebSocket Origin 为宽松生产配置；当前配置文件还存在 dev 默认 JWT 密钥风险。

**答辩前最低动作**不是扩展新需求，而是：先复现 P0/P1 权限与数据一致性问题，再补最小修复和回归证据；短信、微信、移动端、对象存储、消息队列、复杂趋势分析等内容放到展望，不作为本轮扩大范围的理由。

## 2. 审查范围、证据等级与环境限制

### 2.1 审查范围

本轮以静态代码和既有测试文档交叉核对为主，覆盖：

- 后端 Controller 的 URL、HTTP 方法、`@PreAuthorize` 和 `SecurityConfig`；
- Service 的对象归属检查、居民关系检查、状态机、通知和回执逻辑；
- DTO/VO、Flyway 表结构、唯一约束、软删除和数据级权限拦截器；
- 上传、WebSocket、JWT、配置缓存、日志 AOP 和定时任务；
- 前端 API、路由角色、页面字段、占位工具和第五轮 C 轨待复验项；
- `08`、`11`、`_中控` 中已有的回归状态、环境及出口口径。

### 2.2 证据等级

| 等级 | 口径 | 可写成什么 | 本文采用方式 |
|---|---|---|---|
| A | 已在脚本/浏览器/数据库中执行并复现 | “实测”“回归通过/失败” | 只沿用 `DEF-001～044` 已有记录，不把静态发现倒写成 A |
| B | 静态代码路径已闭合，但当前轮尚未启动环境复测 | “静态代码确认，待环境复现” | 本轮大多数 `DEF-045+` |
| C | 实现与需求、接口或页面契约冲突，需要产品/矩阵裁决 | “契约问题/待需求复核” | `DEF-046/054/055` 等 |
| D | 依赖 Redis、MySQL、浏览器、代理、生产配置或并发条件 | “需要环境/数据库复测” | 不能标为已通过 |

**重要原则**：代码中“看起来会发生”不等于运行时已经发生；“单测通过”也不覆盖公开入口、真实数据库约束、跨角色、跨标签页和生产配置。新增缺陷统一在 `08` 中列为待复现，不虚构回归结果。

### 2.3 当前构建/测试环境限制（必须随答辩材料保留）

本轮实际尝试记录如下：

- 后端：`cd backend && ./mvnw -q -DskipTests compile` 首先遇到 wrapper 不可执行（`Permission denied`）；改用 `bash ./mvnw -q -DskipTests compile` 后，Maven Wrapper 下载失败：`wget: Failed to fetch https://repo.maven.apache.org/maven2/org/apache/maven/apache-maven/3.9.6/apache-maven-3.9.6-bin.zip`。因此本轮不能把 Maven 编译结果写成通过，也不能以编译失败直接证明业务代码失败。
- 前端：`cd frontend && npm ci` 失败，npm 输出 `npm error Exit handler never called!`，并提示这是 npm 自身错误。依赖没有形成可重复的本轮安装证据。
- 前端 `package.json` 只有 `dev`、`build`、`preview`、`typecheck`，没有 Jest/Vitest/Playwright 等自动化测试脚本；因此页面真实性、权限入口、字段展示和视觉结论必须由 C 轨浏览器手测/截图或另行建立测试资产证明。
- 既有文档中“单测 288/288”“第三批/第四批专项通过”等结论保留其原执行环境和基线，不因本轮静态审查而改写；它们不能自动覆盖本文件新增条目。

| DEF-066 | 迁出；`ResidenceRelationService.moveOut()` | 只检查当前未迁出，不校验 `moveOutDate` 与 `moveInDate`、当前日期的关系；未来迁出日期也会立即让关系不再被 `IS NULL` 识别，并联动租约为 MOVED_OUT。 | B：静态代码确认，需业务日期裁决 | 校验日期顺序和是否允许未来办理；如允许预登记，另建 plannedMoveOutDate，不要复用生效字段 | 早于入住、等于入住、今天、未来日期分别断言；关系/租约/房屋状态联动一致 |
| DEF-067 | 公开 available-slots；资源/房源 `availableSlots()` | `startDate/endDate` 未见统一 `start≤end` 和最大跨度限制；匿名接口可请求极大日期范围，触发逐日展开、全量占用查询和大响应，具备资源消耗/拒绝服务风险。 | B/D：静态确认，需压测/边界复测 | 强制最大跨度（如 7/31 天，以产品口径为准）、非法范围 400、响应上限和缓存；创建日期规则与查询规则一致 | 反向日期、1 天、最大天数、超过上限、超大跨度；状态码、耗时、响应条数有上限 |

### 3.3 当前暂不升级为缺陷的观察项

- `OperationLogAspect` 的人工 JSON 拼接、代理头 IP 信任、WebSocket 认证后 `SecurityContextHolder` 清理等属于部署/健壮性加固候选；除非环境复现造成日志写入失败、审计字段伪造或跨请求主体污染，不在答辩前扩展修复面。
- 房源浏览计数公开且无频控会被刷高，属于统计真实性风险；若 R53/R55 的指标被用于验收，应补去重/频控用例，否则列为 P2 观察，不与权限越权混为 P0。
- `PublicResourceService` 的 `status` 参数是契约漂移，不应为了“让参数有效”临时新增资源状态需求；优先删除无效参数并同步接口文档。

## 4. 分类建议与设计指南

### 4.1 权限矩阵（修复/回归的最小基线）

| 能力 | 游客 | 无有效居住关系居民 | 有效居民 | ADMIN（绑定社区） | STAFF | SUPER_ADMIN |
|---|---|---|---|---|---|---|
| 认证、公开房源/公告 | 仅公开白名单 | 仅公开白名单 | 公开白名单 | 公开白名单 | 公开白名单 | 全部 |
| 社区结构/资源详情 | 仅字段白名单 | 同左 | 同左；私有字段不因登录扩大 | 绑定社区完整管理字段 | 不开放管理字段 | 全局 |
| 提交入住申请 | 否 | **允许**，这是建立关系的入口 | 视重复申请规则 | 审核绑定社区 | 否 | 全局 |
| 工单、反馈、资源预约 | 否 | **拒绝** | 仅本人且社区关系有效 | 仅绑定社区处置 | 仅被派工单 | 全局/审计 |
| 居民公告/通知 | 公开广播口径 | 不得读取私有定向公告 | 仅关系社区/楼栋和广播 | 绑定目标社区 | 不因 STAFF 身份看到居民私有公告 | 全局 |
| 评价/查看者/附件 | 否 | 否 | 仅本人关联工单/附件 | 绑定社区 | 仅被派工单必要字段 | 全局 |
| 看房预约详情/取消 | 公开创建需防滥用；详情脱敏/核验 | 本人预约 | 本人预约 | 绑定社区管理 | **禁止取消/处置** | 全局 |
| 配置 | 公开键只读 | 公开键只读 | 公开键只读 | 按明确权限 | 否 | 读写全局 |
| 操作日志 | 否 | 否 | 否 | 绑定社区日志 | 按需求决定，不默认开放 | 全局 |

**实现要求**：Controller 的角色注解只是第一层；Service 必须校验对象归属和当前居民关系；DataScope 只负责 SELECT 改写，不能替代 INSERT/UPDATE 前的显式授权。

### 4.2 状态机与副作用指南

| 状态域 | 权威流转 | 必须保证 |
|---|---|---|
| 公告 | DRAFT → PUBLISHED → WITHDRAWN | 目标解析、游客可见、居民可见、管理员管理、通知接收人、查看回执五条路径使用同一范围函数；非法状态不产生通知/回执 |
| 资源预约 | PENDING → RESERVED → COMPLETED；PENDING/RESERVED → CANCELLED；RESERVED → VIOLATED | 日期边界、模板覆盖、栅格容量、居民关系、状态占用集合一致；重复请求幂等 |
| 看房预约 | TO_CONFIRM → RESERVED → COMPLETED；TO_CONFIRM/RESERVED → CANCELLED；RESERVED → VIOLATED | 游客与居民身份分支明确；详情脱敏/核验；管理处置角色固定；锁、唯一键、通知同一口径 |
| 工单 | 以架构 §6.1 为准 | 非法/同态流转返回业务码且零时间线、零通知副作用；居民、STAFF、ADMIN 对同一工单的读写面不同 |
| 入住申请 | PENDING → APPROVED/REJECTED | 关系、租约、房屋状态、申请状态在一个事务内；关系创建前后的入口口径一致 |
| 租约/居住关系 | PENDING → ACTIVE → MOVED_OUT → ARCHIVED | 日期顺序、迁出日期与关系生效日期一致；终态不能通过其他 PUT 旁路修改 |

### 4.3 接口契约指南

1. **状态码先于页面文案**：缺文件、未知配置、日期越界、无权限、对象不存在分别固定 400/404/403，不让 NPE/数据库异常变成 500。
2. **DTO、VO、前端类型三方同源**：删除 `status` 这类无效参数；去掉 `appointmentNumber`、`visitorCount`、`tags` 等幽灵字段，或后端真实提供并写回接口文档。
3. **公开接口拆 DTO**：管理端 VO 不应直接成为游客 VO；公开接口不因“方便 `<img>`”而公开业务文件。
4. **配置必须有注册表**：每个 key 要有类型、默认值、权限、脱敏策略、唯一消费点和回归用例；读写未知 key 均拒绝。
5. **公开 GET 也要做资源授权**：`permitAll` 只表示 HTTP 层免认证，不代表响应可以返回全实体、内部 ID 关系、占用状态或个人数据。

### 4.4 数据一致性指南

- 通知接收人和公告可见人都从同一 `NoticeTargetResolver` 产生；BUILDING 必须经 building→house/residence_relation 解析。
- Redis 只做缓存/加速时，不能让故障切换改变业务游标的数值量纲；通知 `seq` 需要单调、唯一、可恢复。
- “先查后插”不能作为唯一幂等保障；唯一键异常要按接口语义转换，计数使用原子 SQL 或可靠事件汇总。
- 所有“账号创建”“入住关系建立”“租约建立”必须在表、接口、页面和演示词中使用同一语义，不用一个动作冒充另一个动作。
- 级联删除、软删除、历史外键清理要在同一事务和同一回归数据集验证；已有 DEF-033 的修复结论不能推导出新链路都安全。

### 4.5 前端真实性指南

- 页面只显示真实响应字段；缺字段显示“未提供/—”，不使用取模、随机、示例值补足居民画像。
- 每个后端能力至少有：入口、请求体、成功回显、错误提示、刷新后持久化、Network 证据和数据库证据。
- C 轨失败不得改写为“后端已通过”；如果只是后端端点交付但页面未接线，应继续保留为前端待办。
- `npm` 依赖安装失败且无前端自动化测试时，答辩材料应明确“浏览器手测/截图证据”而不是写“前端测试通过”。

### 4.6 部署安全指南

- 生产必须通过环境变量注入 JWT、数据库、Redis 和上传存储；默认密钥、dev profile、localhost 依赖均应启动即失败或被部署检查拦截。
- WebSocket Origin 使用环境白名单，不使用 `*`；SockJS 代理、反向代理、HTTPS 和预览域名分别验证。
- 上传文件采用授权下载或短时签名 URL；文件类型、大小、路径穿越、Content-Disposition、缓存和日志脱敏要成套验证。
- 生产日志不得记录密码、JWT、初始密码、完整身份证、附件 URL 或配置敏感值；操作日志失败要有可观测告警，不能只 WARN 后静默丢失。

### 5.2 建议的答辩演示最小路径

- SUPER_ADMIN 创建社区/楼栋/资源、绑定 ADMIN；

- 前端展示只来自真实接口字段，缺数据不显示伪造性别/身份；
- 展示测试限制和仍待执行列表，而不是用单测数字覆盖尚未验证的安全路径。
