# 业务详情页减负方案：重点整理租约详情

依据：用户2026-10-17采纳三段会话稿，并提出工单/反馈详情聊天收口及租约详情过于臃肿。本稿只说明这些页面如何精简；用户随后授权实施，分区及沟通入口已写入工程，证据见[cl验证](evidence/cl-conversation-workspace-20261017/README.md)。不改租约、付款、审批或权限规则。

## 1. 改造前的问题

管理端租约详情同时展开：租约属性、押金及退还流水、关联看房、完整变更历史、状态操作、完整协议面板、完整租约群聊。群聊还在较窄右栏中，查一项信息需要跨多个长面板滚动。同样的聊天在详情和会话页各占一块完整界面。

**推荐：详情负责查业务、办业务；统一会话页负责沟通。** 不推荐只把字号/卡片缩小，也不把所有区块折叠成难以发现的功能。

## 2. 租约详情：顶部摘要＋四个分区

```text
返回租约列表   房屋 / 租户 / 租约标识     当前状态 · 协议状态 · 押金状态
合同起止、月租、当前需处理事项             进入租约沟通 / 当前可用操作
──────────────────────────────────────────────────────────────
概览      合同与协议      费用记录      业务记录
当前分区内容（默认只展开概览，不再全部堆在一页）
```

| 区域 | 放什么 | 原功能如何保留 |
|---|---|---|
| 顶部摘要 | 房屋/社区、租户、合同起止、三类状态及当前操作提示 | 使用真实状态/后端数据，不重复整张属性表；当下可用状态动作紧邻摘要，不再占一整条侧栏 |
| 概览（默认） | 关键身份与租约属性、月租/押金及付款安排摘要、备注 | “编辑属性”打开原编辑表单，沿用字段限制/校验/留痕，不把所有编辑框常驻首屏 |
| 合同与协议 | 合同期限、已批准延长、首期/后续付款约定、协议快照及确认记录 | 复用现有合同与协议组件；原“合同与租期”入口打开此分区。发出/撤回等操作继续原权限，管理端发出代表同意，居民只确认一次 |
| 费用记录 | 已有费用/支付信息、押金状态和退还流水 | 原退还入口、渠道状态、失败原因、记录查看全部保留；没有真实数据的合计不编造，打开分区不会触发支付/查单/退款 |
| 业务记录 | 关联看房、完整变更历史 | 按“看房记录／变更历史”组织，保留原记录与失败重试；不删历史，不把最近几条冒充全部记录 |

主数据失败才阻断详情；其它分区按需加载、各自提示错误和重试，切换保留位置。返回列表保留原筛选；从会话打开详情时可返回原会话，不跳到另一条租约。租约终态冻结、付款生效、金额和期限规则均不因分区调整而改变。

## 3. 工单、反馈详情：不再内嵌整套聊天

| 页面 | 详情继续保留 | 沟通如何进入 |
|---|---|---|
| 三端工单详情 | 报修内容、现场附件、进度/派单/处理/验收及当前动作 | 小型“工单沟通”入口，显示真实会话状态；已有摘要时可展示一条最新摘要，缺摘要不新造数据。点击进入统一会话并选中对应群 |
| 管理/居民反馈详情 | 原始反馈、分类/匿名选择、办理状态、原提交/历史附件及已有处理动作 | “进入反馈沟通”选中本反馈；会话中的新图片仍归对应消息。原始内容/历史附件不能因聊天迁走而丢失，查看不自动受理 |
| 租约详情 | 上述四分区，协议及状态动作仍属于业务详情 | 顶部“进入租约沟通”，不再在窄右栏常驻消息列表/输入框；原与租户直通入口可保留为明确的次级动作 |

从任何入口进入，都命中同一条真实沟通来源。群聊与反馈用来源类型＋标识区分，不能只靠可能碰撞的数字ID。匿名标题、摘要、头像、成员/搜索继续隐藏身份；服务人员不因此获得反馈或租约权限。工单/租约存量漏群仍由有权管理方显式补齐，普通查看不自动加群。

## 4. 落地顺序与本次边界

1. 会话整体结构已经用户采纳，先按32补最小真实契约并接通三端会话工作区，含反馈入口、排序/搜索/未读/历史及业务动作，不能用合成稿代替。
2. 验证新入口能够定位原会话、发送/读回/返回和关闭只读后，再把旧详情内嵌聊天换成入口；接通前保留原聊天，不出现“详情删了，新页面尚不可用”。
3. 租约详情按已授权四分区拆出概览、费用、业务记录子组件及局部样式；保留原按钮、状态门禁、协议/付款/历史能力。费用与业务记录按需读取、独立重试，费用读取失败不伪装为空记录；不夹带改动租约或金融规则。
4. 三端工单、两端反馈详情已用准确来源入口替换内嵌聊天，保留原内容、附件与动作；从详情进入会话可返回原对象。查看不受理、不自动补群。
5. 只测会话及受影响的详情链；CF-02、其它已通过业务不重跑，不要求再次付款。自动验证不代替人工观感；正常环境加载边界见cl证据。
