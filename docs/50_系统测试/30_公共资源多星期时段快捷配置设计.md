# 公共资源多星期时段快捷配置设计

> 依据2026-10-15用户“快捷选中多天添加同时段”的反馈拟定，用户已采纳；只改资源时段配置，不改预约额度算法。

## 1. 现有时段是什么

当前资源时段是**每周循环模板**：dayOfWeek（周一～周日）＋起止时间＋开放状态；不是一个个具体年月日。当前表单每次只选一个星期，创建一条模板，因而配周一到周五要重复五次。

## 2. 推荐：多选星期，一次应用

```text
应用日期：每周循环
[周一] [周二] [周三] [周四] [周五] [周六] [周日]
快捷选择：工作日 / 周末 / 全周 / 清空
开始：[09:00]  结束：[12:00]  状态：[开放]
将为选中的5个星期添加同一时段
[取消] [添加到所选星期]
```

- 可选任意1～7个星期，开始/结束时间只填一次。预览所选星期和时段，提交后保留星期和时间以便继续补下午时段，而不是每次重置周一。
- 成功提示实际新建数及已存在数；列表按星期、时间逻辑排序，不依赖自增ID看顺序。
- 时间范围、栅格对齐、资源容量继承原校验；跨午夜仍拆为两段，不借快捷配置改变一天的定义或把容量复制成总预约条数。

## 3. 冲突与后端处理

推荐单个受权限保护的批量操作，在同资源锁内核对所有所选星期后写入，而不是前端连发七次、失败后留下不清楚的一半数据。

- 完全相同模板：报告已存在并跳过，不复制，也不擅自重启原来停用的时段。
- 不是完全相同、但与原时段重叠：显示冲突星期与原时间，整批不新增，不覆盖既有预约/模板；用户调整后重试。
- 无冲突的新条目一次提交；并发提交或重试不能生成重复模板。权限仍限管辖社区，不扩大成跨社区配置。

## 4. 与“选择具体多天”的区别

此推荐首先满足现有**周一～周日多选**，可马上覆盖日常运营。如果用户指的是“10月20、22、25日”这种任意具体日期，则需要额外设计日期例外/节假日开闭与周模板优先级，不能把日期强塞进dayOfWeek。本版不擅自引入第二套日历规则。

按用户批准以现有周模板落实，确认不会把“多天”误实现为跨日期预约；可后续单独讨论具体日期例外，不混入本次。

验收：工作日一键新增5天；任意周二/周四同一时间；已存在不重复；部分重叠整批拒绝且数据不变；停用模板不被复活；跨社区拒绝；预约时仍按24×100等原额度口径展示。
