## 2. 验收中发现并修复的前端缺陷（8 类契约漂移，均「前端适配后端」收口）

| # | 缺陷 | 根因（接口文档 vs 后端实现） | 修复 |
|---|------|------------------------------|------|
| F1 | 楼栋创建 400「floors 不能为空」 | 文档 totalFloors / 后端 floors | types + 4 视图 |
| F2 | 单元创建字段全错 | 文档 unitNumber+totalFloors+householdsPerFloor / 后端 name+description | types + UnitListView |
| F3 | 房屋创建字段漂移 | 文档 bedrooms/livingRooms/bathrooms/propertyType / 后端 roomCount+layout | types + HouseListView |
| F4 | admin1 公告存草稿失败「必须指定目标社区」 | 登录响应 boundCommunities 文档为对象数组 / 后端为 ID 数组，默认社区取值落空 | types/user.ts + NoticeCreateView（ID 数组+社区列表补名）+ ServiceCategoryListView |
| F5 | 居民提交工单 400「content 不能为空」 | 文档 description+urgency / 后端 content+priority；工单 VO 另有 orderNo/address、无时间戳族字段 | workorder types + 8 视图全量适配 |
| F6 | 反馈办结 400「remark 不能为空」 | 文档 reason / 后端 remark | types + FeedbackDetailView |
| F7 | 公告发布 500 | 前端 toISOString() 带 Z 后缀 / 后端 Jackson 不解析带时区 ISO | 3 处视图转本地无时区格式 |
| F8 | 看房预约提交字段全错 | 文档 timeslotId 模型 / 后端 appointmentDate+startTime+endTime+contactPhone；看房状态机文档 PENDING/CONFIRMED / 后端 TO_CONFIRM/RESERVED；评价文档 4 维评分 / 后端单维 rating+tags+isSatisfied | housing/evaluation types + 5 视图 + 时段周模板降级展开 |

另修复 2 个 UI 完备性缺口：游客房源列表卡片补浏览量展示（E12 验证点）；
居民端社区归属改从本人 ACTIVE 居住关系推导（登录响应对居民恒为空数组）。

修复后 `vue-tsc --noEmit` 0 错误、`vite build` 通过。

## 3. 验收中发现的后端问题（新增 4 项，转后端会话）

| 编号 | 问题 | 优先级 |
|------|------|--------|
| BE-ISSUE-5 | `GET /housings/{id}/available-slots`（接口设计 9.12.2.8）未实现——前端已做周模板降级展开，后端补齐后建议前端回切真接口 | P1 |
| BE-ISSUE-6 | `PATCH /notices/{id}/publish` 不接受带 Z 后缀的 ISO 时间（Jackson 未配时区），前端已绕过；建议后端统一支持 ISO 8601 含时区格式 | P2 |
| BE-ISSUE-7 | 社区无 DELETE 端点（楼栋/单元/房屋/资源均有）；前端用「停用」语义与之一致，验收判定为设计口径而非缺陷，但 R1「社区增删改查」需求映射与实现不符，需后端确认口径 | P2 |
| BE-ISSUE-8 | `DELETE /notices/{id}` 恒 500：notice_target 有 FK 指向 notice，删除顺序先父后子违反约束；应先删 notice_target 再删 notice（草稿残留 currently 无法清理） | P1 |
