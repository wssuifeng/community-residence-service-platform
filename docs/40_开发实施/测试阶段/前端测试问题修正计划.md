## 2. 前后端契约漂移（已由前端适配，仅供参考）

### 2.1 全局配置接口契约不一致（FE-BUG-2）

**接口文档描述**：
- `GET /api/v1/configs` 返回分页结构 `{records: [{key, value}], total, page, size}`

**后端实际实现**：
- 返回全量数组 `[{configKey, configValue, configGroup, configDescription}]`

**前端适配方式**：
- 修改类型定义：`ISysConfig` 改为 `configKey/configValue`
- 修改 API：`getConfigList()` 返回类型改为数组
- 修改视图：`GlobalConfigView.vue` 移除分页逻辑

---

### 2.2 统计接口契约不一致（FE-BUG-3）

**接口文档描述**：
- `GET /api/v1/statistics/dashboard` 返回嵌套结构 `{summary: {...}, trend: {...}}`
- 独立端点：`/statistics/residents`、`/statistics/work-orders`、`/statistics/evaluations`

**后端实际实现**：
- 返回扁平 Map 结构：`{workOrderTotal, byStatus, byCategory, ...}`
- 无独立统计端点，全部数据在 `/dashboard` 一次性返回

**前端适配方式**：
- 重写类型定义：`types/modules/statistics.ts` 改为扁平结构
- 重写 API：`api/statistics.ts` 统一从 `getDashboardData()` 获取
- 重写 4 个统计视图：
  - `DashboardView.vue`（运营看板）
  - `WorkOrderStatisticsView.vue`（工单统计）
  - `ResidentStatisticsView.vue`（居民统计）
  - `EvaluationStatisticsView.vue`（评价统计，复用看板数据）

---

### 2.3 房源/反馈数据结构不一致（FE-BUG-4）

**接口文档描述**：
- 房源数据 `tags` 字段必填
- 房源数据 `description` 字段必填
- 反馈消息接口返回分页结构

**后端实际实现**：
- `tags` 字段不返回（null）
- `description` 字段可为 null
- 反馈消息接口返回数组（非分页）

**前端适配方式**：
- `tags` 改为可选类型 + 8 处空值防御（`tags?.length` / `tags?.split()`）
- `description` 增加 null 分支渲染
- `listFeedbackMessages()` 返回类型改为数组，两个反馈会话视图同步

## 3. 后端待修复问题（4 个）

### 3.1 BE-ISSUE-1：通知接口 500 错误（Critical）

**问题描述**：
- 接口：`GET /api/v1/notifications`
- 现象：返回 500 系统内部错误
- 影响：三端通知页无法加载数据，显示空态

**排查方向**：
- 检查 `NotificationController` 和 `NotificationService`
- 可能原因：
  - 数据库查询异常（JOIN 语句错误、字段不存在）
  - 分页参数处理异常
  - 返回数据格式化异常

**验证方式**：
- 访问 `GET /api/v1/notifications?page=1&size=20`
- 预期返回：`{code: 200, data: {records: [...], total, page, size}}`

**优先级**：P0（阻塞三端通知功能）

---

### 3.2 BE-ISSUE-2：反馈附件接口 404（Major）

**问题描述**：
- 接口：`GET /api/v1/feedbacks/{id}/attachments`
- 现象：返回 404
- 影响：反馈详情页附件区显示为空

**排查方向**：
- 检查路由映射是否存在该端点
- 对比接口设计文档 §9.6.2.3 定义的路径
- 可能原因：
  - 端点未实现
  - 路径拼写错误（如 `/attachment` vs `/attachments`）
  - Controller 缺少 `@GetMapping`

**验证方式**：
- 访问 Swagger UI：`http://localhost:8080/swagger-ui.html`
- 搜索 `attachments` 相关端点
- 或直接访问：`GET /api/v1/feedbacks/1/attachments`

**优先级**：P1（反馈功能不完整，但不阻塞核心流程）

---

### 3.3 BE-ISSUE-3：游客公告回执权限拒绝（Major）

**问题描述**：
- 接口：`POST /api/v1/notices/{id}/view`
- 现象：游客访问返回 403
- 影响：游客查看公告详情无法记录查看回执
- 矛盾：接口设计文档 §9.5.1.x 标注「记录查看（公开）」

**排查方向**：
- 检查 `NoticeController` 的 `@PreAuthorize` 注解
- 确认是否配置为 `permitAll()` 或 `anonymous()`
- 可能原因：
  - 接口误配置为需要登录
  - Spring Security 配置未放行该路径

**验证方式**：
- 未登录状态访问：`POST /api/v1/notices/1/view`
- 预期返回：200（或 401 if 设计变更）

**设计确认**：
- 如果游客不需要记录回执：前端移除游客端调用逻辑
- 如果游客需要记录回执：后端放行权限或改为匿名记录

**优先级**：P1（需要澄清设计意图）

---
