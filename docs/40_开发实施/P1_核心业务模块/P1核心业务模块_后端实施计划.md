## 3. 通用开发规范

### 3.1 包结构规范

每个模块（C1~C12）按以下结构组织：

```
com.community.residence.{module}/
├── controller/        # Controller 层（RESTful 接口）
├── service/          # Service 层（业务逻辑）
│   └── impl/        # Service 实现类
├── mapper/           # Mapper 层（数据访问）
├── entity/           # Entity 层（数据库实体）
├── dto/              # DTO 层（请求参数）
└── vo/               # VO 层（响应数据）
```

### 3.2 命名规范

| 层次 | 命名规则 | 示例 |
|------|---------|------|
| Controller | `{Resource}Controller` | `CommunityController.java` |
| Service | `{Resource}Service` | `CommunityService.java` |
| ServiceImpl | `{Resource}ServiceImpl` | `CommunityServiceImpl.java` |
| Mapper | `{Resource}Mapper` | `CommunityMapper.java` |
| Entity | 与表名对应（驼峰） | `Community.java` |
| DTO | `{Action}{Resource}DTO` | `CreateCommunityDTO.java` |
| VO | `{Resource}VO` | `CommunityVO.java` |

### 3.4 参数校验规范

**DTO 参数校验**（JSR-303）：
```java
@Data
public class CreateCommunityDTO {
    
    @NotBlank(message = "社区名称不能为空")

    private String contactPhone;

```

### 3.5 权限注解规范

**功能级权限**（Spring Security `@PreAuthorize`）：
```java
// 超级管理员专用
@PreAuthorize("hasRole('SUPER_ADMIN')")

// 管理员（社区管理员 + 超级管理员）
@PreAuthorize("hasAnyRole('ADMIN', 'SUPER_ADMIN')")

// 服务人员
@PreAuthorize("hasRole('STAFF')")

// 居民
@PreAuthorize("hasRole('RESIDENT')")

// 多角色组合
@PreAuthorize("hasAnyRole('ADMIN', 'SUPER_ADMIN', 'STAFF')")
```

**数据级权限**（自动注入，无需手动处理）：
- 社区管理员（ADMIN）：自动过滤 `community_id IN (绑定社区列表)`
- 超级管理员（SUPER_ADMIN）：不过滤，可见全部数据
- 服务人员（STAFF）：自动过滤 `community_id IN (绑定社区列表)`

### 3.6 异常处理规范

**业务异常**（统一使用 `BusinessException`）：
```java
// 资源不存在
throw new ResourceNotFoundException("社区不存在");

// 业务逻辑错误
throw new BusinessException(ErrorCode.COMMUNITY_DISABLED, "社区已停用");

// 参数校验错误（@Valid 自动处理，无需手动抛出）
```

### 3.7 状态机实现规范

系统共有 **6 个状态机**（参考 `架构设计.md` §6），必须严格实现状态流转校验：

#### 3.7.1 工单状态机（C4 模块）
```
PENDING（待派单）
  ↓ assign（派单）
ASSIGNED（已派单）
  ↓ accept（接单）
IN_PROGRESS（处理中）
  ↓ complete（完成）
COMPLETED（已完成）
  ↓ confirm（居民确认）
CONFIRMED（已确认）

非法流转：PENDING → IN_PROGRESS（跨越 ASSIGNED）
```

#### 3.7.2 入住申请状态机（C2 模块）
```
PENDING（待审核）
  ↓ approve（通过）
APPROVED（已通过）

PENDING（待审核）
  ↓ reject（拒绝）
REJECTED（已拒绝）

非法流转：APPROVED → REJECTED（终态不可变更）
```

#### 3.7.3 租住状态机（C3 模块）
```
EFFECTIVE（生效中）
  ↓ 到期前 30 天（系统判定）
EXPIRING（即将到期）
  ↓ 到期日（系统判定）
EXPIRED（已到期）

EFFECTIVE/EXPIRING
  ↓ terminate（提前终止）
TERMINATED（已终止）

非法流转：EXPIRED → EFFECTIVE（过期不可恢复）
```

#### 3.7.4 预约状态机（C7 模块）
```
PENDING（待审核）
  ↓ confirm（确认）
CONFIRMED（已确认）
  ↓ complete（完成）
COMPLETED（已完成）

PENDING/CONFIRMED
  ↓ cancel（取消）
CANCELED（已取消）

CONFIRMED
  ↓ 未到场（超时未确认）
NO_SHOW（未到场，记录违约）

非法流转：COMPLETED → CANCELED（完成后不可取消）
```

#### 3.7.5 看房预约状态机（C12 模块）
```
（复用 C7 预约状态机逻辑）
PENDING → CONFIRMED → COMPLETED
         ↓ cancel
       CANCELED
         ↓ no_show
       NO_SHOW
```

#### 3.7.6 反馈状态机（C6 模块）
```
PENDING（待受理）
  ↓ accept（受理）
PROCESSING（处理中）
  ↓ resolve（解决）
RESOLVED（已解决）

PROCESSING
  ↓ close（直接关闭）
CLOSED（已关闭）

非法流转：RESOLVED → PROCESSING（已解决不可回退）
```

**实现要点**：
- Service 层状态流转方法必须先调用 `validateStateTransition(currentState, targetState)` 校验合法性
- 状态变更必须记录日志表（如 `lease_status_change_log`）
- 非法流转抛出 `BusinessException(ErrorCode.STATE_TRANSITION_INVALID)`

**错误码枚举**（`ErrorCode.java`）：
```java
public enum ErrorCode {
    // 通用错误码 5001~5099
    OPERATION_FAILED(5001, "操作失败"),
    DATA_EXISTS(5002, "数据已存在"),
    DATA_NOT_FOUND(5003, "数据不存在"),
    
    // 社区管理 5101~5199
    COMMUNITY_DISABLED(5101, "社区已停用"),
    BUILDING_REFERENCED(5102, "楼栋被引用无法删除"),
    
    // 居民管理 5201~5299
    ACCOUNT_FROZEN(5201, "账号已冻结"),
    APPLICATION_REVIEWED(5202, "入住申请已审核"),
    
    // 工单管理 5301~5399
    WORKORDER_NOT_FOUND(5301, "工单不存在"),
    WORKORDER_STATUS_INVALID(5302, "工单状态流转非法"),
    
    // 预约管理 5401~5499
    RESERVATION_CONFLICT(5401, "预约时段冲突"),
    RESERVATION_CANCELED(5402, "预约已取消"),
    
    // 评价管理 5501~5599
    WORKORDER_NOT_COMPLETED(5501, "工单未完成不可评价"),
    EVALUATION_EXISTS(5502, "已评价不可重复");
    
    private final int code;
    private final String message;
}
```
