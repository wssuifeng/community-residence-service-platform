# 后端自测提示词

**测试会话**：后端工作区会话  
**测试范围**：后端自测（26 个 Controller、27 个 Service、状态机、权限控制）  
**测试计划**：`docs/40_开发实施/P1核心功能测试计划.md` §2 后端自测计划

---

## 提示词

```
你好，我需要你执行 P1 阶段的后端自测。

【测试目标】
验证所有后端接口功能正确、参数校验有效、权限控制准确、状态机流转正确、业务逻辑完整。

【测试计划】
请阅读测试计划文档：docs/40_开发实施/P1核心功能测试计划.md 的第 2 章"后端自测计划"。

【前置条件 - 必须先完成】
1. 确认 MySQL 和 Redis 已启动
2. 确认 Flyway 迁移已执行（V1~V5）
3. 启动 Spring Boot 应用：
   ```bash
   cd backend
   mvn spring-boot:run
   ```
4. 确认应用启动成功（http://localhost:8080）
5. 访问 Swagger UI 确认接口文档可用：http://localhost:8080/swagger-ui.html

【测试范围】
执行以下测试项（共 150+ 个测试用例）：

**1. C1 社区基础信息管理**（BE-C1-001 ~ BE-C1-030）
- 社区管理：创建（超管专属）、查询、更新状态、删除
- 楼栋管理：创建、删除保护检查、数据级权限过滤
- 单元管理：创建、删除保护检查
- 房屋管理：创建、更新状态、查询状态历史、数据级权限过滤
- 公共资源管理：创建、停用、查询
- 资源时段管理：创建时段配置、查询可预约时段、冲突检测

**2. C2 居民与居住关系管理**（BE-C2-001 ~ BE-C2-020）
- 居民账号管理：自助注册（开关控制）、代建账号、冻结、冻结后登录拒绝
- 入住申请管理：提交申请、审核（通过/拒绝）、状态机非法流转验证、审核通过自动联动（房屋状态变更、建立居住关系、创建租约）
- 居住关系管理：查询、搬出登记、查询历史

**3. C3 租住管理**（BE-C3-001 ~ BE-C3-010）
- 租约管理：创建、审核、状态自动判定（EFFECTIVE → EXPIRING → EXPIRED）、提前终止、查询即将到期租约

**4. C4 工单管理**（BE-C4-001 ~ BE-C4-020）
- 工单管理：居民提交、管理员派单、服务人员接单、处理、居民确认、状态机非法流转验证、数据级权限过滤、查询处理记录时间线

**5. C5 公告管理**（BE-C5-001 ~ BE-C5-010）
- 公告管理：创建（草稿）、发布（定向全社区/指定楼栋/指定居民）、置顶、下线、有效期过滤、居民查看记录回执、查询回执统计

**6. C6 反馈管理**（BE-C6-001 ~ BE-C6-010）
- 反馈管理：居民提交、管理员回复自动受理、办结、查询会话消息列表、数据级权限过滤

**7. C7 资源预约管理**（BE-C7-001 ~ BE-C7-015）
- 预约管理：居民创建、时段冲突检测、管理员审核（通过/拒绝）、居民取消、预约完成、预约违约（NO_SHOW）、查询可预约时段

**8. C8 评价管理**（BE-C8-001 ~ BE-C8-010）
- 评价管理：居民提交评价（满意/不满意）、工单未完成拒绝评价、重复评价拒绝、管理员跟进不满意评价、查询评价统计（按服务人员/服务类别聚合）

**9. C9 社区运营统计**（BE-C9-001 ~ BE-C9-005）
- 统计管理：查询运营看板数据（16 卡片 + 4 图表）、统计数据准确性验证（与数据库对比）、数据级权限过滤

**10. C10 权限管理**（BE-C10-001 ~ BE-C10-015）
- 系统用户管理：超管创建管理员/服务人员、管理员尝试创建拒绝、超管绑定管理员到社区、社区绑定变更后令牌吊销、冻结账号后令牌吊销、修改密码后令牌吊销
- 全局配置管理：超管修改全局配置、管理员尝试修改拒绝
- 操作日志管理：查询日志列表、操作日志自动记录

**11. C11 通知中心**（BE-C11-001 ~ BE-C11-010）
- 通知管理：查询通知列表（未读优先）、标记已读（单条/全部）、增量拉取通知（基于 seq）、通知自动生成（工单派单/反馈回复触发）

**12. C12 房源管理**（BE-C12-001 ~ BE-C12-015）
- 房源管理：管理员上架/下架房源、查询房源列表（按社区/户型/价格筛选）、查询房源详情（浏览统计 +1）、游客浏览房源（仅显示已上架）
- 看房预约管理：居民创建、游客创建（填写姓名/电话）、无时段配置拒绝、管理员审核

【执行步骤】
1. **启动后端应用**：`cd backend && mvn spring-boot:run`
2. 确认应用启动成功，访问 Swagger UI：http://localhost:8080/swagger-ui.html
3. 使用 Postman 或 curl 执行测试用例（按测试计划第 2.3 节）
4. 验证响应数据与数据库状态
5. 使用 MySQL Workbench 验证数据库数据一致性
6. 查看应用日志（IDEA 控制台或 application.log）
7. 记录测试结果（通过/失败）
8. 发现缺陷时，记录缺陷详情

【测试数据】
- 超管账号：superadmin / Admin@123456（V3 迁移已创建）
- 管理员账号：手动创建（绑定社区 1）
- 服务人员账号：手动创建（绑定社区 1）
- 居民账号：手动创建（已入住）
- 社区/楼栋/单元/房屋：手动创建（社区 1、社区 2）

【单元测试编写】
执行接口测试的同时，编写以下 Service 层单元测试（使用 JUnit 5 + Mockito）：
- [ ] CommunityServiceTest：社区业务逻辑测试
- [ ] BuildingServiceTest：楼栋删除保护测试
- [ ] HouseServiceTest：房屋状态变更测试
- [ ] ResidentServiceTest：注册开关/代建测试
- [ ] ResidenceApplicationServiceTest：申请审核/状态流转测试
- [ ] LeaseServiceTest：状态判定/到期提醒测试
- [ ] WorkOrderServiceTest：状态机测试/派单测试
- [ ] ReservationServiceTest：冲突检测/违约处置测试
- [ ] EvaluationServiceTest：评价提交/不满意跟进测试
- [ ] NoticeServiceTest：公告发布/有效期/定向测试

**目标覆盖率**：≥ 60%

【测试报告】
测试完成后，记录以下内容：
1. 测试执行总结（测试用例总数、通过数、失败数、通过率）
2. 缺陷统计（按等级、按模块）
3. 单元测试覆盖率报告
4. 重点验证项结果：
   - 功能级权限（@PreAuthorize）拦截是否正确
   - 数据级权限（DataScopeInterceptor）过滤是否正确
   - 6 个状态机流转是否正确
   - 删除保护、冲突检测、令牌吊销是否生效
5. 数据一致性验证结果

【通过标准】
- [ ] 所有测试用例执行完成
- [ ] P0 级别用例（核心功能）100% 通过
- [ ] P1 级别用例（重要功能）≥ 95% 通过
- [ ] P2 级别用例（一般功能）≥ 90% 通过
- [ ] 单元测试覆盖率 ≥ 60%
- [ ] 无 Blocker/Critical 级别缺陷遗留

【注意事项】
- **必须先启动后端应用**，确认 Swagger UI 可访问后再开始测试
- 优先测试核心模块（C2 入住申请、C4 工单、C6 反馈、C7 预约）
- 重点验证状态机流转（6 个状态机的合法/非法流转）
- 重点验证权限控制（功能级 + 数据级）
- 重点验证令牌吊销（社区绑定变更、冻结账号、修改密码）
- 发现 P0/P1 级别缺陷时，立即记录并修复
- 使用独立测试数据库（community_residence_test）
- 测试完成后，执行单元测试覆盖率报告：`mvn test jacoco:report`

请先启动后端应用，然后开始执行后端自测，并实时报告测试进展。
```

---

**使用说明**：
1. 在后端工作区会话中使用此提示词
2. 复制上述提示词发送给后端会话 AI
3. AI 将启动后端应用并执行自测
4. 测试完成后查看测试报告
