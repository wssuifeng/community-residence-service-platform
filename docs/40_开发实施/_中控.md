## 6. 开发规范

### 6.1 后端代码规范

**包结构**（根包以架构设计.md §2 为准，2026-09-07 用户裁决）：
```
com.community.residence
├── config          # 配置类（Security/Redis/MyBatisPlus/WebSocket）
├── common          # 通用类（ApiResponse/异常/ErrorCode/PageVO）
├── filter          # 过滤器（JwtAuthenticationFilter）
├── interceptor     # 拦截器（DataScopeInterceptor）
├── community       # C1 社区管理
│   ├── controller
│   ├── service
│   ├── mapper
│   ├── entity
│   └── dto/vo
├── resident        # C2 居民管理
├── lease           # C3 租住管理
├── workorder       # C4 工单管理
├── notice          # C5 公告管理
├── feedback        # C6 反馈管理
├── reservation     # C7 资源预约
├── evaluation      # C8 服务评价
├── statistics      # C9 运营统计
├── auth            # C10 权限管理
├── messaging       # C11 通知中心
└── housing         # C12 房源管理
```

**命名规范**：
- Controller：`XxxController`，RESTful 风格
- Service：`XxxService` + `XxxServiceImpl`
- Mapper：`XxxMapper`
- Entity：与数据库表名对应（驼峰命名）
- DTO：`XxxDTO`（请求参数）
- VO：`XxxVO`（响应数据）

**注解规范**：
- Controller：`@RestController` + `@RequestMapping("/api/v1/xxx")`
- 权限：`@PreAuthorize("hasRole('ADMIN')")`
- 参数校验：`@Valid` + JSR-303 注解（@NotNull/@NotBlank/@Size/@Pattern）
- Swagger：`@Tag(name="社区管理")` + `@Operation(summary="创建社区")`

**命名规范**：
- 组件：大驼峰（PascalCase），如 `WorkOrderCard.vue`
- 页面：大驼峰，如 `WorkOrderList.vue`
- 路由：kebab-case，如 `/resident/work-orders`
- API 方法：小驼峰（camelCase），如 `getWorkOrderList`
- 类型定义：大驼峰 + Interface 前缀，如 `IWorkOrder`

### 6.3 Git 提交规范

**提交信息格式**：
```
<type>(<scope>): <subject>

<body>

<footer>
```

**type 类型**：
- `feat`：新功能
- `fix`：修复 bug
- `refactor`：重构
- `style`：代码格式调整
- `docs`：文档更新
- `test`：测试相关
- `chore`：构建/工具链相关

**示例**：
```
feat(community): 完成社区管理模块后端接口

- 实现社区 CRUD 接口
- 实现楼栋/单元/房屋管理接口
- 添加数据级权限过滤
- 覆盖 R1~R6 需求

Refs: C1 社区基础信息管理
```
