## 2. 功能需求（R1~R57，挂 C 编号）

### C1 社区基础信息管理

| 编号 | 需求 | 验收标准 |
|------|------|---------|
| R1 | 多社区管理：**超级管理员**新建 / 停用 / 删除社区（名称、地址、联系方式、简介）；删除为**级联删除**——社区退场时其下级结构（楼栋 / 单元 / 房屋 / 公共资源 / 房源）与关联业务数据一并删除（v1.1，见 R6）；社区管理员可编辑其绑定社区的基本信息，管理端可切换当前操作社区（限绑定范围内） | 社区新建 / 停用 / 删除仅超管可执行，社区管理员调用对应接口 100% 被拒并记录；社区管理员切换范围外的社区被拒绝；删除后社区及其下级数据不可再查且无孤儿残留 |
| R2 | 楼栋管理：社区下维护楼栋（编号、名称、层数、备注） | CRUD 可用；被引用的楼栋禁止删除（见 R6） |
| R3 | 单元管理：楼栋下维护单元（编号、名称） | CRUD 可用；被引用的单元禁止删除（见 R6） |
| R4 | 房屋管理：单元下维护房屋（房号、面积、户型、朝向、状态）；状态 ∈ {自住, 出租, 空置, 维修中, 停用}，变更留记录（操作人 / 时间 / 原因） | CRUD 与状态变更可用；状态历史可查 |
| R5 | 公共资源管理：维护资源（名称、类型、位置、容量、介绍），配置是否开放预约及可预约时段 | 资源 CRUD 可用；可预约时段可配置（术语见术语表） |
| R6 | 删除保护：已被下级节点或业务数据引用的**楼栋 / 单元 / 房屋 / 资源**禁止物理删除，仅可停用；**社区除外**——社区由超级管理员执行级联删除（真实场景：社区管理方退场，其下级结构与关联业务数据随之删除，v1.1 变更），删除须二次确认并全量留痕 | 对含下级或被引用的楼栋 / 单元 / 房屋 / 资源执行删除返回明确错误且数据不变；社区级联删除后各关联表无孤儿记录（判据对齐 C1） |

**端到端流程 E1（C1）**：触发=管理员初始化社区。参与者=社区管理员。数据流=
新建社区 → 楼栋 → 单元 → 房屋（初始状态空置）→ 配置公共资源与可预约时段；
各步写入操作日志，后续业务按社区隔离查询。

### C2 居民与居住关系管理

| 编号 | 需求 | 验收标准 |
|------|------|---------|
| R7 | 注册方式全局开关（**全局级，仅超级管理员**）：配置启用「管理员代建」与「自助注册」（两者可独立开关）；社区管理员不可操作全局配置 | 社区管理员访问全局配置接口 100% 被拒并记录；关闭自助注册后，前端注册入口隐藏且注册接口返回明确拒绝 |
| R8 | 管理员代建：管理员录入居民信息（姓名、联系方式、证件号等）并创建账号（初始密码）；支持**批量导入**（CSV 模板：逐行居民信息，导入结果逐行反馈成功/失败原因，v1.2 扩展） | 代建成功后居民可登录；操作入日志；批量导入部分成功时成功行生效、失败行带原因反馈 |
| R9 | 入住申请：自助注册用户选择社区 / 房屋 / 关系类型（产权人 / 承租人 / 共同居住人等）与居住起止，提交入住申请；管理员审核通过建立居住关系，驳回须填理由 | 申请状态机「待审核→已通过 / 已驳回」；通过后账号获得居民端业务功能入口（判据对齐 C2） |
| R10 | 搬出登记：居民申请或管理员发起搬出，审核后居住关系终止并记录搬出时间，历史保留 | 搬出审核通过后该居民失去对应房屋的居民端功能入口；历史关系可查 |
| R11 | 居住关系台账：按房屋查当前与历史居住人员；按居民查其全部居住历史 | 双向查询结果与居住关系数据一致 |
| R12 | 公开信息子集控制：管理方后台配置游客 / 无关系账号可见范围（公告、房源等开关）；居住私有数据对无关系账号一律拒绝 | 未配置开放的私有接口对无关系账号返回拒绝（判据对齐 C2） |

**端到端流程 E2（C2）**：触发=潜在居民注册。参与者=居民、社区管理员。数据流=
自助注册 → 提交入住申请（房屋 / 关系 / 起止）→ 管理员审核 → 通过：建立居住关系
（通知申请人，R48）→ 居民端功能开放；（期末）搬出申请 → 审核 → 关系终止归档。

### C3 租住管理

| 编号 | 需求 | 验收标准 |
|------|------|---------|
| R13 | 租住登记：承租关系登记（承租人、房屋、租期起止、租金备注，不涉资金），经审核流转「待审核→已生效」 | 审核通过后租住记录生效且与房屋、居民关联正确 |
| R14 | 租住状态自动判定：「即将到期」（止期前 N 天内，N 管理员可配）与「已到期」（止期已过）由系统按止期与当前日期自动判定，非人工流转 | 判定结果与"止期 + 当前日期 + N"规则完全一致，无需人工干预 |
| R15 | 到期提醒：按配置天数向居民与管理员触发站内通知；同一租住记录同一状态只提醒一次，可由管理员手动重发 | 提醒在止期前 N 天触发，通知入消息中心且不重复（同一状态仅一条） |
| R16 | 搬出与归档：已生效租住经搬出登记流转「已搬出→已归档」，历史可查 | 全状态流转留痕；归档后不可修改 |

**端到端流程 E3（C3）**：触发=租客申请租住。参与者=租客、管理员。数据流=
租住登记申请 → 审核 → 已生效 → 止期前 N 天自动提醒（R15）→ 续租（重新登记）
或搬出 → 已搬出 → 已归档。

### C4 服务申请与工单管理（报修渠道）

| 编号 | 需求 | 验收标准 |
|------|------|---------|
| R17 | 服务类别管理：管理员维护类别目录（如室内维修 / 公共设施报修 / 公共区域卫生 / 水电管道 / 电梯楼道 / 安全隐患上报 / 其他） | 类别 CRUD 可用；停用类别不再出现在提交选项 |
| R18 | 工单提交：居民选择类别、填写标题与描述、可附多张图片，提交生成工单（待受理） | 提交成功生成工单号；图片随单保存 |
| R19 | 受理与驳回：管理员受理（→待派单）；无效工单驳回须填理由（→已驳回）。居民可在受理前取消（→已取消） | 状态分支符合状态机：已驳回仅可自待受理流转，已取消仅可自待受理 / 待派单流转 |
| R20 | 派单与接单：管理员指派服务人员（→已派单）；服务人员接单（→已接单）并开始处理（→处理中） | 派单对象须为启用状态的服务人员账号；接单后其他人不可再接 |
| R21 | 处理与结果提交：服务人员更新进度并提交处理结果（文字 + 多张图片），流转至待确认 | 结果含至少文字描述，图片可选多张；流转后居民端可见 |
| R22 | 居民确认与关闭：居民确认 → 已完成（进入可评价状态）；工单关闭（→已关闭）由管理员执行，存在未评价的已完成工单时系统先行提示；居民对结果不满意可退回处理中（注明原因） | 退回仅可自待确认发起且须填原因；已完成的工单在关闭前保持可评价（与 R37 联动）；关闭操作留痕 |
| R23 | 处理记录留痕：每次流转记录操作人、时间、备注，工单详情按时间线展示 | 全部状态流转均产生处理记录，无遗漏（判据对齐 C4） |

**端到端流程 E4（C4）**：触发=居民报修。参与者=居民、管理员、服务人员。数据流=
提交工单（类别 + 描述 + 图片）→ 管理员受理 → 派单 → 服务人员接单处理 →
提交结果（文字 + 图片）→ 居民确认 → 已完成 → 评价（R37）→ 关闭；全程通知双方
（R48）。

### C5 公告广播管理

| 编号 | 需求 | 验收标准 |
|------|------|---------|
| R24 | 公告发布与编辑：管理员发布公告（标题、正文、分类、可附图），可编辑；**社区管理员的发布范围限其绑定社区内的社区 / 楼栋，超级管理员可全系统广播** | 发布后目标范围用户可见；编辑留痕；社区管理员选择绑定范围外的目标被拒绝并记录 |
| R25 | 定向与置顶：目标范围支持勾选一个或多个社区及楼栋；支持置顶 | 置顶公告排在列表最前；范围外用户不可见 |
| R26 | 有效期与下线：设置生效 / 失效时间，过期公告自动从居民端列表下线 | 过期后列表接口不再返回该公告，但后台归档可查 |
| R27 | 查看记录：目标用户查看公告即记录，统计已读人数 / 目标人数 | 已读统计数与查看记录明细一致 |

**端到端流程 E5（C5）**：触发=管理员发公告。参与者=管理员、目标用户。数据流=
发布（范围 + 有效期 + 渠道勾选 R51）→ 站内通知触达目标用户（R48）→ 用户查看
（记录回执）→ 有效期止自动下线 → 归档。

### C6 居民反馈管理（反馈渠道，会话式）

| 编号 | 需求 | 验收标准 |
|------|------|---------|
| R28 | 反馈提交：居民提交意见 / 建议 / 投诉（分类、内容、可附图） | 提交成功生成反馈单，状态「待受理」 |
| R29 | 反馈受理：管理员受理并建立会话 | 受理后进入会话，居民收到通知 |
| R30 | 会话沟通：居民与管理员通过会话实时收发文本消息（长连接）；在线秒级送达，离线消息由 C11 补拉机制保证不丢 | 双方在线时消息 ≤3 秒送达；会话记录完整可查；会话归属限定"本反馈单"（新话题须另提反馈） |
| R31 | 办结归档：管理员办结须填处理结论，会话归档只读，全程留痕 | 办结后会话不可再发消息；记录不可修改 |

**端到端流程 E6（C6）**：触发=居民提交投诉。参与者=居民、管理员。数据流=
提交反馈 → 受理建会话 → 双方实时沟通（长连接）→ 办结（结论）→ 归档只读。

### C7 公共资源预约管理

| 编号 | 需求 | 验收标准 |
|------|------|---------|
| R32 | 预约申请：居民选择资源、日期与时段（时段须落在该资源可预约时段配置内，R5）提交预约 | 时段外请求被拒绝并提示；提交后状态「待审核」 |
| R33 | 冲突校验：同一资源同一时段的重叠预约 100% 拦截（含并发提交场景） | 专项用例集内拦截率 100%（判据对齐 C7） |
| R34 | 审核与取消：管理员审核通过（→已预约）/ 拒绝（→已拒绝，须填理由）；用户可取消（→已取消） | 全状态流转留痕；拒绝 / 取消通知对方 |
| R35 | 完成与违约：预约到期后登记已完成；用户违约（未到场等）登记已违约并可触发违约处置（冻结账号 / 限制预约，留痕） | 违约处置记录可查；被处置账号受相应限制 |
| R36 | 预约记录查询：居民查看本人预约记录及状态；管理员可按资源 / 社区 / 状态 / 时间范围检索全部预约 | 查询结果与预约数据一致；检索条件组合可用 |

**端到端流程 E7（C7）**：触发=居民预约活动室。参与者=居民、管理员。数据流=
选资源 / 时段 → 冲突校验 → 提交（待审核）→ 审核通过（已预约，通知）→ 使用 →
登记完成 / 违约 →（违约）处置留痕。

### C8 服务评价管理

| 编号 | 需求 | 验收标准 |
|------|------|---------|
| R37 | 工单评价：居民对已完成工单评价一次（满意度等级 1~5 星 + 文字评语） | 每工单仅一次评价，重复提交被拒绝 |
| R38 | 不满意跟进：≤2 星评价触发管理员跟进，处理结果记录在案 | 不满意评价均有跟进记录后才可关闭跟进流程 |
| R39 | 评价统计：按服务人员、服务类别聚合满意度 | 聚合数值与评价明细一致 |

**端到端流程 E8（C8）**：触发=工单完成。参与者=居民、管理员。数据流=完成 →
居民评价（星级 + 文字）→（≤2 星）管理员跟进 → 记录 → 计入统计（R39 / R40）。

### C9 社区运营统计

| R41 | 统计一致性：报表数值与库内明细抽样核对 100% 相符 | 抽样核对用例全部相符（判据对齐 C9） |
| R42 | 可视化：统计以图表呈现（ECharts），支持导出图片 | 图表渲染正确，导出可用 |

**端到端流程 E9（C9）**：触发=管理员打开看板。数据流=选择社区 / 时间范围 →
后端聚合查询 → 图表渲染 →（答辩演示口径）逐项与明细核对一致。

### C10 用户与权限管理

| 编号 | 需求 | 验收标准 |
|------|------|---------|
| R43 | 登录认证：账号密码登录，签发 JWT（含有效期与刷新机制），注销后令牌失效 | 正确凭据登录成功；过期 / 注销令牌访问被拒 |
| R44 | 角色权限校验：五角色（游客 / 居民 / 服务人员 / 社区管理员 / 超级管理员）菜单与接口权限按 §1 权限矩阵控制，含**全局级 / 社区级两层**（社区管理员越全局级操作 100% 拒绝）；越权访问 100% 拒绝并记录 | 否定用例（各角色交叉越权 + 社区管理员越全局级）全部拒绝且产生日志（判据对齐 C10） |
| R45 | 两级数据授权：超级管理员可访问全系统数据；社区管理员账号由超管创建并绑定管辖社区，业务查询按绑定社区过滤 | 社区管理员越绑定范围的数据查询返回空 / 拒绝并记录；超管全局查询可用 |
| R46 | 用户管理：超级管理员管理社区管理员账号（创建、启停、社区绑定分配）**与服务人员账号（创建、启停、社区绑定，v1.2 修订——服务人员账号归平台统一管理）**；社区管理员管理本社区居民账号（启停、重置密码、角色分配、违约处置的冻结 / 限制预约）——**社区管理员不可直接启停 / 封禁服务人员账号（属越权，100% 拒绝并记录），其对服务人员的控制经业务机制实现（派单选择、服务类别配置等）** | 社区管理员不可见 / 操作管理员与服务人员账号体系（越权 100% 拒绝并记录）；被冻结账号无法登录或仅保留受限功能（按处置类型） |
| R47 | 操作日志：关键数据变更（新增 / 修改 / 删除 / 状态流转 / 审核 / 处置）记录操作人、时间、对象、内容，仅追加不可修改，可按条件查询 | 全部关键变更可检索到对应日志（判据对齐 C10） |
| R58 | 日志留存清理与通知：操作日志保留 **2 年**（阈值经全局配置可调，默认 730 天），到期由定时任务自动清理；清理发生后**自动通知运营者**（超级管理员，经通知中心），清理动作本身写入任务日志——杜绝运营者不知情的数据清理（v1.1 新增，挂 C10） | 到期日志被清理且未到期日志不受影响；每次清理产生超管通知与任务日志记录；阈值调整即时生效（测试可短时调低验证，验后必须恢复默认） |

**端到端流程 E10（C10）**：触发=用户登录。数据流=登录 → JWT 签发 → 访问接口
（角色 + 全局级 / 社区级两层校验 + 绑定社区过滤）→ 越权请求（含社区管理员越
全局级）被拒并记录 → 关键操作写日志。
**端到端流程 E10b（C10，权限初始化）**：触发=超管搭建组织。数据流=超管新建
社区 → 创建社区管理员账号 → 绑定管辖社区 → 社区管理员登录后在本社区范围内
开展工作（代建居民 / 服务人员账号、发布公告限本社区范围）。

### C11 消息与通知中心

| 编号 | 需求 | 验收标准 |
|------|------|---------|
| R48 | 通知生成：业务事件自动生成站内通知——工单流转、审核结果（入住 / 搬出 / 租住 / 预约 / 看房）、租期到期、公告广播、反馈会话新消息、违约处置 | 以上每个事件均产生对应通知，覆盖无遗漏；通知记录操作时间与来源事件，可溯源 |
| R49 | 长连接实时推送：用户在线时通知经长连接推送，≤3 秒送达 | 在线推送专项用例全部 ≤3s（判据对齐 C11） |
| R50 | 上线补拉：登录 / 重连时按通知序号增量拉取离线期间通知，不丢失 | 离线期间产生通知 → 上线后全部可见（专项用例） |
| R51 | 渠道分级与已读管理：通知按等级支持渠道勾选（站内必达；短信 / 微信服务号为可插拔模拟通道，触发留痕）；通知支持已读 / 未读管理 | 勾选的模拟通道触发留痕可查；已读 / 未读状态准确 |

**端到端流程 E11（C11）**：触发=工单状态变更。数据流=事件 → 生成通知 →
（在线）长连接 ≤3s 推送 /（离线）入库待补拉 → 用户上线补拉 → 查看已读 →
（公告类）按勾选渠道触发模拟通道留痕。

### C12 房源展示与看房预约

| 编号 | 需求 | 验收标准 |
|------|------|---------|
| R52 | 房源管理：管理员后台添加 / 编辑 / 下架房源（关联本社区房屋：位置地图标注、户型、面积、朝向楼层、租金 / 售价、图片），信息遵循真实性自查清单（对照《住房租赁条例》口径：地址、面积、租金真实准确完整） | 房源 CRUD 可用；下架后前台不可见；完整性必填校验生效 |
| R53 | 房源浏览：游客与居民按条件筛选（社区 / 户型 / 价格区间 / 租售类型）浏览房源列表与详情（含地图位置） | 筛选结果准确；浏览量计入统计（R40） |
| R54 | 可预约时段配置：每个房源后台配置可预约时段，时段外的预约请求不被受理 | 时段外请求被拒绝并提示可预约范围 |
| R55 | 看房预约：注册账号选择时段申请看房（冲突校验复用 R33 机制），管理方确认（→已预约）；用户可取消（→已取消）。状态机「待确认→已预约→已完成 / 已取消 / 已违约」 | 同一房源同一时段重叠预约 100% 拦截；确认 / 取消均通知对方；全状态流转留痕 |
| R56 | 带看完成与违约：带看后登记已完成 / 已违约；违约触发违约处置（冻结账号 / 限制预约，留痕） | 处置记录可查；被处置账号受相应限制 |
| R57 | 浏览与带看统计：房源浏览量、带看量计入运营统计 | 与明细数据核对一致 |

**端到端流程 E12（C12）**：触发=管理员上架房源。参与者=管理员、游客。数据流=
后台添加房源（关联房屋 + 地图标注）→ 游客筛选浏览 → 选可预约时段申请看房 →
冲突校验 → 管理方确认（通知）→ 线下带看 → 登记完成 / 违约 →（违约）处置留痕。
