## 2. 功能需求（R1~R74，挂 C 编号）

### C1 社区基础信息管理

**2026-10-11 社区结构与责任人增量（用户批准14设计，沿R1/R2/R53/R62）**：每栋楼的层数是自身房屋楼层边界，不设99/200等固定业务上限，1000层可登记；新建、编辑与批量建房均不得超出所属楼栋层数，增层须先修改楼栋，降层不得遗留现有超层房屋。删除房间数属性，仅用真实户型描述；生成批次采用表单户型，结构卡片支持多选配置，关联挂牌同步。社区联系人由责任人账号ID绑定系统ADMIN账号（超管/人员/居民账号不能作为候选），本社区已绑定者优先，其他ADMIN亦可选；姓名电话随账号资料同步，不由社区维护副本，选择责任人不隐式授予社区权限。


| 编号 | 需求 | 验收标准 |
|------|------|---------|
| R1 | 多社区管理：**超级管理员**新建 / 停用 / 删除社区（名称、地址、联系方式、简介）；删除为**级联删除**——社区退场时其下级结构（楼栋 / 单元 / 房屋 / 公共资源 / 房源）与关联业务数据一并删除（v1.1，见 R6）；社区管理员可编辑其绑定社区的基本信息，管理端可切换当前操作社区（限绑定范围内） | 社区新建 / 停用 / 删除仅超管可执行，社区管理员调用对应接口 100% 被拒并记录；社区管理员切换范围外的社区被拒绝；删除后社区及其下级数据不可再查且无孤儿残留 |
| R2 | 楼栋管理：社区下维护楼栋（编号、名称、层数、备注） | CRUD 可用；被引用的楼栋禁止删除（见 R6） |
| R3 | 单元管理：楼栋下维护单元（编号、名称） | CRUD 可用；被引用的单元禁止删除（见 R6） |
| R4 | 房屋管理：单元下维护房屋（房号、面积、户型、朝向、状态）；状态 ∈ {自住, 出租, 空置, 维修中, 停用}，变更留记录（操作人 / 时间 / 原因） | CRUD 与状态变更可用；状态历史可查 |
| R5 | 公共资源管理：维护资源（名称、类型、位置、容量、介绍），配置是否开放预约及可预约时段 | 资源 CRUD 可用；可预约时段可配置（术语见术语表） |
| R6 | 删除保护：已被下级节点或业务数据引用的**楼栋 / 单元 / 房屋 / 资源**禁止物理删除，仅可停用；**社区除外**——社区由超级管理员执行级联删除（真实场景：社区管理方退场，其下级结构与关联业务数据随之删除，v1.1 变更），删除须二次确认并全量留痕 | 对含下级或被引用的楼栋 / 单元 / 房屋 / 资源执行删除返回明确错误且数据不变；社区级联删除后各关联表无孤儿记录（判据对齐 C1） |

**端到端流程 E1（C1）**：触发=管理员初始化社区。参与者=社区管理员。数据流=
新建社区 → 楼栋 → 单元 → 房屋（初始状态空置）→ 配置公共资源与可预约时段；
各步写入操作日志，后续业务按社区隔离查询。
